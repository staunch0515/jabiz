## 1. 目标与原则

1. 用 jabiz 平台实现需求所述的美国单公司基础财务系统，通过 FIN-SCN-01…15 并**逐项复现** FIN-EXP-*。
2. **公共能力进 `platform`，财务专有进 `finance`。** 判断标准：换一个与财务无关的业务应用（例如物流、商城、culture）是否也需要。
   需要 → 平台阶段（带平台自己的测试与 `app` 中的示范，不提财务）；不需要 → 财务阶段。
3. 合并方向只有 `platform → finance`；`finance` 不改任何平台目录（`backend/core|runtime|ext-geo|app|build-logic`、`frontend`、`spec`、`docs/design`、`docs/guide`、根目录 `CLAUDE.md`）。
4. 期望结果只作为测试的判定依据，**永不写入系统**（20 §3、40 §1.5）：税、折旧、汇兑损益、所得税等都由系统计算。
5. 比较协议（40）：每个提交信息以工作项 ID 开头（`FIN-GL-003: …`、`TASK-xxx: …`），工作记录与缺陷记录放在 `docs/finance-work/`。

## 2. 现状：平台已有什么、缺什么

### 2.1 可以直接使用

| 平台能力 | 财务中的用途 |
|---|---|
| 双时态只追加实体（`effect_start_time` / `created_time`、`asOf` / `knownAt`、历史、只追加触发器） | 主数据历史（FIN-AR-001 按发票日取地址、FIN-GL-004、FIN-UI-008）、"as known on"（FIN-RP-020）的基础、账不可改（FIN-GL-012） |

| 流程引擎（同步扩展点、`ChangeSet`、违规累积、子流程同一事务、幂等键） | 全部单据的过账流程、API 幂等（FIN-DI-006） |

| RBAC、JWT、遮蔽 `@Sensitive`、BCrypt、登录锁定 | 角色（01 §2）、认证 |
| 文件（上传、策略、PDF） | 附件（FIN-GL-016） |
| SQL 模板 + 静态校验、场景回放、`platformCheck`、ArchUnit、BlockHound、jqwik | 报表查询、验收测试 |

## 3. 公共 / 专有 划分

### 3.1 放 `platform`（公共能力，新增平台阶段 14）

| 平台阶段 | 内容 | 解决 |
|---|---|---|
| **14a 应用自有后台页面** | 把 `frontend/` 拆为可复用的后台外壳包（登录、令牌、菜单、元数据驱动的列表/表单/历史、API 客户端）+ 通用后台入口；应用在自己目录里建 SPA，引用外壳并注册自己的路由与页面（AntD 可用）。新增决策 D21（补充 D19：D19 的"不用 AntD"只针对公开前端）。另：界面语言可由应用限定为子集（`jabiz.i18n.languages`，消息只需覆盖所选语言）、区域格式（`en-US` 日期/数字）、金额字段自动校验小数位（G12） | G1 G11 G12 |
| **14b 编号、审批、任务与通知** | ① `DocumentNumbering`：按"序列名 + 范围（年度、来源）"的无缺号编号，在过账事务内取号（计数行 + 行锁，回滚不消耗号）；平台步骤 `AssignNumber.of(...)`。② 审批：版本化的审批规则（条件：金额、实体字段、动作；审批人角色与限额），审批请求记录规则版本，**审批绑定内容哈希**（内容变则失效），提交人 ≠ 审批人的强制检查，多级审批；步骤 `RequireApproval.of(...)`。③ 职责分离：可配置的互斥权限/角色对，运行时拒绝 + 冲突报告。④ 任务收件箱（`sys_task`）与邮件通知（SMTP，经 Outbox 投递）；影响预览（规则变更前对历史数据重算）作为可选接口 | G2 G3 G10 |
| **14c 账本增强** | 多币种分录（交易币种金额、汇率、记账本位币金额，两边分别平衡）；行备注；至多 N 个分析维度；来源单据引用（实体类型 + 主键，可钻取）；过账日期与记录时间分开（已有 `bookingTime` 与 `created_time`）；余额模板增加 `from`/`to` 区间、按维度汇总与 `knownAt`；科目增加上级科目（汇总科目不可过账）。账本本位币/小数位保持配置（`USD`/2）。`ledger.post` 只经业务流程的子流程使用（不授予任何角色），即可实现"控制科目只允许子账过账" | G4 |
| **14d 时点查询、导出与报表存档** | SQL 模板支持 `asOf` / `knownAt` 运行（时态实体按指定时点渲染）；模板结果导出 CSV / XLSX（数值单元格）/ PDF（页眉：公司、报表、期间、运行时间、页码）；**报表运行存档**：参数、模板版本、内容哈希，按需原样重现；后台"报表"页面运行模板 | G5 G6 |
| **14e 导入框架** | 文件类型增加 CSV / XLSX / XML / 纯文本（导入专用策略，不重新编码）；导入 = 解析 → 映射 → **全部行校验后才写入** → 预览 → 导入报告；按文件哈希与外部引用去重；每行交给一个业务流程处理（同一事务或整体拒绝） | G7 |
| **14f 审计与保留** | 审计记录前后值（敏感值遮蔽）与原因；审计页面；**防篡改**：对账本行、操作表、审计记录做哈希链并定期封存，提供校验接口（能指出被改或缺失的行）；保留期与法律保全（到期前拒绝删除）；全量数据导出（开放格式 + 模式说明） | G8 |
| **14g 安全增强** | TOTP 二次验证与"按操作要求二次验证"（step-up，流程声明 `requiresMfa()`）；OIDC 单点登录（SAML 不做，见 §7）；会话闲置锁定；字段"按权限显示明文"（`f.masked(permission, 样式)`）且每次明文查看写日志；用户角色带数据期限/范围属性（进入 `RequestContext`，数据视图范围可引用）；用户访问报告与审查签核 | G9 |

## 4. 财务总体设计要点（详见 F0 产出的 `docs/finance/00-design.md`）

1. **总账**：每张子账单据（发票、账单、收款、付款、折旧、重估、银行分录、结账分录）在自己的过账流程中以子流程 `LEDGER_POST` 过账，同一事务；账本行带来源单据引用 → 钻取（FIN-RP-006）。
   科目扩展属性（报表行、控制科目、现金流分类等）放财务实体 `FinAccount`（与账本科目按代码一一对应，时态）。
2. **日记账**：`FinJournal`（草稿/提交/批准/过账/驳回）+ 行；草稿期间可改，过账才取号（14b，按财年 + 来源无缺号）、才写账本。
3. **期间**：`FinPeriod`（open / soft-closed / closed，子账可先关）；每个过账流程在写账前检查期间与权限；第 13 期（调整期）只进年报。
4. **"as of" 与 "as known on"**：过账日期 = 账本 `bookingTime`，记录时间 = 平台操作时间（来自注入的 `Clock`）；报表用 14c/14d 的 `knownAt`。结账产物、已发报表存档可原样重现（RP-009、PC-005/006）。
5. **金额**：`BigDecimal`，USD 2 位，汇率至少 6 位小数；四舍五入"远离零"（`RoundingMode.HALF_UP` 对 `BigDecimal` 即远离零），按需求规定的层级（税按发票+辖区、折旧按资产+月）。
6. **审批**：使用 14b；规则数据（阈值 10,000.00 等）是带生效日的配置，规则版本记入审批记录（CT-002、SCN-10）。
7. **性能**：年 250 万行、试算表 ≤ 5 s。先用索引 + 实时汇总实现并用压测验证；不达标时增加"已结期间余额快照"（结账时写入，只追加）。
