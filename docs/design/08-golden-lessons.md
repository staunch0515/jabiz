# 08 来自 golden 的经验

golden 是 2014 年由一个人在约 3 个月内从零开发的业务系统（JSP + Servlet + Spring 2.5 + MySQL，自研 `ichigo` 框架）。
它能在短时间内支撑频繁的业务调整（一次调整涉及上百条 SQL），靠的是一套配置驱动的设计思想。

**本平台只吸收 golden 的设计思想，不迁移其代码，也不实现其业务规则，golden 的业务领域不作为本平台的示例领域。**

## 1. 吸收的思想及其在 jabiz 中的落地

| golden 的做法 | 解决的问题 | jabiz 中的落地 | 设计文档 |
|---|---|---|---|
| 一个请求一个工作单元：`open → exeService → save → output`，业务只改 `AppData`，最后统一保存 | 业务代码不碰连接和事务，要么全成功要么全回滚 | 流程的 `ChangeSet` 自动提交；一个流程一个事务 | 06 §3、§4 |
| 用例组合：`ExeService("app.setorder")` | 大用例由小用例拼成 | `CallProcess`，同一事务，`parent_seq_id` | 06 §5 |
| `AppClient` 是接口，Web、Job、测试各有实现 | 同一业务可被网页、定时任务、测试调用 | `ProcessExecutor` 与传输方式无关 | 06 §8 |
| 错误码 `err.*` + 多语言，错误累积后返回 | 前端一次拿到全部错误；多语言 | `Violation.ruleCode` + 多语言资源；业务规则阶段也累积 | 02 §3.1 |
| dataset：按名字配置的列表查询 | 新增列表页只需一段配置 | 数据视图 + SQL 模板 + 列表视图元数据 | 03、05、02 §7 |
| 页面 `columnList` 配置 | 列表页改列不动后端 | 元数据导出 → ProTable 适配层 | ROADMAP 阶段 10 |
| applist：静态或 SQL 的下拉列表 | 统一的选项来源 | 字典注册表 | 02 §5 |
| 菜单 XML（`DirectViewPage`） | 菜单与页面统一配置 | 菜单元数据 + 权限码 | ROADMAP 阶段 7、10 |
| 成对记账，同一 `actionid`，每条记余额 | 资金可追溯 | 通用复式记账模块，分录只追加 | ROADMAP 阶段 9 |
| 座位升级时复制新记录、旧记录填结束时间；账本只追加 | 保留历史 | **只追加的双时态模型**（通用化） | 04 |
| 场景测试 XML（`app_test_*.xml`）：整月业务回放 | 复杂规则的回归保障 | 场景 YAML + 可控时钟 + 快照 | 07 §3 |
| 业务参数修改留在代码注释里（`20150728 Update`） | —（反面教材） | 带生效时间的参数（时态实体）+ 流程版本化 | 04 §9、06 §6 |
| `fireEvent` 钩子（设计了但没用上） | 模块解耦 | 实体变更事件 + Outbox | ROADMAP 阶段 9 |
| `actionid` 防重复提交 | 幂等 | `Idempotency-Key` + `op_process` 唯一约束 | 06 §8 |

## 2. 明确不要带过来的做法

| golden 的做法 | 问题 | jabiz 的约定 |
|---|---|---|
| 字符串拼接 SQL，值以 `@` 开头时原样拼入 | SQL 注入 | 全部参数绑定；标识符只来自元数据 |
| 一切都是字符串的 `Map`（`AppData`、上下文） | 拼写错误到运行时才发现 | 语义类型；输入输出是 record；上下文提供类型化访问 |
| 金额用 `double` + `DecimalFormat` 取整 | 精度错误 | `BigDecimal` + `Monetary(currency, scale)` |
| 余额"读出—内存加减—写回"，无锁无版本 | 并发丢失更新 | 乐观锁 / 版本号唯一约束；账本只追加 |
| 状态保存在 Session 中的 `AppClient` | 无法水平扩展 | 无状态服务；上下文随请求传递 |
| 按 URL 直接执行任意同名 Bean（测试用的清库服务也在线上容器中） | 越权执行危险操作 | 流程、数据视图、模板都必须声明权限；测试代码不进入生产上下文 |
| Cookie 只校验"用户名是否已登录"，失败分支也放行 | 认证可被绕过 | 默认拒绝；Spring Security |
| 明文密码 | 泄露风险 | BCrypt |
| 数据库密码写在 XML 并提交到仓库；日志打印密码 | 凭据泄露 | 环境变量 / 密钥管理；日志遮蔽 |
| Java 中拼接 HTML | 表现与逻辑耦合、XSS | 前后端分离；前端按元数据渲染 |
| 写死的 Windows 日志路径、自写连接池 | 部署问题、资源泄漏 | 标准日志框架；标准连接池 |
| 捕获异常后返回 0 或空串 | 无法区分"无数据"和"出错" | 异常经 `ProblemDetail` 如实返回 |
| 编译产物、`.svn` 提交进仓库 | 仓库污染 | `.gitignore`；CI 构建 |

## 3. 一句话

golden 证明了"配置驱动能让一个人快速响应频繁的业务变化"；jabiz 的任务是**保留这种速度，同时用类型、约束、历史和自动校验保证正确性**。
