# 00 平台总览

## 1. 定位

jabiz 是一个**元数据驱动的业务应用平台**，面向"规则多、变化快、数据正确性要求高"的企业中后台业务系统。

开发者**声明**：实体与语义类型、字段规则、状态机、数据视图（dataset）、SQL 模板、流程。
平台**保证**：类型与校验、权限与数据范围、事务与并发、完整历史与追溯、启动自检、页面生成、场景回放测试。

设计来源：
- **golden**（2014 年的项目）：配置驱动、工作单元、命名查询、用例组合、场景回放测试等思想（见 `08-golden-lessons.md`）。
- **jabiz 现有内核**：语义类型、逻辑名/物理名分离、数据视图策略、严谨的写入流程、SQL 模板经元数据解析、流程版本化、启动自检。

## 2. 能做什么

| 能力 | 说明 | 设计文档 |
|---|---|---|
| 语义化元模型 | 金额、时间（含角色）、字典编码、版本、标识等语义类型；逻辑名/物理名分离，可对接遗留表 | 02 |
| 规则只定义一次 | 同一条规则同时用于服务端校验和前端校验；错误累积返回；错误码多语言 | 02 |
| 状态机 | 迁移、初始状态、迁移守卫写在元数据中，由写入流程统一执行 | 02 |
| 数据视图 | 一个实体多个视图；读写都受范围约束；范围值可取自请求上下文 | 03 |
| 只追加的双时态数据 | 修改即插入新版本；按时间点查询；预定生效；每个变化追溯到一次操作；可撤销操作 | 04 |
| SQL 模板 | 复杂查询手写 SQL，表/列经元数据解析，自动附加范围和时态处理；外层分页筛选；预编译校验 | 05 |
| 流程引擎 | 版本化、强类型；平台负责 I/O，业务只写同步计算；一个流程一个事务；可组合 | 06 |
| 字典与参数 | 字典注册表（静态或 SQL，多语言）；带生效时间的业务参数（基于时态机制） | 02、04 |
| 账本 | 复式记账，分录只追加，每笔交易借贷平衡，更正即冲正 | 11 |
| 事件、审计、定时任务 | 实体变更事件（Outbox，至少一次投递、消费端只处理一次）、基于操作表的审计、多实例安全的定时任务 | 11 |
| 前端 | 由元数据生成列表、表单、菜单、权限；数据历史时间线 | 12 |
| 质量保障 | 启动自检、`platformCheck`、场景回放 + 可控时钟 + 快照、ArchUnit、BlockHound | 07 |
| 可观测性与运行 | 流程、数据视图、模板等的指标与链路（OTLP），结构化日志，本地 Grafana LGTM，Docker Compose 一条命令启动 | 13 |

**目标开发体验**：新增一个业务对象（建表到后台可用）半天到一天，主要工作是写声明；
一次调整上百条 SQL，由静态校验和场景回放保证安全；业务开发者不接触响应式代码。

## 3. 不做什么（非目标）

- 海量 C 端用户的高并发交易核心、大数据分析、强实时系统（游戏、行情撮合）、以复杂算法为主的系统。
- 在线拖拽式低代码设计器（以后可能做，但不是当前目标）。
- 微服务拆分、多数据库类型支持、跨库分布式事务。

## 4. 整体架构

```
┌──────────────────────────────── 前端 (React 19 + TS + Vite + AntD ProComponents) ───────────────────────────────┐
│  元数据 → ProTable / ProForm 适配层 │ RuleSpec → 前端校验 │ 动态菜单/权限 │ 多语言 │ 数据历史时间线             │
└────────────────────────────────────────────────────┬──────────────────────────────────────────────────────────────┘
                                                     │ REST + ProblemDetail（OpenAPI 生成 TS 类型）
┌────────────────────────────────────────────────────┴──────────────────────────────────────────────────────────────┐
│ jabiz-runtime（响应式，很薄）                                                                                       │
│  Web 接入（元数据 API / 数据视图 API / 流程 API）  RequestContext（Reactor Context）  Security                     │
│  DatasetEntityManager（写入流程）  AdvancedQueryExecutor  ProcessExecutor  StorageEngine(R2DBC)  事务                 │
│  启动自检（MetaModelConsistencyChecker 等）                                                                          │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ jabiz-core（纯 Java，无 reactor）                                                                                    │
│  EntityDefinition / SemanticKind / FieldValueCoercer / EntityValidator / 规则 / 状态机 / 迁移守卫                    │
│  DatasetDefinition / DatasetPolicy / QueryCompiler / SQL 模板解析与渲染 / ProcessDefinition / 字典 / 错误码           │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 业务模块（只写声明 + 同步扩展点）：EntityDefinition、Dataset、*.sql 模板、ProcessDefinition、ComputeStep、规则       │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                                                     │
                                            PostgreSQL 16
      业务表（普通 / 只追加时态）  op_process / op_process_item  entity_registry  字典 / 参数  Outbox
```

## 5. 模块规划（阶段 2 起生效）

| 模块 | 内容 |
|---|---|
| `backend/core` → `jabiz-core` | 纯 Java 核心（见 01） |
| `backend/runtime` → `jabiz-runtime` | 响应式运行时 |
| `backend/ext-geo` | H3 空间编码、物理量等领域扩展语义类型（从核心移出） |
| `backend/app` | 启动模块和示范业务（物流运单、报关、运费月结；订单与库存 `com.jabiz.app.commerce`，阶段 11） |
| `frontend/` | 通用后台前端（可挂在子路径，16 §6） |
| `backend/build-logic` | 约定插件 `jabiz.boot-app`（阶段 13a，17 §3） |
| `docs/` | 设计文档与路线图 |

平台与应用分开开发：`platform` 分支只含上表内容；具体项目（如 culture）在各自的应用分支上增加自己的模块、公开前端与文档（17、D19）。

## 7. 术语

| 术语 | 含义 |
|---|---|
| 实体定义（EntityDefinition） | 一个业务对象的元数据：物理表、字段、语义类型、规则、状态机 |
| 语义类型（SemanticKind） | 字段的业务语义，决定转换、校验、查询约束和前端渲染 |
| 数据视图（Dataset） | 对某实体存储的一种带策略、带范围的访问方式 |
| 时态实体 | 启用只追加双时态模型的实体（见 04） |
| 操作（process execution） | 一次流程执行，对应 `op_process` 的一行，由 `process_seq_id` 标识 |
| 操作范围 | 一次操作写入的全部实体版本，记录在 `op_process_item` |
| 生效时间 `effect_start_time` | 业务上从何时起生效；不预定时等于记录时间 |
| 记录时间 `created_time` | 系统记录该版本的时间，等于该操作的 `op_time` |
