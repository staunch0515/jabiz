# jabiz 平台功能清单（供整理需求使用）

本清单按能力领域列出平台**已经实现**的功能（线 1.1，阶段 1–14r），供整理基于本平台的应用需求时对照使用：

- **需求不必重复描述平台已有的机制**（历史、审计、权限检查、校验、幂等、只追加……），只需写"用哪一项、怎样配置"。
- **需求应把平台需要的"声明"写清楚**：每一节的"写需求时应给出"列出了平台为了工作而需要业务方回答的问题。把这些问题逐条回答，需求就能直接落成声明。
- **平台不做的事**在每节末尾与第 20 节单独列出：需要它们时必须显式提需求（并可能需要先改平台，见 17 与 CLAUDE.md 第 8 节）。

设计原文：`docs/design/`（00–22）；约束性决策：`docs/design/09-decisions.md`（D1–D31）；各阶段验收：`docs/ROADMAP.md`。
名词：**实体**＝一个业务对象的元数据；**数据视图**＝对实体的一种带范围与策略的访问方式；**流程**＝一次业务操作（一个事务、一条操作记录）；
**时态实体**＝只追加、按时间点查询的实体；**SQL 模板**＝带 YAML 头的手写 SQL；**报表**＝头部声明了 `report` 的模板；**单据**＝多区块的 PDF（发票、确认书）。

## 1. 数据建模（元模型，02）

**已实现**

- 用 Java DSL 声明实体（`EntityDefinition.define`），编译期检查；可导出 JSON（给前端）与 JSON Schema（给工具与 AI）。
- 语义类型（决定转换、校验、可用运算符、前端控件与导出格式）：业务标识（UUID）、金额（币种 + 小数位，`BigDecimal`）、时刻（带角色：事件时间 / 记录时间 / 生效起止）、日历日期（与时区无关）、字典编码、文本（长度、多行）、数值（精度）、布尔、引用（指向另一实体）、乐观锁版本、自定义类型（SPI）；扩展包 `ext-geo` 提供物理量与 H3 空间编码。
- 逻辑名与物理名分离：接口、规则、模板只用逻辑名；可对接遗留表。
- 规则只定义一次：六种可导出规则（范围、小数位、长度、正则、不晚于现在、非空白）由前后端共用，同一非法输入两端报同一错误码；依赖服务端状态的规则写成仅服务端规则；错误全部累积后一次返回。
- 实体级校验（跨字段规则）：在完整候选状态上评估，所有写入途径都经过。
- 状态机：迁移表、显式或推导的初始状态、迁移守卫（可按"任意→某状态"）；状态不能清空；非法迁移 422。
- 字典：静态字典（代码中声明，三语标签）、固定值、SQL 字典（模板返回）、数据库字典（平台时态实体，有历史、可预定生效、多实例缓存失效）；输入只接受启用项；接口 `GET /api/dictionaries/{urn}`。
- 唯一性声明（`eb.unique`）：普通实体建同名唯一索引并自检；时态实体用咨询锁 + 当前与预定版本检查，预定版本中的重复也被拒。
- 字段标记：`sensitive`（密码等：读不返回、只专用流程能写、日志遮蔽）、`processOnly`（只由流程改变，照常可读）、`auditMasked`（可读可写但不进审计）、`masked`（按权限显示明文，见 14）、`immutable`、`generated`、`required`。
- 实体标记：`display`（被引用时显示哪个字段）、`publishChanges`（每次写入发布变更事件）、`temporal` / `allowScheduled` / `writeOnce`。
- 列表视图：列、可筛选字段、可排序字段、默认排序（白名单，违反 400）；分页稳定（总追加主键排序）。
- 启动自检：表与列存在、类型兼容、字典有来源、文案齐全、索引与触发器齐全……全部问题一次报告。

**写需求时应给出**（每个业务对象）

1. 字段清单：逻辑名、语义类型（金额写币种与小数位；时间区分"时刻"与"日期"）、必填、不可变、长度 / 精度。
2. 字段规则（范围、格式、长度等）与错误提示文案（zh / ja / en；应用只选部分语言时只写所选的）。
3. 跨字段规则（实体级校验）与其错误码。
4. 字典：取值与三语标签；由谁维护（代码里固定 / 后台维护且可预定生效 / 由某查询给出）。
5. 唯一性约束（哪些字段组合）。
6. 状态机：状态、允许的迁移、初始状态、迁移条件（守卫）。
7. 哪些字段只能由流程改变；哪些是秘密（`sensitive`）；哪些是"部分人才能看明文"（`masked`，见 14）；哪些不进审计。
8. 列表页显示哪些列、允许按哪些字段筛选与排序、默认排序；被引用时显示哪个字段。
9. 是否需要历史与按时间点查询（缺省应为是，见 3）；是否允许预定生效；是否"只记一次、以新记录更正"。
10. 是否需要向其他模块发布变更事件。

**平台不做**：拖拽式设计器；在线修改元模型（元模型在代码里，随版本发布）；一个字段多个文件（用子实体）。

## 2. 数据视图与访问范围（03）

**已实现**

- 一个实体多个视图（后台全量、会员只看自己、报表只读走读库……），恰好一个默认视图；每个视图声明读 / 写权限码（未声明即拒绝）。
- 范围：固定值、取自请求上下文（操作人、租户，取不到即 403）、数据期限（调用者只看某一期间，见 14）；范围同时约束读与写（插入自动填充、不能移出范围）；手写 SQL 模板同样绕不过范围。
- 策略：只读、逻辑删除（普通实体）、单次查询与写入条数上限、查询超时、禁止时间旅行、只经流程写入（`processOnlyWrites`：接口与通用流程不能写、撤销不可）、公开读取（见 12）、写入要求二次验证。
- 接口：按主键读、查询（白名单筛选 / 排序 / 分页，时态实体可带 `asOf` / `knownAt`）、批量提交（增改删、预定、取消预定、追溯更正带原因）、历史、按显示字段搜索（`lookup`）、批量取显示文本（`labels`）、逐值显示明文（`reveal`）。
- 元数据目录 `GET /api/meta/datasets` 只列调用者可读的视图，前端据此生成页面。
- 负载保护：浏览类查询在数据库一侧按时限中止（超时 503，不占着连接继续跑）；一页未取满时不再另跑计数查询；每页上限只限浏览，不影响流程中的读取（见 4）。

**写需求时应给出**

1. 每个业务对象需要哪几种视角（谁看全部、谁只看自己 / 本部门 / 本租户、报表视角），各视角的范围依据什么字段。
2. 各视角的读、写权限码；哪些视角只读；哪些只能由流程写入。
3. 是否允许按历史时间点查看（默认允许）；每页上限。
4. 哪些数据受"数据期限"限制（见 14.9），按哪个时间字段。

**平台不做**：按字段的读权限（除 `masked` / `sensitive` 外，一个视图的列对持有读权限者全部可见——按列可见性用多个视图或遮蔽字段表达）。

## 3. 历史、追溯与操作记录（04）

**已实现**

- 时态实体的表只插入：修改＝新版本、删除＝墓碑；数据库触发器拒绝 UPDATE / DELETE / TRUNCATE（受控清除除外，未在 MVP 开放）。
- 双时态：生效时间与记录时间分开；任意时点查询（`asOf`）、"按当时所知"查询（`knownAt`）；更正不篡改，更正前的值仍可查。
- 预定生效（如下月起调价）：到期自动生效，无定时任务；预定存在时的其他修改自动变基，改同一字段则拒绝并列出冲突；取消预定。
- 追溯更正：需权限 `temporal.backdate` 与原因；之后已生效的版本自动变基。
- 操作记录（`op_process`）：每次流程执行、每次数据视图提交都是一次操作，记操作人、流程与版本、时间、原因、遮蔽后的输入摘要、所有写入的版本与改动字段；子操作指向父操作；操作详情接口。
- 撤销（`temporal.revert`，原因必填）：字段粒度冲突检测，后续改了同一字段即拒绝并列出阻塞操作；子操作一并撤销；可重做；只经流程写入的字段与敏感字段不可被撤销改回。
- 幂等：`Idempotency-Key` 请求头，同一人同一键只执行一次并重放结果。
- 规模：按不可变字段（单号、引用）查询与表大小无关；只写一次的实体读取更快；唯一约束缺索引时启动告警。
- 业务参数（`SysParam`）：带生效时间的费率、阈值等，可预定、可取消；规则按业务发生时间读取参数；后台可维护。
- 同一操作内所有写入时间一致；失败的操作不留痕（随事务回滚）。

**写需求时应给出**

1. 哪些对象需要历史与时点查询（建议全部业务对象），哪些是高频计数 / 日志类（不开时态）。
2. 哪些对象允许"预定生效"；哪些允许追溯更正，谁有权。
3. 哪些操作允许撤销，谁有权；哪些对象只写一次、以新记录更正（如账本）。
4. 哪些数值是"带生效时间的业务参数"（税率、费率、阈值），各自的类型与维护者。
5. 需要"按当时所知"重现的场景（例如期末报表按某记录时点）。

**平台不做**：个人信息的物理删除 / 匿名化（受控清除与加密粉碎已设计、未开放，需单独立需求与决策）；对时态表的物理归档分区。

## 4. 业务流程（06）

**已实现**

- 流程＝一次操作＝一个事务（含子流程），结束时统一提交变更；任一步骤登记违规即整体 422 并一次返回全部违规。
- 业务方只写同步代码：计算步骤（纯计算）与阻塞步骤（调用外部 SDK，平台放到虚拟线程上）；不接触数据库与响应式 API。
- 平台 I/O 步骤：加载实体、查询实体、运行 SQL 模板（可指定时点）、立即保存、调用子流程（可按条件、可对列表逐项）、读取业务参数、取单据号、取得审批结论、撤回审批、发布事件、建待办、关闭待办、取命名锁、使公开文件缓存失效。
- 流程中的读取取**全部**结果（不按浏览的一页截断），超过 `jabiz.process.max-read-rows` 即 422 拒绝而不是悄悄少算。
- 命名锁 `HoldLock.shared / exclusive`：不能重叠的流程（如过账与关账按期间串行）声明同名的锁，持有到根流程事务结束；等待超时或死锁为 409。
- 输入 / 输出为 record，Bean Validation 自动校验，前端据此生成表单；秘密组件标 `@Sensitive` 自动遮蔽。
- 版本化（同名多版本共存、`latest`、废弃告警）；单步流程简写；流程目录接口；`actsOn` 把流程显示为实体行上的操作。
- 提交后步骤（`AFTER_COMMIT`）：外部调用在事务提交后执行，进程内重试并记录每次尝试。
- 试运行（`DRY_RUN`）：执行完整流程后整体回滚（导入预览即此）；保存点（平台内部，导入按单元回滚）。
- 每个流程声明权限码（未声明即拒绝）与可选的二次验证要求；流程 API 另做职责分离兜底。
- 通用实体流程（新增 / 修改 / 删除任一实体）由平台提供，供后台通用表单使用。

**写需求时应给出**（每个业务操作）

1. 操作名、输入、输出、谁有权执行（权限码）、是否要求二次验证。
2. 读哪些数据、算什么、改哪些数据、违反哪些规则时拒绝（错误码与文案）。
3. 是否由其他操作组合而成（子流程）；是否要调用外部系统（放在提交后，或改为发布事件）。
4. 是否作为某实体行上的操作显示、在什么状态下显示。
5. 是否需要防重复提交（通常由前端的幂等键自动覆盖，无需另写）。
6. 需要的编号、审批、待办、事件（见 7、9）。
7. 哪些操作彼此不能同时进行（例如同一期间的过账与关账、同一账户的两笔扣减），互斥的粒度（锁名由什么组成）。
8. 流程中一次读取的数据量级（上限缺省 10 万行，超过要拆小或改为汇总）。

**平台不做**：图形化流程编排；长事务 / 跨数据库事务；人工环节的"流程实例状态机"（用审批 + 待办 + 事件表达，见 7）；流程事务内读取的数据库侧时限（只有应用侧超时）。

## 5. 查询、SQL 模板与报表（05、19）

**已实现**

- `.sql` 文件（YAML 头 + SQL）即查询：表、列只写占位符，平台解析物理名、附加数据视图范围、时态"当前版本"子查询、遮蔽字段投影；参数与结果带语义类型；列表参数数组绑定。
- 外层分页、白名单筛选与排序、总数；行数上限；执行权限（全部具备才可执行）。
- 预编译校验（`platformCheck` 与启动）：字段写错、结果列类型不兼容、参数未声明、禁用写法等在 CI 中一次全部指出；改物理列名模板不用改。
- 时点运行：请求的 `asOf` / `knownAt`，或头部 `timeSlice` 把某参数作为时点，让模板中的所有时态实体（含主数据）按同一时点读取；模板版本（内容哈希）。
- 模板目录 `GET /api/meta/queries`（有权运行的模板、参数 Schema、结果列、筛选排序、时点、是否报表）。
- 报表＝头部声明 `report`（期间参数、横向）的模板：后台"报表"页面按分组列出、参数表单、时点选择、结果表格；标题与列名来自消息资源。
- 导出：CSV（精确小数、防公式注入）、XLSX（数值与日期单元格、页眉）、PDF（页眉页脚、页码、列宽、负数括号、逐字节确定）；超过上限拒绝不截断；中日文字体由配置提供。
- 签发存档（`REPORT_ISSUE`）：固定时点、规范化内容与哈希、保存模板全文与权限与数据范围；按存档原样重现（不重算）、核对（`identical` / `differs` / `template_changed`）、取代；读取需存档权限、模板权限与相同数据范围；事件 `jabiz.report.issued`。
- 平台自带模板：账本余额（含层级汇总）、维度余额、科目明细、币种余额、访问权限报表。

**写需求时应给出**（每个查询 / 报表）

1. 用途、参数（含是否列表、必填、缺省）、结果列及其类型、允许的外层筛选与排序、默认排序、执行权限。
2. 是否是报表（出现在报表页面）：期间参数、横向 / 纵向、标题与列名的三语文案。
3. 是否需要按时点重现（期末、按当时所知）；是否需要签发存档与核对；谁能签发、谁能读存档。
4. 导出格式与行数量级；是否需要中日文 PDF（部署时配置字体）。
5. 公司名、报表时区、区域格式（应用级配置）。

**平台不做**：图表 / 透视（在应用扩展页中自行渲染）；报表设计器；跨库查询；汇总表 / 物化视图（大表按可变字段的汇总由应用自行维护）。

## 6. 单据（22）

**已实现**

- 代码声明版式 `DocumentLayout`：区块（发出方 / 收件方、键值、明细表、合计、说明文字、备注）、单号、对象实体、权限、缺省收件地址列；数据来自普通 SQL 模板；启动检查版式与模板的一致性。
- 签发（`DOCUMENT_ISSUE`，通常由业务流程以子流程调用并给出单据日期为时点）：按同一时点读取全部模板、排版 PDF（Letter / A4、并排区块、跨页重复表头、折行不截断、页脚页码）、保存 PDF 原样字节与规范内容、内容哈希与 PDF 哈希；事件 `jabiz.document.issued`。
- 重印取存档字节（平台升级不影响已签发单据）、下载前核对哈希；核对（`copyIntact`、`identical` / `differs` / `layout_changed` / `template_changed`）；预览（不保存、每页标"预览"）。
- 发送（`DOCUMENT_SEND`）：附件为存档字节，每个收件人一封，地址缺省取签发时存档的数据地址，发往其他地址需 `document.send.any`；投递与每次尝试只追加记录，失败重试；主题正文可按版式定制文案。
- 后台"单据"页（列表、筛选、下载、核对、发送、投递记录）；`DocumentPanel` 组件供应用扩展页使用；`actsOn` 流程即可在实体行上签发。
- 同一对象可多次签发，单据从不修改（更正用另一张单据，如贷项通知）。

**写需求时应给出**

1. 单据种类、各区块显示的字段、单号来源、对象实体、标题与区块文字（三语）、纸张。
2. 签发时点依据哪个业务日期；签发条件（例如只有已过账的发票）；谁能签发、谁能读存档、谁能发送。
3. 收件地址取自哪个数据列；邮件主题正文文案；是否允许发往数据以外的地址。
4. 发出方信息（公司名、地址、税号）来自哪个数据（应来自数据而非配置）。

**平台不做**：电子签章 / 数字签名；非 PDF 格式（电子发票 XML 等走"生成文件"，见 11）；打印机对接；短信 / 即时消息渠道。

## 7. 编号、审批、职责分离、待办与通知（18）

**已实现**

- 编号 `NumberSequence`：格式（固定文字 + `{n}` / `{n:宽度}` + `{scope}`）、按范围（年度、来源）各自计数、起始值；流程内取号，流程失败归还号码——无缺号、无重复、并发安全；每个号码的发放记录只追加可查。
- 审批：审批对象（可检验的事实：数字 / 文本 / 布尔）；规则为时态实体（条件 `all` / `any` 嵌套、优先级、0–5 个层级、每层所需权限与限额事实、可预定生效）；审批人限额；步骤 `RequireApproval` 得到 `NOT_REQUIRED` / `PENDING` / `APPROVED`，批准绑定单据内容哈希（内容改了原批准作废并建新请求）；`APPROVAL_DECIDE`：层级权限、限额、准备人不能审批、同一人不能判断两层、驳回需理由、并发只一个成功；事件 `requested` / `approved` / `rejected`，应用订阅事件继续原流程；撤回；评估记录（规则版本与事实）只追加；影响预览（规则草案对历史单据结论的影响）。
- 四眼修改：审批规则、限额、职责分离规则只经"提出 → 另一人发布"修改，可预定生效、可撤回。
- 职责分离：规则（互斥的两组权限）；授予角色或权限造成冲突即拒绝；流程入口对已存在冲突的操作人兜底拒绝；冲突报告接口。
- 待办 `SysTask`：指派给用户或权限（持有者皆可见、先做先关）、标题文案键 + 参数、关联实体、链接、截止、来源键；步骤 `CreateTask` / `CloseTasks`；审批请求自动产生逐层待办（标题为"审批 <对象显示名> <人认得的单据标识>（第 n 级）"）；"我的待办"接口与页面、页头计数；`ApprovalPanel` 组件。
- 邮件通知：新待办自动邮件（指派用户，或明确持有该权限的启用用户）；通知与尝试只追加、失败重试；`jabiz.mail.enabled` 缺省关闭。

**写需求时应给出**

1. 每种单据的编号格式、按什么范围计数（年度 / 公司 / 来源）、起始值、何时取号（通常在全部校验之后）。
2. 哪些单据需要审批：可检验的事实（金额、来源、类型……）、规则（条件、层级、各层权限、限额）、规则由谁提出 / 谁发布；批准后、驳回后分别做什么（事件消费者流程）；撤回条件；审批对象的三语显示名与待办中显示的单据标识（单号而不是主键）。
3. 职责分离规则（哪些权限不能同时持有）。
4. 哪些事情要生成待办（给谁：用户还是权限）、标题文案、链接到哪个页面、截止时间、何时自动关闭。
5. 是否开邮件通知、发件人与邮件服务器（部署配置）。

**平台不做**：代理审批 / 转签；审批委托期；移动端推送、短信、即时通讯；待办的 SLA 升级（可用定时任务 + 流程自行实现）。

## 8. 账本（11 §1）

**已实现**

- 科目（代码、类型、启用、上级、汇总科目）、交易、分录为平台时态实体；交易与分录只写一次、只经 `LEDGER_POST` / `LEDGER_REVERSE` 写入（接口与撤销都拒绝）。
- 过账校验：2–200 行、金额为正且不超小数位、借贷平衡、科目存在且启用且可过账；数据库提交时触发器兜底平衡。
- 冲正：借贷互换的新交易、指向原交易、一笔只能冲正一次；更正即冲正。
- 科目层级（汇总科目不能过账、层级规则检查、改层级与过账互斥）；分析维度（1–4 个，来源为字典或实体的文本、代码、身份（主键）、引用字段，如按用户或供应商编号；过账时校验）；行备注；来源单据（实体 + 主键，报表可钻取）。
- 多币种：本位币金额 + 币种、交易金额、汇率；换算四舍五入；每个外币各自平衡；冲正照复制。
- 模板：科目余额（区间、按当时所知、层级汇总）、维度余额、科目明细（期初 / 滚动 / 期末）、币种余额。
- 本位币与小数位由应用配置（`jabiz.ledger.currency` / `scale`）；账本可按数据期限限定审计师可见范围。

**写需求时应给出**

1. 本位币与小数位；科目表（代码、名称、类型、层级、哪些是汇总科目）。
2. 每种业务事件的会计分录（借贷科目、金额来源、过账时间取哪个业务时间、来源单据、备注）。
3. 分析维度（名称、取值来源）。
4. 外币业务：汇率来源（属于应用）、汇兑差额科目。
5. 需要的财务报表（在账本模板之上用 SQL 模板声明，见 5）。

**平台不做**：汇率表与取价；期末结转 / 关账流程；预算；多账套（一个部署一本账本）。

## 9. 事件与定时任务（11 §2、§4）

**已实现**

- 事务性 Outbox：流程内 `PublishEvent`，或实体 `publishChanges()` 自动发布变更事件（只含字段名不含值）；事务回滚即无事件。
- 投递：至少一次 + 消费端只处理一次（消费标记与消费者流程同一事务）；失败按指数退避重试、记录每次尝试；消费者就是流程（`EventSubscription`），以系统身份执行；新增订阅可收到历史事件。
- 定时任务 `JobDefinition`：cron + 时区 + 调用的流程；多实例集群锁；同一计划时刻至多执行一次（幂等键）；执行记录只追加；任务列表接口；停机期间错过的时刻不补跑。
- 平台事件：实体变更、审批请求 / 批准 / 驳回、待办创建、报表签发、单据签发、导入提交。平台任务：文件清扫、封存、校验。
- Webhook（把事件送给其他系统）：订阅写在配置（名称、事件类型、地址、来自环境变量的密钥），每个订阅是一个独立的 Outbox 消费者；平台以签名的 POST（HMAC-SHA256，时间戳 + 正文）投递，2xx 即送达，否则记录尝试并按退避重试、不跟随重定向；目标主机白名单、仅 https；启动检查配置；业务代码不自己发 HTTP 请求。

**写需求时应给出**

1. 哪些业务事件要通知其他模块；消费后执行什么流程；重复投递下的幂等由平台保证，需求只需说明消费动作。
2. 定时业务（月结、对账、提醒）：cron、时区、调用的流程、输入（通常由计划时刻推导）、错过是否需要人工补跑。
3. 要推送给外部系统的事件：接收方、地址、密钥的管理方式、载荷中可以包含哪些字段（有订阅的事件不放遮蔽字段的值）；接收方按事件 ID 去重并验证签名。

**平台不做**：外部消息系统（Kafka 等）；事件顺序保证；经界面增减 Webhook 订阅（只能改配置并重启）；入站 Webhook（接收外部系统的回调需另立需求）。

## 10. 导入（20）

**已实现**

- 文件先经文件上传（策略只允许导入类型 TEXT / XLSX / XML，原样保存、只作附件）。
- 版式：CSV（分隔符、表头、跳过行、字符集可调）、定宽、XLSX（工作表、表头行；日期、公式结果、15 位精度）、XML（路径取值、文件头）、自定义解析器 SPI；XML 一律禁 DTD；行数、单元格、解压大小上限，超出整体拒收。
- 导入定义 `ImportDefinition`：字段（语义类型、必填、缺省列名）、按行或按组交给**手工录入所用的同一个业务流程**、整个文件的检查（如借贷相等）、控制合计、外部引用（重复时跳过或报错）、时区与日期格式、权限、每次导入的参数（表单自动生成）。
- 映射：字段取自哪一列或常量、版式调整；可按名保存（只追加）。
- 预览＝试运行：全部行执行再整体回滚，报告全部问题（含流程拒绝），不留任何数据与操作记录。
- 提交：有任何问题整体拒收并留下被拒记录；成功则写导入记录、外部引用并发布 `jabiz.import.committed`；同一文件只成功导入一次；并发提交只一个成功。
- 导入记录（结果、行数、重复、问题、控制合计、说明）、报告导出（PDF / XLSX / CSV）、后台向导与历史页；场景回放步骤 `import`。

**写需求时应给出**（每种导入）

1. 文件来源与格式样例、字符集、表头、日期格式、时区；每行字段与类型；外部唯一引用是什么、重复时跳过还是报错。
2. 每行（或每组、分组键）对应哪个业务流程；整个文件的检查与控制合计。
3. 导入权限；是否允许保存映射；每次导入的参数（期间、公司等）。
4. 导入的文案（三语）。

**平台不做**：定时自动拉取文件（可用定时任务 + 阻塞步骤获取后调用导入流程）；增量 / 更新型导入的语义（由行流程决定是新增还是更新）；格式之外的业务映射表（供应商代码→科目等属于业务数据，由行流程查询）。

## 11. 文件（14）

**已实现**

- 上传 `POST /api/files?policy=`：按魔数判定类型（JPEG、PNG、PDF、MP3、M4A、OGG；导入专用 TEXT / XLSX / XML）；永不接受 SVG / HTML / 脚本；超限边读边中止；上传限流。
- 图片：解码前防解压炸弹、按 EXIF 转正、重新编码去掉全部元数据（含 GPS）、按宽度生成变体；PDF 与音频以附件 + 沙箱提供；音频支持 Range。

- 文件是普通表、可真正删除：手动删除（被引用时拒绝）、每日清扫孤儿行与对象（受保留期 / 法律保全的跳过）；上传与删除都有操作记录，文件名不进操作摘要与审计。

- 存储：本地目录（单实例）；S3 等按同一接口以后加入。

**写需求时应给出**

1. 每类文件：允许的类型、大小上限、是否图片及需要的尺寸、谁能上传、谁能查看；挂在哪个实体的哪个字段（多个文件用子实体）。
2. 文件何时可删除（随哪个业务流程）、保留期。
3. 服务器生成的文件：格式与规范（NACHA、XML 申报等）、文件名规则、读取权限、保留期。
4. 多实例部署时的共享存储方案（部署需求）。

**平台不做**：WebP / HEIC；视频；病毒扫描（预留 SPI）；对象存储（S3）实现；文件版本。

## 14. 安全（10）

**已实现**

1. **认证与会话**：用户名密码（BCrypt）；JWT 短期访问令牌 + 轮换的刷新令牌（重用即吊销整族）；登出、改密吊销；闲置锁定（服务端与前端）；令牌表只追加。
2. **登录保护**：失败计数与锁定（阈值、时长可配）；并发猜密码不能绕过；不泄露用户名是否存在；每次尝试写登录记录。
3. **RBAC**：用户、角色、角色权限、用户角色（可预定生效、可带数据期限）、菜单、登录记录——都是平台时态实体，经后台维护、有历史与审计；权限码即数据视图 / 模板 / 流程声明的字符串；`*` 为全部权限；菜单按权限过滤成树。
4. **默认拒绝**：`/api/**` 必须认证；未声明权限的入口启动失败 / 请求拒绝；范围取不到即拒绝；缺密钥不启动。
5. **二次验证（TOTP + 恢复码）**：绑定、确认、重置（管理级）；角色可要求二次验证；验证码错误计入同一锁定、码不可重用；密钥加密存放。
6. **按操作要求二次验证（step-up）**：流程 `requiresMfa`、数据视图 `writeRequiresMfa`；平台管理操作缺省为管理级要求；前端自动弹出验证并重发请求。
7. **OIDC 单点登录**：授权码 + PKCE + nonce，多个提供方，平台校验 ID 令牌后签发自己的令牌；外部身份由管理员关联（不自动开户）；提供方的二次验证可按 `amr` 视同；只用单点登录的用户可无密码。
8. **敏感数据**：`sensitive` 字段与 `@Sensitive` 组件在日志、操作摘要、幂等结果、响应中遮蔽；密码规则（最短长度、BCrypt 强度）。
9. **按权限显示明文（`masked`）**：银行账号、税号等在读接口、历史、审计、模板、导出中一律遮蔽（样式：末 4 位 / 全部 / 纳税人号码）；持有权限者逐值显示并留记录（`sys_reveal_record`，可查询）；写入、筛选、排序需权限；签发的报表一律遮蔽。
10. **数据期限**：角色分配带 `dataFrom` / `dataTo`，受限者只能看声明了 `withinDataPeriod` 的视图中期间内的数据（含账本、审计），期限外写入被拒；令牌与页头显示期限。
11. **访问审查**：访问权限报表（用户 × 角色 × 权限 × 最近登录，按期末签发）、期间内安全变更与职责分离冲突、签核流程（要求二次验证）与只追加记录、后台页面。
12. **首个管理员**：由环境变量在空库上自动创建。
13. **用户显示名**：数据只存用户编号；页头、待办、审计、历史、操作详情、访问审查等按编号显示名字（`GET /api/users/names`，不泄露登录名；多租户时只含本租户）；扩展页用 `UserName` 组件。

**写需求时应给出**

1. 角色清单与各角色的权限码（按 1–13 节各能力的权限）；哪些角色要求二次验证；哪些操作总要求二次验证。
2. 是否接入单点登录：提供方、是否信任其二次验证、账号关联方式；密码策略是否需要比平台缺省更严（需提平台需求）。
3. 哪些字段"部分人才能看明文"、遮蔽样式、看明文的权限码；哪些用户（审计师、外包）只能看某一期间的数据、哪些视图受此限制。
4. 访问审查的周期与签核人。
5. 令牌有效期、闲置时长、锁定阈值等参数（部署配置）。
6. 菜单结构（代码、父子、路径、图标、所需权限、三语名称）。

**平台不做**：SAML；单点登出；密码复杂度 / 历史 / 过期策略（只有最短长度）；IP 白名单；审批式开户 / 自助注册；行级"字段读权限"之外的 ABAC。

## 15. 审计、防篡改、保留与导出（21）

**已实现**

- 审计记录：每次实体写入（普通与时态）在同一事务记前后值（只记变化字段）、操作人、时间、原因、流程；敏感与不进审计的值只存 `***`，遮蔽字段存遮蔽形式；按实体 / 人 / 时间 / 流程 / 字段查询，可一并列出该记录的审批人与结论；后台审计页与历史页入口；操作记录（谁在何时执行了什么）另有接口。
- 防篡改封存：所有只追加表的每行摘要进入 HMAC 哈希链的块（每 5 分钟），校验（每天）报告被改、缺失、断链、保护被关闭、换密钥；表结构演进不影响旧块；最新块哈希可留存系统外；接口与页面。
- 保留期 `RetentionPolicy`：按时间或日期字段、可自会计年度末起算；保留期内与受法律保全的删除一律拦截（所有删除路径，含文件清扫与撤销）；到期报告。
- 法律保全：按主键列表或"字段 = 值"下达、须写原因解除；只经流程修改。
- 开放格式导出 `POST /api/exports/data`：所选数据视图的 CSV（按时点、按权限与范围、敏感字段不导出）+ `schema.json` + `manifest.json`（哈希、链锚点）+ 期间内已签发报表 PDF；写操作记录；后台页面。

**写需求时应给出**

1. 每类记录的法定保留期与起算依据（单据日期 / 会计年度末）；会计年度末月份。
2. 谁能查审计、谁能查看明文显示记录、谁能下达 / 解除法律保全、谁能导出。
3. 封存密钥的保管与备份方案，最新块哈希的外部留存方式（运维需求）。
4. 到期后的物理删除 / 匿名化需求（平台未开放，需另立决策）。

**平台不做**：到期自动删除；匿名化；WORM 存储对接；外部时间戳服务。

## 21. 需求整理检查清单

对每个**业务对象**：字段与类型 → 规则与文案 → 字典 → 唯一性 → 状态机 → 只经流程写入 / 敏感 / 遮蔽 / 不进审计的字段 → 列表列、筛选、排序 → 显示字段与子实体 → 时态 / 预定 / 只写一次 → 视角（数据视图）与各自权限、范围、数据期限 → 变更事件 → 文件字段与策略 → 保留期。

对每个**业务操作**：输入输出 → 权限与二次验证 → 读取、计算、写入 → 拒绝规则与错误码 → 子流程 → 外部调用（提交后或事件） → 编号 → 审批（事实、规则、层级、限额、继续方式） → 待办与通知 → 行操作显示条件 → 账本分录 → 单据签发与发送 → 场景回放用例。

对每个**查询 / 报表 / 单据 / 导入**：参数与结果 → 权限 → 筛选排序 → 时点与存档 → 导出格式 → 文案 → （导入）文件样例、行流程、去重、控制合计 → （单据）区块、单号、收件人。

对**整体**：角色与权限码矩阵 → 职责分离规则 → 菜单 → 语言与区域 → 本位币与会计年度末 → 单点登录与二次验证策略 → 公开访问范围 → 定时任务 → 保留期与法律保全 → 访问审查周期 → 部署与性能要求 → 平台不做的事中需要哪些（另立需求）。
