# R-001 First-version planning document

- Source: *UBOS Digital Business Chip Platform · First-Version Planning Document*, 2026-09-30 (PDF, owner)
- Class: v1 must · Status: planned (P0–P4)

Summary of the original (the PDF is the authoritative text; keep a copy under `docs/requirements/source/` once the repository exists):

- A website: the user submits a requirement, the platform structures it and the user confirms, then AI builds a complete
  application from pre-made digital chips, and the user downloads and deploys it locally.
- Chips: Rust, closed source, binary delivery with an interface specification; one chip = one complete business capability;
  own data management; chips call each other; forms FFI / WASM / sidecar. Each chip has a datasheet: capabilities, interface
  (OpenAPI), configuration, call examples, known limitations.
- v1 choices: sidecar only; SQLite per chip; one generated stack (React + Node.js, TypeScript); docker-compose deployment;
  one scenario (small web shop order management); fixed chips (Product, Inventory, Order; Order calls the other two).
- Pipeline: requirement input → structuring → user confirmation → chip matching → all mapped? (else terminate) → AI generation
  in a sandbox → smoke test (start all services, call every feature; errors fed back, bounded retries) → package and download.
- Deliverable zip: `docker-compose.yml`, `start.sh` / `start.bat`, `README.md`, `app/`, `chips/*.tar`.
- Validation plan: 1 chips (criterion: three chips start under compose, Order calls the other two); 2 manual AI generation
  without a website (criterion: one-command start, all features work, less code and fewer fixes than from scratch);
  3 website (criterion: a person not involved completes requirement → local run alone). Step 3 only if step 2 holds.
- Out of scope in v1: see R-101 … R-108.
