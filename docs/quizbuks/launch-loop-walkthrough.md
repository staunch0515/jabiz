# 首次上线闭环：需求方走查清单（第 1–6 步）

给需求方在测试系统（`staging`）亲手走一遍用。内容与自动化的闭环测试 `quizbuks-web/e2e/tests/launch-loop.spec.ts` 的步骤一一对应
（计划 `plans/impl/F-F12.md`）：测试能跑通的，这里请用真实的页面和真实的邮件再走一次，看有没有哪里不顺、说不清或不好用。
界面里的叫法照词表 `glossary.md`。发现的问题记入 Q94 §7，已修的划掉，留到下一期的写明。

**钱的部分**：提交发布时的资金检查已随 F-M5 补在第 2′ 步；配送费、月账单与运营商结算不在这一轮：随 F-M6、F-M12 合并时，由各自的负责人在本文件末尾补几行，并在 e2e 的同一个文件里补对应的步骤。

**要先有的人**（彩排步骤见 `rehearsal-staging.md` 第 5–6 节）：一个运营商，有负责人和另一位能审核的成员；
发起方 A（已入驻、已改归这个运营商：平台管理系统的发起方页面里「改派运营商」）；发起方 B（同一个运营商，第 6 步用）；
学者 C（日本，邮箱已验证）、学者 D（第 4 步当 A 的店员，也是学者）；平台管理员两位（第 6 步建平台的图，要另一位批准）。
A 的奖品方式要允许「到店兑换」和「电子奖品」（平台管理系统，发起方的奖励方式）。

## 1. 知识结构图
- [ ] A 在发起方页面「发布 → 知识结构图」建一张图：节点「基础」（点亮要通过绑定它的发布，并写**证书名称**）、节点「进阶」（要先点亮「基础」才能答）。保存后提交。
- [ ] 运营商的另一位成员在运营商管理系统的审核队列里批准；批准之前，A 的页面上图在「审核中」，学者看不到。
- [ ] 批准后 A 的页面显示整张图，两个节点都在。

## 2′. 提交时的资金检查（F-M5）
- [ ] 平台管理员（两位，受控参数）打开「受众规则收费」（`qb.audience.billing.enabled`）；运营商负责人在运营商管理系统里给「性别」定日价（如 100）。
- [ ] A 做一个七天的发布，受众条件选「性别：女性」，不绑定节点。向导最后一步的「资金」一栏列出受众规则费（含税）、合计与可用额；A 的平台费账户是空的时，显示差额和「去充值」链接；提交被拒，提示写明各项金额，发布仍是草稿。
- [ ] 运营商负责人确认 A 的入驻赠送；A 用卡充值一点现金到平台费账户。再看「资金」一栏：够了；提交成功。A 的发布页有「预付款」一栏（冻结中），平台费账户有「冻结在预付款中」一行，赠送额度先用掉、现金只扣差额。
- [ ] A 撤回这个发布：预付款显示「已退回」，赠送额度与现金都回到原处，「冻结在预付款中」消失。（审核驳回同样全额退回；发布结束后一天内退回剩余。）

## 2. 绑定节点的发布
- [ ] A 为「基础」做一个发布，奖品是**电子奖品**（共享链接）；为「进阶」做一个发布，奖品是**到店兑换**（写清楚领什么）。题目新建即默认**乱序**。
- [ ] 两个发布提交后由运营商成员批准；A 的邮箱收到「发布已通过」的邮件；A 的发布列表里两条都是「进行中」。

## 3. 学者答题、点亮
- [ ] C 在手机上打开 App：首页（搜索）看不到「进阶」的发布，只有「基础」的；知识结构图里「进阶」是锁定的，点它说明要先点亮「基础」。
- [ ] C 答「基础」（每次题目顺序不同；先选后提交）并通过；「我的 → 知识结构图」里出现这张图，已点亮 1 / 2。
- [ ] 图上「基础」已点亮、「进阶」可以答；C 答「进阶」并通过，整张图点亮。

## 4. 领奖
- [ ] 电子奖品：结果页点「显示奖品」才出现链接；复制；确认。A 的「电子奖品」列表看得到状态，看不到链接本身。
- [ ] 到店兑换：C 的「已答 → 待领奖」里有这一份。A 在发起方中心 → 店员里按 D 的 ID 加 D 为店员；D 在「我的 → 设置 → 店员柜台」打开柜台。
- [ ] C 在「扫一扫 → 出示领奖码」给 D 看六位数字；D 在柜台输入、核对奖品与学者名、点交付。C 的结果页变为「已领取」；A 的「到店兑换」列表有 D 的名字。

## 5. 证书
- [ ] 点亮「基础」的那一刻 C 有了证书（颁发方是 A 的公司名，没有有效期）：「我的 → 我的认证」里下载 PDF，能打开。
- [ ] 不登录的浏览器（新开无痕窗口）打开证书的核实页：显示「有效」、颁发方、点亮日期，没有「有效期」。

## 6. 平台的图与发起方点亮平台节点
- [ ] 平台管理员建一张平台的图（学者点亮的），节点带证书名称，另一位批准；运营商的官方账号（直营发起方）绑定一个发布；C 答题点亮；证书的颁发方是平台名。
- [ ] 平台管理员建平台模板（发起方点亮的，节点带赠送额度；提议并发布参数 `qb.tree.grant.max-per-node`、`qb.fee-credit.grant.enabled`、`qb.tree.gate.digital-prize-node`）；
      运营商复制模板并经另一位成员生效；官方账号在副本的节点上发布「挑战」。
- [ ] B 在发起方页面「发起方中心 → 挑战」答题（可以只用键盘）并通过：结果页说明节点点亮、可以给电子奖品、赠送额度已到账（平台费账户里有一笔「赠送额度」）。
- [ ] 另一位发起方答错，结果页说「等下一场」；学者 C 在 App 里开始这个发布被拒绝（学者看不到发起方的挑战）。
