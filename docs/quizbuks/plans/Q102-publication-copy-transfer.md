# Q102 复制发布换 Quiz 与时间、发布设置的导出与导入（2026-11-05 需求方确认）

需求方 2026-11-05："目前的发布太繁琐"。讨论过"发布模版"（模版审核后免审、自定义参数、定期发布），需求方的结论是：**发布有了导入导出加复制，模版的意义不大**，今天就要。
所以本期只做两件、只改商家后台；模版、模版审核与免审、自定义参数、定期发布、按公司邮箱域名的受众（以后作为规则库中的一种规则，Q47c）都**不做**，真需要免审时再议。

## 1. 决定

| # | 决定 |
|---|---|
| D-Q102-1 | **复制可以换 Quiz 版本与时间**：复制对话框选 Quiz 与版本（缺省为原来的）、开始时间（缺省为下一个整点）、天数（缺省为原来持续的天数，向上取整）、名称（留空按服务端的"…（副本）"）。后端的 `QB_PUBLICATION_COPY` 本来就接受 `versionId`、`startAt`、`endAt`，不改 |
| D-Q102-2 | **发布设置的导出**：发布页"导出设置"下载一个 JSON（`format: quizbuks.publication-settings`，`version: 1`）：名称、满分、持续天数、时限、合格线、抽题数、报名费、预算、名额、档位、奖励方式与说明、电子奖品的方式与说明、受众方式与地区、推荐、语言与译文、客户匹配条件。**不含**：Quiz 版本与时间（导入时选）、封面与采购单（本账户的文件与记录）、邀请名单、电子奖品的码与共用码（服务端密封的秘密）、前置条件（指向本账户的其他发布） |
| D-Q102-3 | **发布设置的导入**：发布列表"导入设置"选文件，再选 Quiz 版本、开始时间、天数与名称，生成新草稿；保存只经 `QB_PUBLICATION_SAVE` 与 `QB_PUBLICATION_AUDIENCE_SAVE`，规则与手填完全相同，问题照常列出。条件保存失败时草稿保留、提示到"对象"一步去设 |
| D-Q102-4 | **换满分时按比例换算**：复制或导入到满分不同的版本（按服务端给出的满分，含抽题），合格线与档位按满分的比例换算（四舍五入；每档从同比例处开始、到下一档之前结束，最后一档到满分，缩成空的档位去掉），再保存一次并提示"已从满分 X 换算为 Y，提交前请检查" |
| D-Q102-5 | 复制与导入完成后**直接打开向导的最后一步**（检查与提交），一屏看到全部问题与预计支出 |
| D-Q102-6 | 名称改了时，文件中名称的译文不带入（它们是旧名称的翻译）；其他译文照带 |

## 2. 实现（`quizbuks-web/sponsor/src/publishing/`）

- `settings.ts`（纯函数）：文件格式、`settingsOf`、`parseSettings`（只查形状，类型不对的值丢掉而不猜，较新的格式版本拒绝）、`rescaleTiers` / `rescaleForm`、`formOfSettings`、时间的辅助。
- `transfer.ts`：`copyOnto`、`importSettings`、`exportSettings`（只调用已有的流程与读取）。
- `PublicationTransfer.tsx`：共用的"Quiz、版本、开始、天数、名称"、复制对话框（取代 `PublicationActions` 中原来的）、导出与导入按钮；文案 `publishing.transfer.*` 三语。
- 后端、数据库、OpenAPI 都不变；`qb/brand-profile.test.ts` 把文件格式名列为允许的标识（两个 SPA 的 `qb/` 同步）。

## 3. 测试

- `settings.test.ts`：写出不含的字段、读回、拒绝其他文件与较新的格式、换算（覆盖完整、最后一档到满分、空档去掉、问卷）、草稿与手填同样的保存输入、改名不带译名。
- `publishing.test.tsx`（Q102）：同一版本的复制（时间、不再保存、打开最后一步、axe）、换满分的复制（再保存的合格线与档位）、导出后导入（文件内容、选 Quiz 后保存与条件、axe）、不是设置文件。
- e2e `sponsor.spec.ts`：复制改为在对话框中确认版本与名称、打开最后一步、开始在未来；新增导出后导入的往返。
