# Q68 App 中的商户

需求方 2026-10-31：几乎所有商户也是答题人，商户也可能从答题人的页面升级而来。在 App 中给同时是商户的人看商户的基本运行情况；手机上以查询为主，操作越少越好：
只有发布的暂停与恢复（不怎么影响资金），其他影响 Kudos 的一律只看、不做（复杂的功能留在电脑上的商户后台）。入口在顶栏；商户的消息并入 Inbox，加分类。

## 1. 安全

- App 的登录照旧只接受 `QB_TAKER`（平台 D36：令牌只含入口所接受角色的权限），手机上 30 天的会话里从来没有充值、发布、编辑的权限。
- 新权限 `qb.sponsor.app`，`QB_TAKER` 与 `QB_SPONSOR` 都持有；它只开放下面的模板与两个流程。隔离靠商户数据视图的范围（`fromContext(publisherId|ownerId|userId, actorId)`：只有调用者本人的行）；平台运行模板时只查模板自己的权限、范围照样生效。不是商户的答题人读到零或无行，别人的发布 404。
- 暂停与恢复照旧要求已验证邮箱、先查封禁；管理员暂停的商户不能恢复（`QB_PUBLICATION_ADMIN_PAUSED`），在 App 中也一样。
- 部署后执行一次 `QB_SETUP`，把 `qb.sponsor.app` 加给两个角色；在此之前商户后台的仪表盘、趋势与暂停 / 恢复也会被拒（它们改为只要求 `qb.sponsor.app`）。

## 2. 内容

- **顶栏**：有商户账号的人在搜索旁有"商店"图标，进入 `/my-sponsor`；有余额不足的发布时图标上有小圆点（可读名称同时说明）。
- **我的商户**（`app/src/mysponsor/`）：头像、公司、入驻状态（未批准只提示到电脑上完成入驻）；今天的数字（进行中、正在答题、今天发出、可用余额、剩余预算、已暂停、待发奖励、更新时间，模板 `qb.sponsor.dashboard`）；
  进行中的发布（待开始、进行中、已暂停、余额不足，模板 `qb.app.sponsor-publications`：开始、答完、通过、正在答题、已发出与预算、结束时间、谁暂停的），每项可展开近 7 天的表（按部署时区的日，`qb.sponsor.analytics.trend`），
  以及确认后的暂停 / 恢复（管理员暂停的不给按钮，注明到商户后台查看）。页尾"打开商户后台"（`/sponsor/`）。
- **Inbox**：商户本人的消息（行动为 `CASH` / `REDEEM` / `DIGITAL` 的：现金奖励、领奖申请、电子奖品）分类为 `SPONSOR`（"商户"，只对商户显示这一选项），打开后注明在电脑上的商户后台处理、按钮进入"我的商户"。
  平台发给全体商户的公告不并入：App 的收件箱模板不能同时以两种视图读 `QbSponsor`（显示商户名用缺省视图），要并入须另加"本人是商户"的判断并改三处匹配（`InboxMatchIT`），收益小，仍在商户后台与邮件中。

## 3. 测试

- 后端：`SponsorInAppIT`（以答题人的令牌读本人的账号、发布与仪表盘，不是商户的什么也没有，别人的发布 404；暂停与恢复本人的，管理员暂停的 422；充值、提交、确认现金 403）；
  `AnalyticsIT`（仪表盘与趋势对答题人开放、只有本人的零；其他分析模板照旧只给商户；`qb.sponsor.app` 只在两个角色中）；`RewardMethodsIT`（商户的现金消息在 App 中为 `SPONSOR` 分类，答题人自己的不在）。
- App：`mysponsor.test.tsx`（顶栏入口只给商户、小圆点；页面的数字、发布、近 7 天、无障碍；暂停与恢复先确认、管理员暂停的没有按钮；入驻中的提示；Inbox 的分类与商户消息的提示）。
- e2e：`sponsor-in-app.spec.ts`（同一地址在 App 注册后加入，从顶栏进入"我的商户"，暂停、恢复，App 的令牌不能充值）。
