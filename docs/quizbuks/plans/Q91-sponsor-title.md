## 1. 需求原文与理解

> 现在那个"商户"的名字，我也决定可以商户自己起名字。让商户可以自己定义 title，这也是一个平台节点。现在所有页面显示"商户"的地方都改成来自商户的 title，默认是"商户"。

理解：

1. **称呼（title）**是"别人怎么称呼这家商户"这一类名词，例如"学校""老师""店铺""工作室""诊所""教练"。它不是商户的名字（公司名、店名，如"拉面 B"），名字照旧。
2. **默认是"商户"**：没有定义称呼、或者还没解锁这项功能的商户，一律显示"商户"。
3. **定义称呼是一项平台功能**，挂在平台知识结构图的某个节点上（Q90 附录 A 新增 `sponsor.title`）：商户点亮该节点后才能设置；节点失效（过期、熄灭）时恢复显示默认的"商户"，已设的称呼保留，重新点亮即恢复。
4. **凡是页面上指"这一家商户"的"商户"，都换成这家商户的称呼。**

## 2. 两种"商户"，必须分开（盘点 2026-11-04）

现在的文字里"商户"与"商家"混用，且有两种意思：

| 种类 | 例子（App 现有文字） | 处理 |
|---|---|---|
| **A. 指某一家具体的商户**（上下文里有这家商户） | 联系商户、与商户的对话、屏蔽商户、商户已关闭这个对话、等待商家支付、商家将付你现金、到商家处领取奖品、等待商家交付、商家逾期未发、商户的商品、你不是商家的店员、商家看不到你填写的内容（某发布的受众说明） | **换成这家商户的称呼** |
| **B. 指"商户"这一类身份**（与哪一家无关） | 成为商户、申请成为商户、商户条款、商户后台、所有商户在发布前都要经过审核、我的商户（答题者自己的商户账号）、收件箱分类"商户"、"来自想让你了解它们的商家的小测验" | **不换**，统一用平台的默认词"商户" |

同时把 B 类与默认词中的"商家"统一为"商户"（需求方定的默认词）；日文、英文同样统一一个默认词（待定，见 §6-6）。

A 类文字按出现的地方分三种做法：

- **前端页面**：页面已知道是哪家商户（发布、对话、奖品都带发布方），用该商户的称呼替换；文案改成带占位符，如 `联系{{title}}`。
- **邮件、站内信、推送**：发送时由服务端填入该商户在发送时刻的称呼（与语言一起），模板加参数 `sponsorTitle`。已发出的不变。
- **服务端的错误消息**（如"商户已关闭这个对话"）：带参数或改写成不需要称呼的句子，逐条定。

## 4. 称呼本身的规则（建议，待确认）

| 项 | 建议 |
|---|---|
| 语言 | 三语各一个（至少一种；缺的语言用默认词，不混用别的语言的称呼） |
| 长度 | 中文、日文 1–6 个字，英文 1–20 个字符；只能是一个名词，不含标点与表情 |
| 禁用 | 冒充官方或特许行业的词（官方、政府、银行、警察、医院、学校法人……）与平台的名字；禁用词表由总部维护 |
| 审核 | 与商户主页一样经所属运营商审核后生效；未通过时照旧显示原称呼或默认词 |
| 历史 | 称呼的修改留历史（审计）；已签发的证书、已发出的邮件不受影响 |
| 门控 | 平台功能 `sponsor.title`（Q90）：未点亮不能设置；点亮后失效即显示默认词 |

## 5. 英文与日文的语法

中文的称呼可以直接替换"商户"。英文与日文不行，要在实施时逐条改写文案：

- 英文：单复数、冠词（"the store""a teacher"）、大小写；称呼放进句子时一律用 "the {{title}}" 的写法，或把句子改成不需要冠词的结构。
- 日文：敬称与语气（"店舗""先生"），"〜様"之类不加；句子改成不随称呼变形的写法。

## 6b. 由决定推出的做法

- **默认词统一**：中文"发起方"、日文"主催者"、英文"Sponsor"。一次全量替换（§3 的全部文字，含 B 类：成为发起方、发起方条款、发起方后台……）；与"称呼"无关的准备工作，可以先做。
- **称呼的数据**：发起方资料下的"称呼"列表：每个称呼三语、审核状态（草稿 / 待审核 / 已通过 / 驳回）、**购买期间**（自—至，付费后才有）、是否生效（同一时刻至多一个）。随资料审核（`QbSponsor` 的入驻与资料审核同一审批对象）。
- **显示规则**：此刻显示的称呼 = 生效的称呼已通过审核、在购买期间内（且，若 §6c-2 定为需要，功能 `sponsor.title` 已点亮）? 该称呼 : 默认词"发起方"。
- **计费**：照 Q47c 的规则费用与 Q87 的平台费：价目表（按运营商，月价）、购买时按所选期间的天数折算一次扣清（预付扣现金账户、后付进账单）、提前停用退未用天数。
- **两条购买路径**：目录称呼——点亮对应节点 → 选期间 → 付费 → 生效；自己申报——点亮申报资格的节点 → 申报文字（三语）→ 平台审核并报价 → 发起方同意 → 选期间 → 付费 → 生效。
- **证书**：颁发方写"名字（称呼）"，用**签发时**的称呼，写进存档的 PDF，以后改称呼不影响已签发的证书。
- **邮件、站内信、推送**：发送时的称呼。
- **Shopify 店**：Shopify 店的资料同样有称呼列表与审核；门控同发起方。
