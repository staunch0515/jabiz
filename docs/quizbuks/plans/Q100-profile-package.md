# Q100 商户资料包：导入、导出与生成（2026-11-05 需求方确认）

需求方（2026-11-05）：
1. 商户资料加导入与导出；文件叫"商户资料包"。
2. 生成的包里可以没有图片，但包的格式要能放图片：生成 → 导入 → 在商户中心补图片 → 再导出，就是完整的备份。
3. 图片（头像、主页封面、商品图片）在包里可以是**链接**。
4. 导入商品一律**整体替换**。
5. 生成资料包的网站 **B 与 C 都做**：B 是招商站上不用登录的生成器；C 是商家后台里的"从官网生成"（Claude 读商户的官网起草）。
6. 导出要包含**邮件服务器**的信息；资料包要支持**三种语言**（日文、中文、英文）。
7. **导入不影响审核**。链接图片**下载**到我们这里；**审核后就不再下载**，避免内容被篡改。

## 1. 决定（草案）

| # | 决定 |
|---|---|
| D-Q100-1 | **格式**：一个 JSON 文件 `<名>.quizbuks-profile.json`，`format: "quizbuks-profile"`、`schema: 1`。四部分：`basics`（公司、联系人、简介与译文、头像）、`page`（主页地址名、首选语言、标语、提供的语言与译文、封面、官网）、`products`（≤ 50 个：名称、说明与译文、价格、币种、购买链接、图片，按数组顺序）、`mailServer`（见 D-Q100-10）。不含店员、钱包、认证、审核与同意的记录 |
| D-Q100-2 | **图片**的三种写法：省略或 `null`（没有图片）；`{ "data": "<base64>", "type": "image/jpeg" }`（内嵌，导出总是这样写）；`{ "url": "https://…" }`（链接，见 D-Q100-6） |
| D-Q100-3 | **导入不影响审核**：导入只做商户自己手填也能做、且不改变任何审核状态的事。写入只经现有流程（作为子流程，在一个事务中，全部成功或全部不写）：`QB_SPONSOR_PROFILE_SAVE`（入驻已通过时）、`QB_SPONSOR_PAGE_SAVE`、`QB_PRODUCT_SAVE` / `QB_PRODUCT_DELETE`、`QB_MAIL_SERVER_SET`，规则与手填相同。<br>按状态跳过、并在确认页说明：①还没申请入驻或入驻被驳回：基本信息不写入，而是**填进入驻申请表**，由商户同意条款后自己提交；②入驻审核中：基本信息不写入；③入驻未通过：主页不写入（现有规则）；④主页审核中：主页不写入（手填保存会撤回审核，导入不这样做）。之后再导入一次即可补上 |
| D-Q100-4 | **商品整体替换**：包里的商品替换现有的全部商品。包里的商品带导出时的 `productId`：是本商户现有的即修改，否则新增；现有的、包里没有的删除。商品照现有规则**保存即生效、不经审核**；被总部或运营商下架的商品照旧保持隐藏。确认页先列出将新增、修改、删除的商品 |
| D-Q100-5 | **导出**：商户中心"概况"页的"导出资料包"，图片一律内嵌；导出的文件可以原样再导入（用于备份、在测试与正式环境之间搬、交给运营商协助） |
| D-Q100-6 | **链接图片下载一次**：导入时由服务器按链接下载图片，走上传的同一条流水线（判断类型、重新编码、去掉位置信息），记为商户自己上传的文件，之后与上传的图片完全一样；链接不保存，**以后从不再下载**，审核的是下载下来的那一份，对方网站之后换图不影响我们。下载需要平台的新能力（§3，`1.3/platform`）；在它合入之前，链接图片在确认页列为"请下载后自己上传"，其余照常导入 |
| D-Q100-7 | **B：招商站的生成器** `/biz/<语言>/profile-builder`：静态页面，不用登录，数据只在浏览器中、不发给服务器；表单填写三部分、选择本机图片（内嵌）或填图片链接、预览主页效果、下载资料包；三语、手机可用 |
| D-Q100-8 | **C：商家后台的"从官网生成"**：商户输入自己的官网地址，作为外部作业由 Claude 以网页搜索与读取起草资料包（复用 AI 获客的 `ClaudeWebResearch`），只起草、不写入：商户在导入的确认页校对后才写入。计入商户的 AI 限额，须同意 `AI_NOTICE`，开关 `qb.ai.enabled`；图片只给链接 |
| D-Q100-10 | **邮件服务器**：导出主机、端口、加密方式、用户名、发件地址与发件人名称，**不导出密码**（密码只以平台的密封方式保存，取不出明文，也不应以明文写进文件）。导入时经 `QB_MAIL_SERVER_SET` 写入：本环境已存的密码在主机与用户名不变时沿用，否则确认页要求输入密码；照旧发测试邮件到商户自己的地址，验证通过后才用于发信 |
| D-Q100-11 | **三种语言**：文字字段（简介、标语、商品名称与说明）在包里写成 `{ "ja": …, "zh": …, "en": … }`，第一种语言是基准（入驻资料的语言、主页的 `language`），其余写进各自的译文（`TextTranslations`，所译原文的哈希按包里的基准文字在导入时算出，因此导入后不算过时）；主页提供的语言（`page.languages`）中其他语言的标语必填，同手填规则。B 的生成器每个文字字段有三种语言的输入；C 起草基准语言，并由 Claude 译出所选的其他语言（标明是机器翻译，商户在确认页校对） |
| D-Q100-9 | 另给一套提示词模板（同 `quiz-file-prompts.md`），让商户用其他 AI 生成资料包 |

### 1.1 商品编号与 Quiz 的商品（需求方 2026-11-05 追加，Q100e）

| # | 决定 |
|---|---|
| D-Q100-12 | **商品编号** `code`：商户自己定的、可选的编号（如 `TEA-001`；字母、数字与 `. _ -`，1–40 字，`QB_PRODUCT_CODE_FORMAT`），同一商户内不重复（`QB_PRODUCT_CODE_TAKEN`，数据库部分唯一索引兜底）。商品页可编辑，资料包导出、导入都带着它；不进公开数据视图。系统内的编号 `productId` 照旧，Quiz 与商品的关联照旧存 `productId` |
| D-Q100-13 | **资料包导入时认商品**：包里的商品有编号就按编号找本商户的商品，没有编号才按 `productId`（同一环境导出的）找；都找不到的新增，本商户其余的商品删除（整体替换照旧）。**删除前提醒**：计划列出将被删除且关联着 Quiz 的商品与那些 Quiz 的名字，商家后台要商户勾选"知道这些商品会从这些 Quiz 上撤下"后才能导入 |
| D-Q100-14 | **Quiz 文件带商品**（格式版本 3）：`products.quiz`（整份 Quiz 的商品，按顺序）与 `products.questions`（`{no, product}`，题号即文件中的题序），每个商品写成 `{"code": …}`（有编号时）或 `{"productId": …}`。导入时按编号、再按 `productId` 找导入者自己的商品，找到的以子流程 `QB_QUIZ_PRODUCTS_SET` 关联到新草稿；找不到的不关联，检查时列出（不阻止导入）。版本 2 的文件照旧读（没有商品） |

## 3. 平台能力：下载公开图片（Q100b，`1.3/platform`）

平台目前只允许访问声明过的主机（`ExternalService` 的白名单），商户的图片可能在任何网站上，所以要给平台加一种受限的下载：

- 只用于**文件上传的同一条流水线**：结果是一个按文件策略登记的文件（类型按内容判定、图片重新编码），上传者为请求人；不给业务代码任意访问外网的能力。
- 只限 `https`；每次连接（含跳转后的每一跳，至多 3 跳）解析出的地址都必须是公网地址（拒绝回环、内网、链路本地、组播、云厂商元数据地址等），并按解析出的地址连接（防 DNS 重绑定）。
- 只收图片类型；大小上限同文件策略；连接与读取都有时限；不带 Cookie 与凭据。
- 作为外部作业或阻塞步骤运行，不在请求的事件线程上。
- 平台自己的测试与示范应用中的示范，不提 QuizBuks（根 CLAUDE.md 第 8 节）。

## 4. 测试（Q100a）

- 单元：资料包的检查（每种问题一例、整体替换的差异、三种语言的译文与必填）、导出与再导入得到相同的内容（邮件服务器除密码外相同）。
- IT：导入写草稿、不改变审核状态；入驻前只写基本信息；商品整体替换；别人的文件、被占用的地址名、超过上限都被拒；邮件服务器导出不含密码、导入沿用或要求密码并发测试邮件；导入的译文不算过时。
- 前端：导出、导入的确认页（新增 / 修改 / 删除、问题列表）、axe；e2e：导出 → 导入同一个文件。

## 5. 实施记录（Q100a，2026-11-05）

- 后端（包 `page`）：`ProfilePackage`（纯 Java，读格式、一次报出全部问题与路径：`QB_PROFILE_PACKAGE_FORMAT` / `_FIELD` / `_FILE`；文字可写成按语言的对象或基准语言的字符串；图片是 `files` 的键、`{"url": "https://…"}`、`null`（去掉）或不写（保留现有的，`Image.KEEP`）；资料包里写了邮件服务器的密码即拒绝）。
  `ProfileTransferProcesses`：`QB_PROFILE_IMPORT_CHECK`（只读，给出计划：各部分的动作、商品的新增 / 修改 / 删除、要上传的图片、链接图片）与 `QB_PROFILE_IMPORT`（同一计划，以子流程 `QB_SPONSOR_PAGE_SAVE` → `QB_SPONSOR_PROFILE_SAVE` → `QB_PRODUCT_DELETE`（逐个）→ `QB_PRODUCT_SAVE`（逐个，顺序即包里的顺序）→ `QB_MAIL_SERVER_SET` 在一个事务中写入；主页最先，因为它先取地址名的锁再取账户锁，与手填相同）。
  译文按包里的基准文字算哈希（`confirmed`），导入后不算过时。上传的图片按位置（`basics.avatar`、`page.cover`、`products[i].image`）给出；缺少即 `QB_PROFILE_IMPORT_FILE_MISSING`；需要密码而没给即 `QB_PROFILE_IMPORT_MAIL_PASSWORD`；同一商品出现两次即 `QB_PROFILE_IMPORT_PRODUCT_TWICE`。
- 商家后台：商户中心"概况"页的"商户资料包"卡片（`profile/ProfileTransfer.tsx`、`profile/transfer.ts`、`profile/ids.ts`）：导出（图片内嵌，邮件服务器不含密码，文件名 `<地址名>-<日期>.quizbuks-profile.json`）与导入（服务器的计划、需要时输入邮件服务器的密码、上传图片、导入；拒绝时逐条列出服务器的原因）。入驻还没提交或被驳回时，导入后转到"基本信息"，申请表已填好包里的内容（本标签页的 `sessionStorage`，取一次即删），由商户同意条款后自己提交。
- 未做（之后的步）：链接图片的下载（Q100b，平台）、招商站的生成器（Q100c）、从官网生成（Q100d）、给其他 AI 的提示词模板（随 Q100c 一起写，格式以本节为准）。

## 6. 实施记录（Q100e，2026-11-05）

- 商品编号：迁移 `V76__quizbuks_product_codes.sql`（列 `code`、部分唯一索引 `(user_id, code) WHERE code IS NOT NULL`）；`QbSponsorProducts.code` / `CODE_PATTERN`；`QB_PRODUCT_SAVE` 的输入加 `code`（旧的构造照旧），格式与重复分别是 `QB_PRODUCT_CODE_FORMAT` / `QB_PRODUCT_CODE_TAKEN`；商家后台的商品对话框与列表显示它。
- 资料包：商品带 `code`；认商品先按编号、再按 `productId`（`ProfileTransferProcesses.matches`）；计划多出 `linked`（将删除且关联着 Quiz 的商品与那些 Quiz 的标题，已移除的 Quiz 不算），商家后台要勾选确认才能导入。
- Quiz 文件版本 3：`QuizFile.Products`（`products.quiz` / `products.questions`，`{code}` 或 `{productId}`），`QuizFileChecks` 查个数与题号；导入检查给出 `products`（会关联的个数）与 `missingProducts`，导入在新草稿保存之后以子流程 `QB_QUIZ_PRODUCTS_SET` 关联找到的商品。商家后台的导出写出 Quiz 的商品（有编号写编号），导入对话框列出找不到的商品。`quiz-file-prompts.md` 改为版本 3 并加了商品的写法。
