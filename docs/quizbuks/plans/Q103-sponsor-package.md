# Q103 发起方包：一个发起方的资料、Quiz 与发布，导出后导入到另一个账户（计划，2026-11-05；需求方确认 §1）

> **已归档（2026-11-07）**：首次上线的内容以 [`docs/quizbuks/first-launch-spec.md`](../first-launch-spec.md) 为准，本文只作存档（查当初的讨论用）；两者不一致时以规格为准。

需求方 2026-11-05：测试期要**反复重置数据库**，已经整理好的发起方资料要能快速导回；上线时用同一个功能**导入样板间**（运营商的直营发起方，Q92a）。
它是工具，不是备份：只带内容与设置，**不带任何状态**，导入的一切照常审核。记录（交易、答题、奖励）、账本与钱都不带。数据库的灾难备份仍是运维的事（`operations.md`）。
**这只是计划**：确认后开发，工作分支 `1.3/quizbuks-103-sponsor-package`，经 PR 合入（CI 跑 e2e）。

## 1. 决定（需求方 2026-11-05）

| # | 决定 |
|---|---|
| D-Q103-1 | **内容，不带状态**：导出的是资料、Quiz、发布的内容与设置。导入后：基本信息在入驻未通过时**填进入驻申请表**、主页与商品照 Q100 的规则（D-Q100-3）、Quiz 是草稿并保存版本、发布一律是**草稿**；一切经现有的审核（入驻、主页、发布），没有任何免审的特例 |
| D-Q103-2 | **只能导入到还没有 Quiz 也没有发布的账户**（避免导两次成两份）。账户已有内容时，页面只提供"只导入资料部分"（即 Q100 的导入，入驻通过后补上主页用） |
| D-Q103-3 | **Quiz**：每个未移除的 Quiz 带**当前内容**；另外，被要导出的发布用到的**每个版本**都带上（发布可能用的不是最新版本）。导入时同一个 Quiz 按版本的先后重建：先导入最早用到的版本的内容并保存版本，依次换成下一个用到的版本的内容并保存版本，最后换成当前内容（与最后一个版本相同时不再换），所以发布能挂回"内容相同的版本" |
| D-Q103-4 | **发布**：只带**没有结束**的（草稿、审核中、待开始、进行中、已暂停、预算不足），已结束的不带。每个发布带 Q102 的设置，并记下它用的是包里哪个 Quiz 的哪个版本；导入为草稿，开始时间为导入时的下一个整点、天数同原来 |
| D-Q103-5 | **"提交全部草稿"**：发布列表加一个按钮，依次提交本人的全部草稿（每个照常经 `QB_PUBLICATION_SUBMIT`，有问题的跳过并列出原因），审核照常逐个进行 |
| D-Q103-6 | 不带：任何状态与审核结果、答题与奖励记录、钱包与账本、店员（别人的账号）、邮件服务器的密码、电子奖品的码与共用码、领奖码、邀请名单、发布的前置关系（以后随 Q90 再加知识结构图） |
| D-Q103-7 | 不做一次导入多个发起方的工具 |

## 2. 文件格式（`format: quizbuks.sponsor-package`，`version: 1`，一个 JSON）

```json
{
  "format": "quizbuks.sponsor-package", "version": 1, "exportedAt": "…",
  "profile": { …Q100 资料包，原样… },
  "quizzes": [
    { "key": "q1",
      "versions": [ { "key": "q1v2", "label": "v2", "file": { …Q16 Quiz 文件（由版本快照写出）… } } ],
      "current": { …Q16 Quiz 文件（当前草稿）… },
      "currentIsLastVersion": true }
  ],
  "publications": [ { "quiz": "q1", "version": "q1v2", "settings": { …Q102 发布设置… } } ]
}
```

- 每个 Quiz 文件照 Q16 自带它用到的文件（base64）；整个包超过 100 MB 时先确认（照 Q16）。
- 版本快照到 Quiz 文件的转换在前端（`content/transfer.ts` 增加 `exportVersion`，与 `exportDraft` 写同一种文件），译文、资料、商品编号（Q100e）都带上。

## 3. 实现

### 3.1 后端（`backend/quizbuks`，小）

- `QB_QUIZ_IMPORT` 增加可选的 `intoQuizId`：把文件的内容**整体替换**进本人的一个草稿 Quiz（规则与新建相同；只允许没有发布的 Quiz，否则 422），使同一个 Quiz 能依次保存几个版本（D-Q103-3）。`QuizImportIT` 增加用例。
- 其他都用现有流程：`QB_PROFILE_IMPORT_CHECK` / `QB_PROFILE_IMPORT`（Q100）、`QB_QUIZ_IMPORT_CHECK` / `QB_QUIZ_IMPORT`（Q16）、`QB_QUIZ_PUBLISH_VERSION`、`QB_PUBLICATION_SAVE` / `QB_PUBLICATION_AUDIENCE_SAVE`（Q102）、`QB_PUBLICATION_SUBMIT`。

### 3.2 商家后台（`quizbuks-web/sponsor`）

- `profile/package.ts`（纯函数为主）：写包（读资料包、Quiz 与发布，挑出要带的版本）、读包（只查形状，较新的格式拒绝）、导入的计划（要做的每一步）。
- 商户中心概况（Q100 的导出、导入旁边）："导出发起方包"与"导入发起方包"：导入前先读本人的 Quiz 与发布，有内容即只给"只导入资料部分"；检查一次列出全部问题与将要生成的内容；导入逐步显示进度，失败时说清是哪一步（照 Q16 的 `ImportStepError`）。
- 发布列表："提交全部草稿"（先确认，逐个提交，结果列出成功与各自的问题）。
- 文案三语。

## 4. 测试

- 前端：包的写出（只带没结束的发布与它们用到的版本、不带状态与秘密）、读回、拒绝其他文件；导入的步骤顺序（版本先后、当前内容与最后版本相同时不再替换、发布挂到对应版本）；有内容的账户只给资料部分；"提交全部草稿"列出各自的问题；两个对话框的 axe。
- 后端：`QB_QUIZ_IMPORT` 的 `intoQuizId`（本人的、没有发布的才可以，别人的 404）。
- e2e：一个发起方导出 → 另一个新发起方导入 → 入驻申请已填好、Quiz 与版本、发布草稿都在、发布挂在内容相同的版本上 → 提交全部草稿进入审核。

## 5. 估计

约 4–5 天（后端 1、前端 2.5–3、测试与 e2e 1）。
