# F-S14 视频使用台账与双方统计：实施计划

依据：`docs/quizbuks/first-launch-spec.md` F-S14（以它为准）；`Q112-video-push.md` §0-5、§6、§7 只作参考。
会话 S3，分支 `1.3/quizbuks-fs14-video-uses`，叠在 F-S13（`1.3/quizbuks-fs13-exposure`，#569，未合入）之上：数字读 F-S13 的计数表 `qb_exposure`。基线已含 F-S12 共享视频（卡片的 `sharedVideoId` / `videoProviderId`）、F-C3、F-S8 屏蔽与统计的最小分组（Q9e，`qb.stats.min-group`）。

## 0. 范围

一个 PR 做完：台账（使用方填写、提供方确认或拒绝、更正即新版本）、数字（每天更新、发布结束时定稿）、两种视角的统计页、提醒、运营商只读页、核对。

- **台账的一行**：一个用了**他人**共享视频的发布（卡片冻结了 `sharedVideoId`，且 `videoProviderId` 不是发布方，同 F-S13 的"他人的视频"）至多一行 `QbVideoUse`；记视频、提供方、使用方（发布方）、发布、期间、计价方式与价格、备注、状态。
- **数字**：每个这样的发布一行 `QbVideoUseFigures`：打开、曝光成功、去答题人数、合格人数，每天由任务更新，发布结束后的第一次运行定稿，之后不再改。
- **不做**：平台代收代付（规格）；台账不进平台的会计账本，不产生任何钱的流动；费用（F-M8）。

**删除的功能：无。** 只新增表、流程、模板、页面中的新区块与管理系统的新页；已有的发布、共享视频、曝光计数、发布页与资源页的内容都照旧。

## 1. 规则（一处定义：`videouse.VideoUseRules`，纯 Java）

- **谁填**：发布的发起方（使用方）。发布须已上线过（有卡片）且用了他人的共享视频；草稿与审核中的发布没有台账。一行一个发布（锁 `qb.video-use:<发布>` 内查重，422 `QB_VIDEO_USE_EXISTS`）。
- **期间**：两个日期（含），`periodFrom ≤ periodTo`，至多 `VideoUseRules.MAX_PERIOD_DAYS`（3660）天；缺省（页面预填）为上线日到结束日。
- **计价方式**：`FIXED`（固定价）、`PER_MILLE`（每千次曝光成功）、`PER_TAKER`（每位去答题的人）。**价格**是 `BigDecimal`，币种与小数位照平台规则以 `Monetary`（JPY，0 位小数，同 Q89 的"系统的币种"）声明，0 到 10^12。
- **参考金额**（不存，模板与 `VideoUseRules.amount` 同一算式）：`FIXED` = 价格；`PER_MILLE` = ⌊价格 × 曝光成功 ÷ 1000⌋；`PER_TAKER` = 价格 × 去答题人数。按当时的数字（定稿后即定稿的数字）；所用的数字少于最小分组时不显示。
- **状态**：`DRAFT` → `SUBMITTED` → `CONFIRMED` / `REJECTED`。使用方的保存（新建或更正）一律回到 `DRAFT`（已确认的更正后须重新确认）；提交只从 `DRAFT`；提供方只答复 `SUBMITTED`，必须带所读的版本号（`baseRevision`，读后被改即 422 `QB_VIDEO_USE_CHANGED`）；拒绝必须写原因（≤ 500 字）。拒绝原因保留到再次提交，供使用方更正时看。
- **版本**：表只追加（时态实体 `qb_video_use_version`），每次保存、提交、确认、拒绝都是新版本（`revision` 加一），平台的审计记下前后值；确认记下确认的版本号（`confirmedRevision`）、人与时间。
- **数字**（`qb.system.video-use-count`，只从计数表算）：
  - 打开 = `qb_exposure` 中该发布 `openedAt ≤ 截止` 的行数；
  - 曝光成功 = `countedAt ≤ 截止` 的行数（F-S13 的成功）；
  - 去答题人数 = `wentToAnswerAt ≤ 截止` 的行数（每人每发布一行，所以是人数）；
  - 合格人数 = 去答题的人中，在截止前提交、合格（`passed`）的答题至少一次的人数。
  - **截止**：进行中的发布为任务的计划时刻；已结束的为卡片的 `endedAt`。所以定稿的数字以后随时可以从计数表重算出同样的值（核对即重算比较）。
- **最小分组**（照 Q9e）：k = `qb.stats.min-group`（整数，否则 5，不小于 3；`stats.MinGroup.of`），每个数字少于 k 即不显示（模板给空值与 `minGroup`，页面写"少于 k"）。双方、运营商同一规则。
- **提醒**：`SUBMITTED` 超过 `qb.video-use.remind-days`（7）天未答复，每日任务给双方各一个待办（使用方："等待提供方确认"，提供方："请确认"），每个提交的版本只提醒一次；答复、更正后关闭。

## 3. 测试

- 单元：`VideoUseRulesTest`（期间、价格、计价方式、参考金额、状态的转换、最小分组的读法、提醒的天数、核对）。
- `VideoUseIT`：
  - **版本**：新建为 `DRAFT` 第 1 版，提交第 2 版，拒绝第 3 版（原因必填），更正第 4 版（`DRAFT`、原因仍可读），再提交、确认；`qb_video_use_version` 每次一行，没有 UPDATE / DELETE（`pg_stat_user_tables` 与触发器）；确认后更正回到 `DRAFT`。
  - **谁能做**：别人的发布 404；用自己视频的发布 422；草稿 422；一个发布一行；提供方以外的人不能答复（404）；读后被改的版本 422；使用方不能确认。
  - **最小分组**：数字少于 k 时为空值（参数调低后显示）；参考金额随之。
  - **每日更新与定稿**：任务前没有数字；任务后与 `qb_exposure` 一致；新的计数第二天才进来；发布结束后第一次运行定稿（截止为结束时刻），之后的计数不改定稿的数字。
  - **核对**：定稿的数字与按截止重算的计数一致，篡改后核对给总部待办。
  - **提醒**：超过参数天数的 `SUBMITTED` 给双方各一个待办，再跑不重复，确认后关闭。
  - **运营商**：只看到自己发起方的台账；权限。
  - **删除账号**：台账保留，`note` / `rejectReason` 被抹除。
- `ProcessAccessIT`（三个内部流程）、`SetupIT` 的参数、场景 `setup` 的 `paramsCreated`（快照按 `-Dscenario.update-snapshots=true` 更新并核对差异）、`OperatorScopesTest`（新实体）、`SealedColumnsMigrationIT` 看到新表。
- 前端：发起方页面 `videouses/videouses.test.tsx`（使用方：数字与"少于 k"、填写、提交、拒绝原因与更正；提供方：确认、拒绝；三语键一致；axe 亮暗）；管理系统扩展 `video-uses.test.tsx`（列表、空、运营商、axe 亮暗）。

## 5. 决定（需转达总控 / 需求方，可改）

1. **谁填**：只有用了他人共享视频、已上线过的发布的发起方（使用方）；一个发布一行（一个发布只能有一个共享视频）。
2. **状态**：`DRAFT → SUBMITTED → CONFIRMED / REJECTED`；使用方的任何保存都回到 `DRAFT`、须再提交；已确认的也能更正（须重新确认）；提供方答复须带所读的版本号。
3. **期间**由使用方填（页面预填上线日到结束日），不限制在发布的日期内（线下的约定可能更长），只要求先后与至多 3660 天。
4. **计价方式**三种，价格只用 `BigDecimal`（`Monetary`，JPY、0 位小数）；"按答题人数"按**去答题人数**计；参考金额不存，按数字算。
5. **合格人数** = 去答题的人中在截止前合格的人数（漏斗：打开 → 曝光成功 → 去答题 → 合格）。
6. **数字存一张普通表**，每天由逐项任务更新；**定稿**在发布结束后的第一次运行，截止为结束时刻（不是运行时刻），所以定稿后的数字可以随时从计数表按截止重算核对；定稿后不再写。
7. **最小分组**：每个数字单独判断，少于 k 不显示；双方与运营商同一规则（k 沿用 `qb.stats.min-group`，不加参数）。
8. **提醒**：唯一的新参数 `qb.video-use.remind-days`（7，不受控，加在最后）；平台待办（有邮件时随待办通知），每个提交的版本给双方各一次，答复或更正后关闭；不另发站内信。
9. **提供方看得到的**：提交过的台账（从未提交的草稿看不到）与用了本人视频的发布的数字。
10. **运营商只读**，按使用方（发布方）的运营商范围；提供方的运营商若不同则看不到（留作以后）。总部看全部。
11. **核对**：每日重算定稿的数字，有差异给总部（`qb.admin.exposure.monitor`）待办，一天一个。
12. **删除账号**：台账保留（双方的记录），使用方的备注与提供方的拒绝原因抹除；编号照平台决策 D62 第 4 条保留。
13. **台账不进平台的会计账本**，不产生钱的流动；以后 F-M8 的平台费用与本台账无关。

## 7. 风险

- 定稿依赖卡片的 `endedAt`；结束后迟到的"去答题"报告不进定稿的数字（按截止），这是有意的。
- 任务首次运行时会为所有用他人视频的旧发布建数字（逐项，上限 `PublishingLimits.TICK_BATCH` 一次）。
