# F-F10 实施计划：首次上线的资金开关

规格：`docs/quizbuks/first-launch-spec.md` F-F10（来源 `Q94-first-launch.md` §4；审查 D 的 A1-1～A1-10、需求方 2026-11-07 晚的补充）；相关：F-S4b（`qb.reward.default-methods` 缺省改空，已合）、`plans/impl/F-M.md`（收费组的开关）。负责：S3。状态：**总控 2026-11-11 批准，§9 十点按建议**（运营商提现不挡；受众规则费仍登记"等 F-M7"、上线前保持关；F-F10 先合，与 F-M5 在 `QbParams` 与 setup 快照上冲突时后合的一方合入并重生）。基线 `origin/1.3/quizbuks`（迁移最大号 V113 前后，本项预计不需要迁移，见 §3）。

一句话：**本项不做任何收费，也不抢收费组的参数**。它做三件事：(1) 一处登记"首次上线的值"（每个开关一行：键、首次上线的值、由谁提供）；(2) `QB_SETUP` 在正式环境按登记提出这些值；(3) 财务页的只读卡片按登记显示"现值 / 首次上线的值 / 待发布的提案"；外加一个真正缺的开关（发布不能设学分奖励）与正式环境的启动告警。尚不存在的开关由各 F-M 的 PR 在自己的 PR 中补登记（§2）。

## 1. 设计

### 1.1 登记与 `QB_SETUP`

- **一处登记** `setup/FirstLaunchSwitches`（纯数据，`QbParams` 旁；core 之外的应用代码，同步、不碰 `reactor.*`）：每行 `键`、`首次上线的值`、`组`（对应规格表的行，用于卡片分组与说明文字键）、`状态`（`ACTIVE`：键已在 `QbParams.ALL` 且值已定；`WAITING(F-Mx)`：键尚未存在或含义尚未做完，**不提出、不显示为"应当"**，只在卡片上列为"等 F-Mx"）。值写成与 `QbParams.Param.value()` 同型（布尔、字符串、数字串）。所有数字仍是参数，登记里不放金额常量：金额类的行（`qb.fee-credit.grant.basic` 等）登记"沿用声明值"（空值表示不覆盖），避免两处写同一个数。
- **`QB_SETUP` 的改动**：提出受控参数时，值 = 登记中该键的首次上线的值（当前环境选用首次上线的值时），否则仍是声明值。`recorder` 的幂等不变：键已建过、见过、被撤回的都不再提。**不新增提出受控变更的方式**，仍是 `ProposeInput(SysParam, …)`，理由文字写"First launch value of …"。
- **何时用首次上线的值**：由环境决定，不由新开关决定。建议：`jabiz.web.environment`（`JabizWebProperties.environment()`）为 `production` 或 `staging` 时用首次上线的值，其余（`test`、`local`、集成测试）用声明值。理由：集成测试与场景快照（`setup.snapshot.json`）大量依赖现在的声明值（例如 `CashAccountIT`、`OperatorCashClawbackIT`、`BankTopUpIT`、e2e `topup.spec.ts` 依赖 `qb.kudos.buy.enabled` 缺省开与 `KUDOS,CASH`），直接改声明值会连带改几十个测试；测试系统（staging）演练的是首次上线的值。F-F10 自己的 IT 以属性覆盖环境来跑首次上线的路径。见 §9 第 1 点。
- **提案不等于上线**：`QB_SETUP` 提出的是一批独立的提案（`SysControlChange`），财务管理员**逐条**发布。`qb.ai.enabled`、`qb.help.enabled`、`qb.fee-credit.grant.enabled` 这类"打开"的提案留到前置条件满足后才发布（AI 使用说明已发布、价目表已设）：发布之前参数不存在，对应功能关闭、启动检查给出已有的警告（`SetupParamsCheck`、`EXTERNAL` 的 `enabledBy` 警告，`operations.md` §3 第 6 步）。所以**待发布的提案**正是卡片要让值班的人看到的。
- 若 F-M 的 PR 在本项之后合入，部署后再执行一次 `QB_SETUP`（`operations.md` §3 第 8 步已有）即补提那条新键的首次上线的值。

### 1.2 `QB_SETUP` 之外：已有系统与默认去向

- 已有参数的系统（测试系统）不被改写。需要时由财务按卡片提示走现有的受控变更页（`CONTROL_CHANGE_PROPOSE` / `PUBLISH`），本项**不新增"一键提出"**（规格："卡片只读，提出与发布照受控变更的现有页面进行"）。
- 核对：`qb.topup.targets=CASH` 时 `qb.topup.default-target` 缺省 `KUDOS` 不在允许的列表里，`TopUpTargets.choose`（`wallet/TopUpProcesses.java:220-224` 调用）会怎样；若返回 `null`，则充值被拒。登记里把默认去向也列为 `CASH`，并加 `TopUpTargetsTest` 的一例（目标只有 `CASH`、未选择时进 `CASH`）。

### 1.3 财务页的"资金开关"卡片

- 位置：`FinanceOverviewPage.tsx`（`backend/quizbuks/admin-extension/src/`）在 `FeeAccounts` 与 `Accounts` 之间加 `FundSwitches` 组件，只读。权限同该页（`qb.admin.finance.read`）；读提案需 `approval.read`（财务角色已有，`operations.md` §3 第 5 步），没有就只显示现值。
- 数据：新模板 `qb.admin.first-launch-switches`（`queries/qb/admin/`，照 `prospect-switch.sql`：`WITH wanted (k, expected, grp, seq) AS (VALUES …) LEFT JOIN SysParam`），列：键、组、首次上线的值、现值、`paramExists`。`VALUES` 中的行由测试 `FirstLaunchSwitchesTemplateTest` 与登记逐行比对（键、值、顺序一致，`WAITING` 行不在其中），所以两处不会漂移。待发布的提案照 `prospect-switch-api.ts` 的 `readSwitchProposals` 读 `SysControlChange`（`targetEntity=SysParam`、`status=PROPOSED`），键在登记中的才列。
- 每行显示：开关名（三语消息 `fundSwitch.<键>`）、现值、首次上线的值、状态徽标：`一致`、`与首次上线的值不同`、`待发布（提出人、理由）`、`尚未建立（等 QB_SETUP 与发布）`、`等 F-Mx 上线`（`WAITING` 行）。状态既用文字也用颜色 token，亮暗两种外观过 axe。
- Stripe 模式不入卡片（它是部署配置，不是参数，`StripeModeCheck` 已在启动时失败于不一致）；若需求方要显示（§9 第 5 点），加一个只读的模板列由 `StripeSettings.livemode()` 提供，不在本项做。
- 表头下一行放"按受控变更修改：到平台管理系统的数据 → `SysControlChange`"的链接（与 `JournalMappingPage` 的说明一致），不在卡片里写入。

### 1.4 "发布不能设学分奖励"：新受控参数

- **现有的挡不住**：学分奖励就是奖励方式 `PLATFORM`（`RewardMethod.PLATFORM`，"Kudos paid by QuizBuks"）。`qb.reward.default-methods` 为空只让**新发起方缺省**没有它；管理员仍可按发起方开通（`QB_SPONSOR_REWARD_METHODS_SET`，`RewardMethodProcesses.java:83-104`），参数不存在时（`QB_SETUP` 之前）还回落到 `PLATFORM`（`RewardMethod.defaultMethods`）。规格要的是**硬关**，所以新增受控参数 `qb.reward.kudos.enabled`（布尔；声明值 true = 现行行为；首次上线的值 false）。定名由本项给出（规格说"在 Q90 T1a 的细化中定名"，F-S2 的计划里没有定名，见 §9 第 3 点）。
- **一处漏斗**：所有路径都经 `PublicationEditing.allowedMethods`（`PublicationEditing.java:271`）→ `methodProblems`（:289）。改法：`loadSponsorMethods` 的参数读取多读 `qb.reward.kudos.enabled`（`LoadParams.optional`，:246-248），`allowedMethods` 在开关**为 false** 时把 `PLATFORM` 从结果中去掉（缺省、本人设定、门槛三个来源都去掉）；参数不存在时：`test` 等其他环境**不挡**（与 F-S4b 已定的"参数不存在仍按平台 Kudos"一致）；`production` / `staging` **算关**（默认拒绝，审查修正，§11.2），`qb.reward.default-methods` 不存在时在这两个环境也不回落到 `PLATFORM`。被拒时：方式为 `PLATFORM` 且开关关闭（含上述缺失）用独立的 422 `QB_REWARD_KUDOS_DISABLED`（三语消息）；其他不允许的方式仍是 422 `QB_REWARD_METHOD_NOT_ALLOWED`，消息与原来一字不差；`allowed` 列表里都没有 `PLATFORM`。
- **四个入口都经过它**（核过）：保存 `QB_PUBLICATION_SAVE`（`PublicationProcesses.java:448`，含推荐奖励 :453）、复制 `QB_PUBLICATION_COPY`（:781，注释已写"复制出的发布，方式被收回"）、提交 `QB_PUBLICATION_SUBMIT`（`PublicationLifecycle.java:265`，规格验收要的就是这一道）、资料包导入（`PackageImportProcesses.java:311` 调 `PublicationProcesses.SAVE`）。规格里的"Q16 导入"是题库导入（`Q16-quiz-transfer.md`），不含发布的奖励，不涉及；实现时在 IT 中确认。
- **两处补充**：(a) `QB_SPONSOR_REWARD_METHODS_SET` 在开关关闭时仍可存 `PLATFORM`（只是被漏斗滤掉）；界面上"允许的方式"列表显示该方式为"暂不开放"，不改存储；(b) 已经提交、审核中或已上线的 `PLATFORM` 发布不受影响（结算照旧）；暂停后恢复、切换版本不改方式，不再检查。通道发布（`CHANNEL`，Shopify）与挑战发布（`forSponsors`，奖励恒为 0，`PublicationProcesses.java:446`）本来不经 `methodProblems`，不受影响。
- 发起方页面：奖励方式选择中 `PLATFORM` 在开关关闭时不出现（`PublicationWizard` 取"可用方式"的现有接口 `allowedMethods`；不另写前端判断，只显示服务端返回的）。

### 1.5 启动检查（正式环境）

- 新 `FirstLaunchSwitchesCheck implements PlatformCheck`（类别 `QUIZBUKS`，位置 `wallet` 包旁，读库的方式照 `SetupParamsCheck`：JDBC 用 Flyway 的连接设置、只读、不在请求路径上；没有数据库地址时跳过）。只在 `jabiz.web.environment=production` 时检查，**警告**而非失败（理由：要先启动才能发布提案，同 `LiveModeDataCheck` 的法律文本一条）。
- 警告的条件（键存在且值为开）：`qb.kudos.buy.enabled`、`qb.kudos.sell.enabled`、`qb.transfer.enabled`、`qb.withdrawal.bank.enabled`、`qb.reward.kudos.enabled`；另：`qb.reward.kudos.enabled` 不存在也警告（"未建立"；正式环境下不存在算关，Kudos 奖励发布被拒，§11.2）。文案点名"首次上线应为关"并指向 `operations.md` §4。**不**因为"尚未发布"而警告（那是 `SetupParamsCheck` 已做的）。
- 现有 `TransferScheduleCheck` 对"正式模式 + 转账开着"的处理不变（开启转账本身需要法务意见，`operations.md` §4 最后一条）。

## 8. 风险

### 11.2 审查修正（2026-11-12，PR #629 的审查意见）

- **默认拒绝**（中）：`production` / `staging` 上 `qb.reward.kudos.enabled` 不存在算关；`qb.reward.default-methods` 不存在时不回落到 `PLATFORM`。`RewardMethod.kudosOff` / `withKudosSwitch(…, firstLaunch)` / `defaultMethods(…, firstLaunch)`；流程的 `firstLaunch` 来自 `PublishingConfig` 注入的 `JabizWebProperties`（`FirstLaunchSwitches.appliesTo`），经 `loadSponsorMethods` 放进上下文。模板 `qb.sponsor.reward-methods` 取得环境的方式：应用不能改平台（模板没有平台给的环境参数），所以用可选的布尔参数 `firstLaunch`，由发起方页面按 `useEnvironment()`（production 或 staging）给出（`publishing/useRewardSettings.ts`）；它只决定页面列出什么，流程自己按服务器的环境判断，调用者传 false 也只是多列一个会被保存拒绝的方式。
