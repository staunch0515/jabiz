## 2. 设计

- **一个文件，串行**：`launch-loop.spec.ts` 用 `test.describe.serial`，每步一个 `test`（步骤失败则后面不跑，报告里一眼看出断在哪一步）；辅助与状态在 `launch-loop.ts`。状态对象 `loop`（发起方、运营商、两条发布、节点编号、学者、证书键……）由第 0 步重新创建，所以 `--repeat-each` 与同一数据库上的重复运行互不影响。重试仍为 0（`playwright.config.ts`），不加 `retries`。
- **数据隔离**：e2e 只增不删、同一数据库重复运行（`app.env`）：所有名称 `unique()`，每次新建运营商、发起方、学者、平台图；不删除。全局受控参数（`qb.tree.grant.max-per-node`、`qb.fee-credit.grant.enabled`、`qb.tree.gate.digital-prize-node`）在用它的步骤开头显式设置（`sponsor-challenge.spec.ts` 同做法，不依赖谁先跑）；闭环里**不改** `REGION_UNKNOWN_IP_COUNTRY`（那是 `foreign-video.spec.ts` 的 `try/finally`）。F-M 补的钱的参数（开关、价目表）同样在步骤内设置、`finally` 还原，免得影响其后的 spec。
- **用页面还是用接口**：需要"一个人坐在那里操作"的用页面（发起方的图与领奖页、学者答题、领奖、证书、挑战答题）；与别的 spec 重复的备数据（草稿保存、题目、平台模板）用接口。编辑器的键盘操作留在 `tree-graph.spec.ts`，不重复。每个关键页面过 axe 的亮、暗两种外观（`accessibleInBoth`，提到 `support.ts`），共约 8 页：发起方图生效、学者图（锁定与点亮各一）、电子奖品已显示、柜台页、到店兑换已领、证书页、核实页、挑战结果。学者的步骤用 390 × 844 的窄屏（`foreign-video.spec.ts`、`a11y.spec.ts` 的同一尺寸），发起方的用桌面宽度；规格没有要求宽度，另加的宽度检查不做。
- **时间与任务**：不靠墙钟，不 `waitForTimeout`。事件（审批后生效、点亮、证书）用 `expect.poll`（30 秒，常量）；可手动补跑的每日任务（`qb.tree-certificate-retry`）事件慢时用 `runJobNow`；钱的月任务（F-M6 / F-M12）也只用 `runJobNow`。**app.env 中每分钟跑的任务**（`QB_TRANSFER_RUN_CRON`、`QB_RECONCILE_RUN_CRON`、`QB_ANALYTICS_RUN_CRON`、账号删除的 `JABIZ_SECURITY_ACCOUNT_DELETION_CRON`）**不用 `runJobNow`**：计划运行占着锁时手动补跑得 409 `JOB_BUSY`，且补跑只取早于上一次计划时刻的请求（F-S5b 的教训），要等它们的计划运行（`expect.poll`，间隔 5 秒）。闭环不用这几个任务（账号删除后证书消失已由 `certificates.spec.ts` 覆盖，不重复）。
- **邮件**：第 2 步核对一封"发布已批准"邮件（Mailpit）；不调用外部服务（Stripe 与 Claude 本来就是桩）。
- **时限与分片**：每步 `test.setTimeout` 用常量（`STEP_TIMEOUT_MS`），整个文件目标 ≤ 6 分钟（预估：备料与审核 1.5 分钟、答题与领奖 2 分钟、证书与平台点亮 1.5 分钟、axe 约 1 分钟）。CI 的 `e2e-shard` 分两片（`--shard=1/2`，每片 35 分钟），分片以测试为单位，串行 describe 整块放一片，所以不改工作流；PR 中看两片耗时，差距过大再用 `test.describe` 的位置或文件名调（§9 第 6 点）。
- **只加不改行为**：不改产品代码。若发现产品缺口（例如"我的 → 知识结构图"的入口缺测试编号），在本 PR 中加 `data-testid`，不改行为。

## 8. 风险

- **串行故事的连锁失败**：一步失败后面全跳过，一次失败看不到后面的问题。缓解：每步只依赖状态对象中前面步骤的产物，步骤名写进报告；备料尽量早做到全。
- **时长**：把几个 spec 的主要路径合在一起，预算 6 分钟；若超出，把第 6a（平台图学者点亮，与 `certificates.spec.ts` 重合最多）改为只验图状态、不再下载证书。
- **共享数据库与全局参数**：同一数据库上多次运行，平台图、赠送上限、门槛参数都是全局的；缓解见 §2（每次显式设置、不依赖残留）。但**门槛参数 `qb.tree.gate.digital-prize-node` 是单值**，`sponsor-challenge.spec.ts` 与本文件 6b 轮流设置；两者串行（`workers: 1`）所以安全，若将来分片并行同库需改。
- **乱序**：缺省乱序使题目顺序随机，按文字选而不按位置；不断言顺序本身（断言会偶发失败），断言"缺省乱序已开启"。
- **异步链**：点亮 → 事件 → 证书、批准 → 事件 → 生效都靠 `expect.poll`，超时 30 秒（常量）；慢时先看事件是否在 `OutboxDeliverer` 中，不盲目加长。
- **证书核实页的浏览器缓存**（最多一分钟）：沿用"每次新开上下文"（`verifyPage`）。
- **F-M 补步骤时的冲突**：三个 F-M PR 都改同一文件。缓解：每步一个 `test`、各占一个函数与一块位置，互不相邻。
