# F-S10 竖屏短视频与竖屏模式：实施计划

依据：`docs/quizbuks/first-launch-spec.md` F-S10（以它为准）；`Q106-shorts-and-china-videos.md` §1、`Q94-review-2026-11-06.md` A3-18、B 节、C 节只作参考。
会话 S3，分支 `1.3/quizbuks-fs10-shorts`，叠在 F-S11（`1.3/quizbuks-fs11-foreign-video`，#505）之上：竖屏模式照首页的境外视频规则过滤（F-S11 的 `mainlandChina`）。

## 0. 范围

一个 PR 做完 F-S10。**删除的功能：无。** 首页的信息流照旧（横屏卡片、Q65 的单一播放器，竖屏的发布也照常在其中）；只多出插在参数位置的"短视频"一排与全屏的竖屏模式，视频资料多一个可选的"竖屏视频"勾选。

**Q108 的框架（F-F4）还没有做**：本条做在现有的 App 首页上。一排（`shorts/ShortsShelf.tsx`）与全屏模式（`shorts/ShortsViewer.tsx`）不依赖首页的布局，只接收短视频、起始的发布与"返回""去答题"的回调；位置的计算（`shorts/shelves.ts`）是纯函数。F-F4 换框架时把它们原样挂到新的首页。

C 节的简化（"竖屏先只认 `/shorts/` 链接，不加勾选"）**不采用**：规格要求保留勾选（Q112 的共享视频要声明竖或横）。C 节的另一半采用：一排的数据由首页模板 `qb.app.feed` 加一个参数 `shorts` 取得，不另写模板。

## 1. 规则（一处定义）

- **竖屏**：卡片视频（`PublicationEditing.cardVideo`：看完即可答题的视频，否则第一个能播放的视频）是 YouTube 的 Shorts 链接（`VideoEmbeds.shorts`），或其资料勾选了"竖屏视频"（`QbMaterial.vertical`，只限基准语言的视频链接；其他语言的资料跟随基准）。前端 `qb/video.ts` 的 `isShorts` / `verticalVideo` 与管理系统扩展 `video.ts` 的 `isShorts` / `cardVideoVertical` 照抄，同一组用例（`VideoEmbedsTest.aShortsLinkIsVertical`）。
- **冻结**：上线（`PublicationEditing.cardOf`）与版本切换（`PublicationVersions.make`）都经 `CardVideo.writeTo` 写卡片的 `videoVertical`（不可空，缺省 `false`）。
- **快照**：只有勾选的视频在快照中写 `"vertical": true`；没勾的资料的快照与以前逐字相同（哈希不变）。资料表上没勾即空（`null`），保存没改动的资料什么也不写。
- **一排**：`qb.app.feed` 的参数 `shorts` 为真时只列 `videoVertical` 的卡片，其余条件与首页完全相同（地区、受众、前置、语言、搜索与筛选、F-S11 的 `mainlandChina`；F-S8 的屏蔽加在同一模板里即自动生效）。每行带参数 `qb.feed.shorts.positions` 与 `.per-shelf` 的值（模板读 `now:SysParam`），App 一次读至多 50 个（`SHORTS_LIMIT`）。
- **位置**（`shorts/shelves.ts`）：第 n 个位置（第几张卡之后，第一张为 1）放第 n 组 `per-shelf` 个短视频（如 YouTube 首页往下是别的 Shorts）；没有剩下的短视频的位置不放；位置超过已读的卡片时等下一页，首页已读完时第一排放在列表末尾、其余不放；没有竖屏发布即没有一排。
- **全屏模式**：地址 `/?shorts=<发布>`（保留搜索 `q`），叠在首页之上，首页不卸载、不滚动，返回（按钮、Esc、系统返回）回到原来的位置。一屏一个，竖向滚动吸附（`IntersectionObserver` 判断当前屏）；上一个、下一个按钮与方向键（焦点在哪里都有效）。**只有当前屏有播放器、且只有一个**：YouTube / Vimeo 用 Q65 的舞台（新模式 `short`，叠在全屏页之上，计入"看完才能答"，与开始页相同），声音开了以后换下一个视频仍开（`openWithSound`）；其他网站用它自己的播放器，由用户点一下播放器开声音（A3-18，页面有提示）。系统设为减少动态效果时不自动播放，显示"播放"按钮。"去答题"带着同一个播放器进入开始页（Q65 的交接），Q75 的记录按发布保存，开始页照用。

- **总控 2026-11-07 定（需求方可改）**：竖屏的发布照常留在首页普通列表中，另外进入竖屏一排（不减少已有的显示）；有几个插入位置时各排不重复（第 n 个位置显示第 n 组）。规格 F-S10 已补这一条。
- 规格写"依赖 Q108 的框架"：新框架（F-F4）还没做，F-S10 做在现在的首页上；组件只接收数据与回调，F-F4 时直接搬过去（总控同意）。

## 8. 补正：竖屏视频铺满整屏、打开即播放（2026-11-27，分支 `1.3/quizbuks-fs10b-vertical-fill`）

学者反馈：竖屏模式（`?shorts=` 与 Q113c 的 `?video=`）中竖屏视频与横屏一样摆放，没有铺满屏幕；打开时有时停在播放器的暂停状态（控制条、等点按）。**删除的功能：无。**

- **原因一（不铺满）**：竖屏视频的框是 9:16，但与底部信息（发起方、名称、按钮）和顶部一行上下排列，手机上只剩中间一块，两侧是黑边；框内的视频文件是 `object-contain`。
- **原因二（暂停）**：声音一经打开，下一个视频（滑动、按钮）与从封面点进来的新播放器在**准备好时**由舞台自己开声音（`soundOn`，不在点按之内）。浏览器不允许时（iOS Safari、取消静音的视频文件）会把视频停下，留在控制条上等点按。
- **做法**：竖屏的框占满整屏的高度、至多屏宽（手机上即全屏，宽屏为中间一列 9:16），顶部一行与底部信息**叠在视频上**（渐变底衬）。为此全屏模式放到 `body` 下：黑底 `z-40`、舞台 `SHORT_STAGE_Z = 45`、屏幕 `z-50`；正在播放的那屏的视频区域 `pointer-events: none`，点按与滑动照旧落到播放器上。填充用 `coverBox`（纯函数，与 `object-fit: cover` 相同）：舞台的 iframe 给成 9:16 盖满、多出的部分由舞台裁掉，视频文件 `object-cover`；其他网站的播放器以容器单位同样盖满。横屏视频不变（中间横放、信息在下）。
- **不经点按的开声音**：只在竖屏模式中、`UNASKED_SOUND_MS`（3 秒）之内，播放器暂停（YouTube 状态 2 或 5、Vimeo `pause`、文件 `pause` 或 `play()` 被拒）或到时仍未播放（缓冲中的不算）即视为被拒：改回静音继续播放，"开声音"按钮重新出现（`playMuted`）。开始页照旧（Q66：等播放器自己的播放键）。
- **测试**：`video/stage.test.tsx`（`coverBox`、iframe 的盖满位置与层次、文件的 `object-cover`、文件与 YouTube 被拒后静音续播、之后的暂停属于观看者）；`shorts/shorts.test.tsx`（竖屏的框、信息叠在视频上、放在 `body` 下与层次、文件与其他网站的盖满、横屏不变）；e2e `shorts.spec.ts` 新增一条（手机与宽屏下舞台盖满、文件在播放、Shorts 链接的 iframe 为 9:16 盖满），`video-file.spec.ts` 的视频服务器抽到 `video-server.ts`。首页 `FeedPage` 未改，首页框架的基准图不变。
- **第二轮（需求方 2026-11-27 指正，照 x.com 实测）**：首页的竖屏视频也不能按横屏放；点视频不应直接进入流转模式。在 x.com（手机 375px、宽屏）实测：信息流中竖屏视频是 9:16 圆角框、靠左（手机约 291×517、宽屏 285×506），静音自动播放、没有控制条；点视频不离开信息流，就地正常播放（控制条、声音）。改为：
  - 首页卡片（`qb/view/FeedCard.tsx`，两个 SPA 同步）：竖屏视频 9:16、宽至多 287px、靠左；横屏照旧 16:9。
  - 正在播放的卡片点一下：舞台的 `engage`，就地开声音、移去盖在播放器上的那一层，播放器自己的控制可用（视频文件出现 `controls` 与全屏键），不离开首页；没在播放的卡片点图片即在原处播放（`FeedPage` 的 `tapped`，直到另一条视频来到屏幕中间），声音在点按之内请求（`openWithSound`）。其他网站的播放器不再盖链接，点按交给它自己。
  - 视频流转模式的入口：正在播放的视频右上角的"全屏"键（`feed-card-video-mode`，`feed.openVideoMode`）与"短视频"一排。Q113 §9.3 的表已先改。
- **第三轮（需求方 2026-11-27 再次指正）**：第二轮把"点视频"理解成在首页原处出控制条播放是错的。需求方的要求是**点首页的视频即最大化这条视频**（进入视频流转模式，同一个播放器带着声音接着播），并且视频**不要停在控制状态**。另外竖屏视频的封面比播放的视频大得多：首页卡片上播放器的位置（`VideoSlot`）仍是 16:9（`aspect-video`），放在 9:16 的封面框里只占顶上一条。改为：
  - 首页：点视频（正在播放的或封面）照 Q113c 进入流转模式（撤回第二轮的 `engage`、原处播放、`tapped` 与右上角的键）；竖屏 9:16 竖框保留，卡片上播放器的位置铺满该框（`absolute inset-0`），封面与视频同一尺寸。
  - 流转模式：视频区域由屏幕接住点按（`shorts-toggle`，舞台的 `togglePlay`：点一下暂停、再点继续），不再把点按交给播放器，所以 YouTube / Vimeo 的控制条不出现；视频文件在流转模式中不显示浏览器的控制条与全屏键（`controls` 只在开始页）。滑动照旧换下一个。
- **第四轮（需求方 2026-11-28）**：封面与视频切换时闪烁，去掉封面；画面中间的大播放标记删除。带视频的帖子（首页卡片、发起方页面的预览、流转模式未播放的屏）不再显示封面图片：视频的位置是页面底色 `bg-muted` 的一块（`feed-card-video-surface`），舞台把它当作淡入的起点（`crossFade`），播放器出第一帧之后才淡入，所以不出现黑屏，也没有另一张图换成视频的跳变。播放标记（`feed-card-video-mark`）只留给读屏的文字。没有视频的帖子与播放失败的视频文件照旧显示封面。
- **第五轮（需求方 2026-11-28 再次）**：去掉封面后留下的底色一块不好看；视频流转模式切换的瞬间有黑屏。改为显示视频自己的画面（`qb/video.ts` 的 `videoPoster`、`qb/view/VideoPoster.tsx`）：YouTube 用 `https://i.ytimg.com/vi/<id>/hqdefault.jpg`（4:3 的图里视频带黑边，以 `object-cover` 裁进 16:9 或 9:16 的框正好去掉黑边；`img-src https:` 已允许，隐私政策已写明显示视频时浏览器会连接 Google（YouTube）），视频文件用一个只加载开头、从不播放的静音 `<video>`（`#t=0.1`）；其他网站（Vimeo、哔哩哔哩等）没有自己的图片，退回发起方的封面；YouTube 的图片加载失败也退回封面。首页卡片与流转模式的各屏都显示它；流转模式中正在播放的那屏把它作为舞台的 `cover`，舞台在播放器出第一帧之前保持透明（`crossFade`），所以切换时不再黑屏。e2e 的共用夹具把 `i.ytimg.com` 答为一个灰色像素（不连外网，基线不变）。另外，开始页的资料下面去掉发起方迷你网站的区块（`SponsorVisit`，结果页保留）。
- **第六轮（需求方 2026-11-28 staging 实测）**：staging 首页的视频全是平台视频服务器上的视频文件（`videos.quizbuks.com/*.mp4`）。两个问题：① 竖屏框里的视频是 3:4（1440×1920），舞台以 `object-contain` 放进 9:16 框上下留空，卡片下面垫的第一帧从空处露出来（模糊条带、字幕重复）；② iPhone 上为显示第一帧而放的、不播放的 `<video>` 画不出（灰框），页面上这类元素一多，正在播放的视频也可能不显示；视频服务器不允许跨域读取，浏览器也无法把帧转成图片。改为：视频文件不再放第一帧的 `<video>`，与其他网站一样显示发起方的封面（需求方选定）；首页卡片上的播放器铺满视频框（`VideoSlot` 的 `fit`：竖屏 `cover`，横屏 `fill`，视频文件都用 `object-cover`），不再露出下面的封面。
