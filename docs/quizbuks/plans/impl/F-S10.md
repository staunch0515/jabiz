# F-S10 竖屏短视频与竖屏模式：实施计划

依据：`docs/quizbuks/first-launch-spec.md` F-S10（以它为准）；`Q106-shorts-and-china-videos.md` §1、`Q94-review-2026-11-06.md` A3-18、B 节、C 节只作参考。
会话 S3，分支 `1.3/quizbuks-fs10-shorts`，叠在 F-S11（`1.3/quizbuks-fs11-foreign-video`，#505）之上：竖屏模式照首页的境外视频规则过滤（F-S11 的 `mainlandChina`）。

## 0. 范围

一个 PR 做完 F-S10。**删除的功能：无。** 首页的信息流照旧（横屏卡片、Q65 的单一播放器，竖屏的发布也照常在其中）；只多出插在参数位置的"短视频"一排与全屏的竖屏模式，视频资料多一个可选的"竖屏视频"勾选。

**Q108 的框架（F-F4）还没有做**：本条做在现有的 App 首页上。一排（`shorts/ShortsShelf.tsx`）与全屏模式（`shorts/ShortsViewer.tsx`）不依赖首页的布局，只接收短视频、起始的发布与"返回""去答题"的回调；位置的计算（`shorts/shelves.ts`）是纯函数。F-F4 换框架时把它们原样挂到新的首页。

C 节的简化（"竖屏先只认 `/shorts/` 链接，不加勾选"）**不采用**：规格要求保留勾选（Q112 的共享视频要声明竖或横）。C 节的另一半采用：一排的数据由首页模板 `qb.app.feed` 加一个参数 `shorts` 取得，不另写模板。

## 1. 规则（一处定义）

- **竖屏**：卡片视频（`PublicationEditing.cardVideo`：看完即可答题的视频，否则第一个能播放的视频）是 YouTube 的 Shorts 链接（`VideoEmbeds.shorts`），或其资料勾选了"竖屏视频"（`QbMaterial.vertical`，只限基准语言的视频链接；其他语言的资料跟随基准）。前端 `qb/video.ts` 的 `isShorts` / `verticalVideo` 与管理系统扩展 `video.ts` 的 `isShorts` / `cardVideoVertical` 照抄，同一组用例（`VideoEmbedsTest.aShortsLinkIsVertical`）。
- **冻结**：上线（`PublicationEditing.cardOf`）与版本切换（`PublicationVersions.make`）都经 `CardVideo.writeTo` 写卡片的 `videoVertical`（不可空，缺省 `false`）。
- **快照**：只有勾选的视频在快照中写 `"vertical": true`；没勾的资料的快照与以前逐字相同（哈希不变）。资料表上没勾即空（`null`），保存没改动的资料什么也不写。
- **一排**：`qb.app.feed` 的参数 `shorts` 为真时只列 `videoVertical` 的卡片，其余条件与首页完全相同（地区、受众、前置、语言、搜索与筛选、F-S11 的 `mainlandChina`；F-S8 的屏蔽加在同一模板里即自动生效）。每行带参数 `qb.feed.shorts.positions` 与 `.per-shelf` 的值（模板读 `now:SysParam`），App 一次读至多 50 个（`SHORTS_LIMIT`）。
- **位置**（`shorts/shelves.ts`）：第 n 个位置（第几张卡之后，第一张为 1）放第 n 组 `per-shelf` 个短视频（如 YouTube 首页往下是别的 Shorts）；没有剩下的短视频的位置不放；位置超过已读的卡片时等下一页，首页已读完时第一排放在列表末尾、其余不放；没有竖屏发布即没有一排。
- **全屏模式**：地址 `/?shorts=<发布>`（保留搜索 `q`），叠在首页之上，首页不卸载、不滚动，返回（按钮、Esc、系统返回）回到原来的位置。一屏一个，竖向滚动吸附（`IntersectionObserver` 判断当前屏）；上一个、下一个按钮与方向键（焦点在哪里都有效）。**只有当前屏有播放器、且只有一个**：YouTube / Vimeo 用 Q65 的舞台（新模式 `short`，叠在全屏页之上，计入"看完才能答"，与开始页相同），声音开了以后换下一个视频仍开（`openWithSound`）；其他网站用它自己的播放器，由用户点一下播放器开声音（A3-18，页面有提示）。系统设为减少动态效果时不自动播放，显示"播放"按钮。"去答题"带着同一个播放器进入开始页（Q65 的交接），Q75 的记录按发布保存，开始页照用。

- **总控 2026-11-07 定（需求方可改）**：竖屏的发布照常留在首页普通列表中，另外进入竖屏一排（不减少已有的显示）；有几个插入位置时各排不重复（第 n 个位置显示第 n 组）。规格 F-S10 已补这一条。
- 规格写"依赖 Q108 的框架"：新框架（F-F4）还没做，F-S10 做在现在的首页上；组件只接收数据与回调，F-F4 时直接搬过去（总控同意）。

## 2. 改动

| 位置 | 改动 |

## 3. 语句数（`AttemptStatementBudgetIT` 不变）

答题路径不读也不写任何新东西：卡片多一列由上线与版本切换写（这两个流程原有的更新），开始答题不看它。一排是首页的第二次模板查询（首页读完第一页之后），与答题无关。其他语句预算（`StatementBudgetIT` 等）同样不变。

## 4. 测试

- 单元：`VideoEmbedsTest.aShortsLinkIsVertical`。
- `ShortsIT`：Shorts 链接与勾选使卡片竖屏、横屏与没有视频的不是；勾选只限基准语言的视频链接；没勾的快照不含 `vertical`、资料行为空；版本切换更新；首页模板的 `shorts`（只有竖屏的、带两个参数、首页照旧全列、F-S11 的 `mainlandChina` 与搜索同样过滤、`PARAM_SET` 后的值）；打开数的计数器；回填（迁移本身的语句，Shorts 的几种写法与横屏的几种）。
- `SetupIT` 的参数表、场景 `setup` 的 `paramsCreated`；快照按 `-Dscenario.update-snapshots=true` 更新（setup 多两个参数、卡片多一列 `videoVertical`）。
- 前端：App `shorts/shorts.test.tsx`（参数的读法、插入位置、等下一页与列表末尾、没有竖屏发布时不显示、请求与首页条件相同、单一播放器、按钮与方向键与 Esc、返回首页、其他网站的播放器与开声音的提示、减少动态效果不自动播放、全屏中的观看计入、去答题、打开数、axe 亮暗）、`qb/video.test.ts` 的同一组用例；发起方页面 `content.test.tsx`（勾选、Shorts 链接自动勾上、axe）；管理系统扩展 `video.test.ts`、`pages.test.tsx`（审核页的"竖屏"）。

## 7. 风险

- 回填只认 Shorts 链接：迁移时资料上还没有勾选，结果与之后冻结的一致。
- 位置参数写错（非数字、0）时忽略那一项；全空即不显示一排。
- 打开数按访客、发布、日去重（平台公开计数器的语义），是"多少人次打开"，不是点击次数。
