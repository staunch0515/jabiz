## 分步

| PR | 分支 | 内容 |
|---|---|---|
| **F-C11a**（本次） | `1.3/quizbuks-fc11a-products-max` | 商品上限改为参数 `qb.products.max`；核对商品迁入资源库以后资料包的读写与发起方页面的链接 |

## F-C11a 做什么

### 1. 参数 `qb.products.max`

- `QbParams`：新增普通参数 `PRODUCTS_MAX = "qb.products.max"`（缺省 50，`numeric(6,0)`，不受控：不涉及钱与审核），放在 `ALL` 的最后（同 F-C1 的做法，此前各键的顺序不变），由 `QB_SETUP` 建立；三语消息 `param.qb.products.max`。
- 读法同 `qb.assets.max-count`：流程以 `LoadParams` 读、`QbParams.limit` 取整（参数还不存在时用缺省值）。
  - `QB_PRODUCT_SAVE`：在账户锁内读参数，新增商品时 `已有 >= 上限` 即 422 `QB_PRODUCT_LIMIT`（`max` 为参数值）。
  - `QB_PROFILE_IMPORT_CHECK` / `QB_PROFILE_IMPORT`：读包之前读参数；纯 Java 的 `ProfilePackage.read(document, maxProducts)` 由调用方给出上限（原 `read(document)` 照旧保留，取缺省值，供测试与没有参数的调用）。
  - 消息 `QB_PRODUCT_LIMIT` 的三语文字中写死的 50 改为 `{max}`；`SponsorPageCodes` 与 `SponsorProductProcesses` 的 Javadoc 改指参数。
- **查询的条数**：`SponsorProductProcesses`、`ProfileTransferProcesses`、`QuizTransferProcesses` 读本人商品时用的是 `MAX_PRODUCTS + 1` 作查询上限。这不是规则，而是"读本人全部商品"；参数调低以后，按上限截断会使修改、删除已有的商品找不到、资料包导入删不全。因此改为读本人全部商品（`Integer.MAX_VALUE`，同资源库的 `lockAndLoad`），条数本身由保存时的上限约束，不再引用常数。
- 删除 `QbSponsorProducts.MAX_PRODUCTS` 常数（规格写"取代"；行为不变，只是数字改由参数给出，不算删除功能）。`ProspectAnswers.MAX_PRODUCTS = 5` 是获客问卷的另一件事，不动。

### 2. 发起方页面的上限从服务器来

- 现有做法：发起方页面读参数一律经 `now:SysParam` 上的模板（`qb.sponsor.topup-limit`、`qb.sponsor.reward-methods`、`qb.sponsor.ai-usage`），不另开接口。商品页本身读的是数据视图 `me:QbSponsorProduct`，不是模板，没有可加列的地方。
- 因此照现有做法新增一个模板 `qb.sponsor.product-limit`（一行：`max`，权限 `qb.sponsor.me`，同商品的流程），经现有的 `/api/queries/{id}`，不新增接口。参数不存在或不是整数时 `max` 为 null（同其他模板："参数不在即为空"），页面这时不限制、不显示个数，由服务器在保存时判断。
- `products/api.ts`：去掉 `MAX_PRODUCTS` 常数，改为 `readProductLimit()`；`ProductsPage` 以查询 `['qb', 'product-limit']` 读它（资料包导入后 `invalidateQueries(['qb'])` 随之重读）。
- `readMyProducts` 现在一次读 200 条：上限可调高以后改为按页读完（否则超过 200 件时商品页与导出会少，导出的包再导入会删掉少了的商品）。

### 3. 商品迁入资源库以后的核对

F-C1c 只把商品页搬进资源库的"商品"标签（`/assets?tab=products`），数据（`qb_sponsor_product`）、流程与组件不变。核对结果：

- 后端 `ProfilePackage` / `ProfileTransferProcesses` 读写的仍是 `QbSponsorProduct` 与 `QB_PRODUCT_SAVE` / `QB_PRODUCT_DELETE`，不受影响。
- 前端 `profile/transfer.ts` 的 `exportProfile` 用 `products/api.ts` 的 `readMyProducts`，导入后使全部 `qb` 查询失效（含商品标签）；资料包卡片中没有指向旧商品页的链接；概况的清单已指向 `PRODUCTS_TAB_PATH`，旧地址转向由 `MOVED_PATHS` 负责。
- 结论：不需要修改；以测试固定（导入后商品标签显示导入的商品）。

## 测试

- `ProfilePackageTest`：超过上限按给出的上限报 `QB_PRODUCT_LIMIT`（`max` 为给出的值），恰好等于上限通过；缺省读法为参数的缺省值。
- `SponsorProductIT`：原有的"满 50 件"改按参数；新增：`PARAM_SET qb.products.max` 调小后保存新商品被拒（`max` 为新值）、已有商品仍可修改与删除，调回后可新增；资料包检查同样按新值拒绝；模板 `qb.sponsor.product-limit` 返回参数值。
- `ProfileImportIT`、`ProductCodeIT`、`QuizTransferIT` 等照旧通过。
- `SetupIT` 的期望值加 `qb.products.max = 50`；场景 `qb/setup.yml` 的 `paramsCreated` 加一项，以 `-Dscenario.update-snapshots=true` 重写快照（差异只应是这个参数与其后的编号）。
- `MessagesTest`：`param.qb.products.max`、`query.qb.sponsor.product-limit`。
- 发起方页面 Vitest（`products.test.tsx`）：上限来自服务器（服务器给 2 时，两件商品即"已满"、新增按钮不可用）；模板读不到时不限制；axe 照旧。

## 文档

- `backend/quizbuks/CLAUDE.md` 的"商户资料包"条目写明参数；`operations.md` 加参数一行（部署后执行 `QB_SETUP`）。
- 帮助页的资料包一节随 F-C11b 改写。

## 风险

- 场景快照：`QB_SETUP` 多建一个参数，其后的提案编号整体后移（F-C1 时相同），需逐项看差异。
- 调低上限不删已有的商品：已有商品多于上限的发起方只是不能新增；资料包导入时包里的商品多于上限即整包拒绝（与手填一致）。
- 前端的其他测试若打开商品页而没有模拟新模板，模板返回 404，页面按"不限制"显示，不会失败。

## F-C11b-1 帮助页的资料包一节改写（S4；不依赖 F-C7，待总控批准）

范围只是**帮助底稿 `docs/quizbuks/help/profile-package.md`** 与核对它的测试；不改产品代码、页面和迁移。来源链接与"机器翻译"标记等 F-C7 做完再接（F-C11b-2）。

### 现状

底稿现在只讲"用其他 AI 从官网生成资料包"（F-C5），而帮助页的"资料包一节"应当讲清资料包本身。F-C1c（商品搬进资源库）、F-C6（链接图片下载）、F-C11a（商品上限参数）都已合入，底稿没有写到：商品现在在资源库的「商品」标签、上限来自参数、再次导入按商品编号对上原来的商品、导出的图片内嵌而链接图片导入时下载一次。

### 做什么

1. 把底稿改写为完整的"发起方资料包"一节（中、日、英三语，每种语言为同一结构，仍由内容管理员发布为 FAQ，`audience = SPONSOR`，分类 `ACCOUNT`）：
   - **资料包是什么**：一个 `.quizbuks-profile.json` 文件，含基本信息、公开主页、商品（和邮件服务器的设置，不含密码）；用途：备份、在测试与正式环境之间搬、交给运营商协助、用 AI 起草。
   - **导出**：概况页头「导入与导出」→「发起方资料包」→「导出」；图片内嵌，文件可原样再导入。
   - **导入**：选文件 → 确认页逐项列出新增、修改、删除 → 勾选与确认 → 导入；**导入只写草稿，不改变审核状态**，主页照常提交审核；整包全部成功或全部不写；被拒时确认页逐条列出问题（含位置），可复制问题与修正提示词。
   - **商品**（取代旧的"商户中心里的商品"）：商品在资源库的「商品」标签；包里的商品**整体替换**现有的：有商品编号（`code`）的按编号对上，没有的按导出时的商品标识；对不上的新增，现有而包里没有的删除（确认页先列出，并提醒被删的商品所关联的 Quiz）；数量上限是参数 `qb.products.max`（缺省 50，超过整包拒绝）；被运营商下架的商品照旧隐藏。
   - **图片**：导出总是内嵌；导入时链接图片由服务器下载一次（只收 https 的公网图片），下载不了的逐张说明原因，可重试、改为自己上传或保持现状（这一段现有的 F-C6 文字保留并并入）。
   - **用 AI 起草**（现有的 F-C5 内容并入此节，不丢）：提示词的用法、一定要校对、被拒时回交 AI、不要让 AI 放图片数据。
   - 用词照 `glossary.md`：发起方、学者（Q91）、运营商、平台管理系统；页面名与按钮名与 `messages.ts` 一致；不出现"后台"、"商户"、"商家"。
2. `docs/quizbuks/plans/impl/F-C5.md` 第 3 条（帮助底稿）与 `F-C11a` 的"帮助页的资料包一节随 F-C11b 改写"两处改为指向这一节；`backend/quizbuks/CLAUDE.md` 的商户资料包条目中"帮助底稿"一句同步。

### 测试（让文案不会悄悄过期）
