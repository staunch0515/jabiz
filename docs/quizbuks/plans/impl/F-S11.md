# F-S11 含境外视频的发布：按 IP 拒绝中国大陆：实施计划

依据：`docs/quizbuks/first-launch-spec.md` F-S11（以它为准）；`Q106-shorts-and-china-videos.md` §2、`Q94-review-2026-11-06.md` A3-15～A3-19 与 B 节 Q106 只作参考。
平台能力已在本线：决策 D74 `ClientCountry`、步骤 `LoadClientCountry`、`GET /api/client/region` 与 `@jabiz/client` 的 `clientRegion()`、启动检查 `GEOIP`（P5，#468）。
会话 S3，分支 `1.3/quizbuks-fs11-foreign-video`。

## 0. 范围

一个 PR 做完 F-S11 中不依赖 F-S12 的全部。**共享视频（F-S12）合入后接上**：`content.ForeignVideos.foreign(Stream<String> 链接, 网站)` 只看一串视频链接，
F-S12 把版本引用的共享视频的链接并进 `ForeignVideos.videoLinks` 即可（卡片冻结、开始答题、模板与提示都不用改）；前端 `foreignVideo` 同理。

**删除的功能：无。** 已有的行为只多一条限制：从中国大陆（或查不到的地址，按参数）开始含境外视频的发布被拒；其他国家、不含境外视频的发布、继续进行中的会话都与以前相同。

## 1. 规则（一处定义）

- **境外视频**（`content.ForeignVideos`）：版本中任何一个视频链接资料（基准与每种其他语言自己的资料，Q73）的网站（`VideoEmbeds.site`）不在受控参数 `qb.video.mainland-accessible-sites`（缺省 `bilibili,youku,tencent`）中，或认不出网站，即"含境外视频"。空链接不算视频。普通链接资料（`LINK`）不算。
  前端 `qb/video.ts` 的 `videoSite` / `foreignVideo`（App 与发起方页面共用的 `src/qb`）与管理系统扩展的 `video.ts` 照抄，三处用 `VideoEmbedsTest.aVideoLinkHasItsSite` 与 `ForeignVideosTest` 的同一组用例。
- **中国大陆的请求**（`region.RegionRules.mainland`）：`ClientCountry` 为 `CN`；查不到时按参数 `qb.region.unknown-ip-country`（不受控，缺省 `CN`；空 = 不算任何国家）。香港、澳门、台湾不是中国大陆。资料中的国家不起作用（A3-19：地区定向、人数估算与受众规则费仍按资料中的国家）。
- **例外**（A3-15，`QbRegionException`）：按发布或按发起方（其全部发布，含以后的），必填原因，可选到期日（UTC 的日期，含当日；过了即不算，比较日期，不需要任务）；撤销后不能再改。
- **拒绝**：`RegionRules.refused` = 中国大陆 ∧ 卡片 `foreignVideo` 不是 `false`（空值按"含境外"）∧ 没有生效的例外。邀请制的发布同样适用。

## 3. 语句数（`AttemptStatementBudgetIT` 不变）

`LoadClientCountry` 在内存中查找、不发语句；例外与参数的读取只在"新开始 ∧ 卡片含境外 ∧ 中国大陆或查不到"时发一条锁外语句（`QueryCompiler.alwaysFalse`：`AND` 中有空的 `IN` 即不发）。
普通的开始（预算测试的卡片没有视频）一条也不多；被拒的开始多一条锁外语句后即结束，不进锁。被拒次数在内存中计数（被拒的事务回滚，写不进库），由每小时的任务写入：答题路径不写任何新数据。

## 5. 运维与部署

- 正式环境须配置地址库（`JABIZ_GEOIP_DATABASE`，DB-IP "IP to Country Lite" 的 CSV，可为 `.gz`），否则正式模式下启动失败（`DeploySafetyCheck`）。
  `server/compose.yaml` 加卷 `geoip`（挂在 `/var/lib/jabiz/geoip`），文件由运维每月放入、平台一分钟内重新读入（D74）；`jabiz.geoip.required` 不在 `application.yml` 中设：
  它会让测试、e2e、本机开发与 `deploy` 的 compose 冒烟测试都必须带地址库，正式模式的检查已足够（测试与本机只有警告）。
- 测试系统（staging）不是正式模式：没有地址库只是警告，所有地址查不到、按参数（缺省中国大陆）对待，含境外视频的发布在那里一律不能答。要在 staging 测试，放入地址库，或以 `PARAM_SET` 把 `qb.region.unknown-ip-country` 设为别的国家。
- 部署后运行一次 `QB_SETUP`（建两个参数，受控的那个由另一位管理员发布；在发布之前按缺省值）。

## 6. e2e

e2e 的应用不配置地址库：浏览器来自本机（`127.0.0.1`），对平台是查不到的地址，按参数缺省为中国大陆，会让含 YouTube 的 `play.spec.ts`、`watch-video.spec.ts` 被拒。
所以 `support.ts` 的 `prepareQuizbuks` 在 `QB_SETUP` 之后把 `qb.region.unknown-ip-country` 设为 `JP`，原有测试照旧。
新的 `foreign-video.spec.ts`（e2e 单线程运行）：含 YouTube 的发布；页面问到的地区由测试回答为中国大陆（`page.route('**/api/client/region')`，平台对中国大陆地址的回答）时首页不列出、发布页说明不可用（axe）；
服务端的拒绝以把参数临时设为 `CN` 覆盖（"查不到 = 参数"），之后设回 `JP`；地区回答为日本时列出并能开始。
**没有用测试地址库的条目**：e2e 的应用在 CI（工作目录 `backend`）与 `tools/quizbuks/e2e.sh`（任意目录）中启动，地址库要给两处不同的绝对路径，且要信任本机代理并让浏览器带 `X-Forwarded-For`；
地址库与可信代理之后的地址由后端的 `ForeignVideoIT` 覆盖。要在 e2e 中也走地址库，另在两处启动脚本中设 `JABIZ_GEOIP_DATABASE` 与 `JABIZ_TRUSTED_PROXIES=127.0.0.1/32`（待定）。

## 7. 风险

- 地址库的准确率：香港、澳门与大陆相邻地址段可能误判；VPN 绕过（需求方接受，D74 剩余风险）。
- 参数缺省按中国大陆：没有地址库的环境（staging、本机）含境外视频的发布一律不能答（有意的取向，启动检查与每日检查告警）。
- 回填只认缺省的三个网站：迁移时参数若已改成别的值，回填结果与之后冻结的不一致（参数在本 PR 才建立，实际不会）；回填函数与 `VideoEmbeds` 由 IT 逐一比较。
- 被拒次数在内存中计数，实例停止前未写出的一小时内的次数会丢（只是统计）。
- 首页等列表的隐藏靠前端传参，防线只在开始答题：直接调模板的人可以看到列表，但开始不了（与 D74 第 4 条一致）。
