# F-S13 推送与曝光的计数：实施计划

依据：`docs/quizbuks/first-launch-spec.md` F-S13（以它为准）与 F-M8（钱的部分，只写接口）；`Q112-video-push.md` §0-3、§0-4、§2–§4 只作参考。
会话 S3，分支 `1.3/quizbuks-fs13-exposure`，叠在 F-S8（`1.3/quizbuks-fs8-blocks`，#566，未合入）之上：推送必须套用屏蔽的条件。基线已含 F-S9 主题词与严格模式、F-S10 短视频与竖屏模式、F-S11 境外视频、F-S12 共享视频（卡片的 `sharedVideoId` / `videoProviderId`）、F-C3、F-S15 任意网址的视频与 Q75 看完才能答（`WatchRules`）。
总控决定 A（2026-11-09，约束本项）：已购次数是发布上的字段，只经一个内部子流程写入，供 F-M8 的购买流程调用；空即不限、永不结束；结束、通知与每日核对按"已用 ≥ 已购"；超出已购的照记、不计费；迁移暂用 V98。

## 0. 范围

一个 PR 做完 F-S13 的计数与推送；钱的部分（单价、预付、结算、追加购买与按比例提醒）随 F-M8。

- **"他人的视频"**：卡片冻结了共享视频（F-S12 的 `sharedVideoId`），且提供方 `videoProviderId` 不是发布方本人。只有这样的发布推送、计曝光；用自己的视频（自己的资料，或将来允许选自己的共享视频）一律不计、不推。
- **推送**：竖屏模式中出现的、用他人**竖屏**共享视频的发布。只经首页模板 `qb.app.feed` 的新参数 `push` 取数（同一模板：屏蔽 F-S8、严格模式 F-S9、境外 F-S11、地区、受众、语言、本人的发布等全部条件自动套用，`BlockIT` 与 `ExposureIT` 的比较测试保证），另加"本人没有打开过"。横屏的这类发布不推送（竖屏模式只放竖视频），只在开始答题页计曝光。
- **F-M8 的接口**：发布的 `exposurePurchased` 与子流程 `QB_EXPOSURE_PURCHASED_SET`（第 2 节），计费的次数 = min（成功次数，已购次数）。规格的 F-S13 与 F-M8 两节都写明。
- **不做**：按推送效果自动调价（规格）；钱（F-M8）。

**删除的功能：无。** 不用他人视频的发布与以前完全相同；首页一排照旧列出全部竖屏发布（预览不计曝光）；竖屏模式照旧，只是用他人视频的发布改在推送位置出现（第 1 节）；答题路径不变。

## 1. 规则（一处定义：`exposure.ExposureRules`，App 的 `exposure/rules.ts` 照抄，同一组用例 `quizbuks-web/app/src/exposure/exposure-cases.json`，照 `WatchRules`）

- **谁的观看算数**：已登录、已验证邮箱的学者（流程 `requiresVerifiedEmail`）；不算发布方、提供方本人及其店员（Q39 的 `QbSponsorStaff`：店员属于发布方或提供方的）。
- **竖视频**（卡片 `videoVertical`）：首页一排的预览不计。竖屏模式中当前屏连续播放 ≥ `qb.exposure.seconds`（10）秒计一次；视频本身比这短（卡片的 `videoDurationSec`）时，连续播放到视频的长度即算（`neededSec`）。
- **横视频**：只在开始答题页计：视频在页面上（至少一半在视口内）且页面在前台，同样连续 ≥ 秒数。首页自动播放不计；没答的发布照常反复出现。
- **时间怎么量**：能读进度的播放器（YouTube、Vimeo、视频文件，即 `VideoEmbeds.trackable`）按播放器的连续播放时间（暂停、跳转、结束即从 0 重新计，速度上限同 Q75 的两倍）；其他网站的播放器与其他网页按"画面上且页面在前台"的连续时间。页面不在前台（切到别的应用或锁屏）即从 0 重新计。
- **每人每个发布至多一次成功**（竖横同一行：`qb_exposure` 以（发布、用户）唯一）。竖视频只在竖屏模式计，横视频只在开始页计（方向不对的报告不计）。
- **每日上限**：一个账号每个 UTC 日至多 `qb.exposure.daily-cap-per-user`（200）次成功；到了上限的报告不计，记在那一行（`cappedDays` 同一天同一发布加一次、`lastCappedOn`），供运营商的可疑刷量页按账号汇总。
- **打开**：推送成为竖屏模式的当前屏即"打开过"（不论看了几秒），记 `openedAt`，以后不再推送给这个人（`qb.app.feed` 的 `push` 排除）。竖屏模式中这类发布只在推送位置出现：从首页一排点进来的那一个照常作为第一屏（打开即记），其余的从普通顺序中拿掉，所以"看过的人不再看到"。
- **推送的位置**：从打开的那一屏起，第 N、2N、3N…屏是推送（N = `qb.exposure.push.every`，5，范围 1–50）；推送用完了放普通的，普通的用完了剩下的推送接着排（`ExposureRules.pushAt` / App 的 `placePushes`）。
- **轮流**：几家使用方轮流：按发起方（卡片的发起方名称；卡片不带发起方编号，F-S8 的约定）轮流取，同一发起方的按首页顺序（`rotate`）。
- **去答题**：竖屏模式中点"去答题"、开始页点"开始答题"时报 `GO`，记 `wentToAnswerAt`（只作统计，客户端的报告）。
- **用完即停**：发布有已购次数且成功次数 ≥ 已购时，分钟级的逐项任务 `qb.exposure-ends` 以 `QB_PUBLICATION_EXPOSURE_END` 结束它（新的结束原因 `EXPOSURE`"曝光已用完"）：进行中的答题照常完成，发起方收到"发布已结束"的邮件（原因写"曝光已用完"）。已结束的发布不再计数（报告时卡片不是进行中即不计）。
- **超出不计费**：并发下成功次数可能略超已购（任务每分钟一次、报告不取锁）。计费的次数 = min（成功，已购），超出 = max（0，成功 − 已购）（`ExposureRules.billable` / `overshoot`，模板写同一算式）；逐行时按计数时间（再按行号）排在已购之内的为计费的。没有已购（空）即不限、全部照记、永不因此结束。
- **每日核对**（`qb.exposure-check`）：成功 ≤ 已购 + 容差（`ExposureRules.tolerance`：max（20，⌈已购 × 5%⌉））；已结束的发布在结束一分钟之后没有新的成功。有差异即给总部（`qb.admin.exposure.monitor`）一个待办，一天一个。

**F-M8 的接口**（总控决定 A）：
- `QbPublication.exposurePurchased`（时态，`processOnly`，整数 ≥ 1 或空；空即不限），卡片的同名字段随之同步。
- 子流程 `QB_EXPOSURE_PURCHASED_SET {publicationId, purchased}`（`subProcessOnly()`，权限 `qb.publication.system`，不授予任何角色）：取发布锁 `qb.pub:<发布>`（F-M8 的提交在发布锁内以 `CallProcess.of` 调用时锁已在本事务中），写发布的下一版本与卡片（有卡片时）；草稿与进行中都可以，已结束的 422 `QB_EXPOSURE_PUBLICATION_ENDED`；不改状态，所以不取开始锁。不给发起方页面与管理系统；复制发布不带。
- 计费的次数 = min（成功，已购）；成功次数是 `qb_exposure` 中该发布 `counted_at` 不为空的行数（`qb.sponsor.exposure` 的 `successes` / `billable` / `overshoot`）。

锁：上报取本人的锁 `qb.exposure:<用户>`（同一人的报告依次处理，每日上限因此准确），**不取发布锁、开始锁或钱包锁**。结束流程照状态流程取发布锁与开始锁（锁序不变）。写已购只取发布锁。

## 3. 语句数

- **答题路径不变**（`AttemptStatementBudgetIT` 不变）：开始、提交、超时都不读也不写曝光；开始页的计时与上报是另外的请求。
- 上报 `QB_EXPOSURE_REPORT`：参数一条、卡片与本人店员身份一条（`QueryEntities.all`）、取本人锁、本人这批发布的行与今天的成功（`QueryEntities.all`，一条）、写入（缓冲，提交前写出）。不在热门发布的锁内，不读计数。
- 首页模板多一个相关子查询（`push` 时本人的打开，唯一索引）；不是答题路径。

## 6. 决定（需转达总控 / 需求方，可改）

1. **推送只取竖屏的**：竖屏模式只放竖视频，用他人横屏视频的发布只在开始页计、不推送。
2. **竖屏模式中这类发布只在推送位置出现**；首页一排照旧（预览不计），从一排点进来的那一个照常是第一屏（打开即记）。
3. **推送位置**：从打开的那一屏起每第 N 屏；推送不够时放普通的，普通的不够时推送接着排。
4. **轮流按发起方名称**：卡片不带发起方的编号（F-S8 的约定），按名称分组轮流。
5. **"打开" = 推送成为当前屏**（不论几秒）。
6. **连续时间**：暂停、跳转、结束、切到别的应用即重新计；短于秒数的视频连续播放到它的长度即算。
7. **横视频只在开始页计、竖视频只在竖屏模式计**（规格）；竖视频的开始页不计，横视频不进竖屏模式。
8. **每日按 UTC 日**；上限的命中记在行上（同一天同一发布记一次）。
9. **计费不逐行存标记**：计费 = min（成功，已购），逐行按计数时间排在已购之内的为计费的；比存标记稳（并发时标记会与总数不一致）。F-M8 的结算按这个数。
10. **已购字段在发布与卡片**，子流程只取发布锁、草稿也可设、已结束的拒绝、复制不带。
11. **结束通知用已有的"发布已结束"邮件**（原因"曝光已用完"），不另加模板。
12. **去答题是客户端的报告**，只作统计。
13. **删除账号时曝光行保留**（只含编号，同答题与浏览，平台决策 D62 第 4 条）。
14. **核对的容差** max（20，⌈已购 × 5%⌉），结束后一分钟的宽限；待办给总部的 `qb.admin.exposure.monitor`。
15. **运营商的可疑刷量页**按账号汇总自己发起方的发布上的上限命中（命中次数、天数、最近一次、这些发布上的成功），列出到达上限的账号；总部看全部。
16. **上报**：攒到 `qb.exposure.report.batch`（20）条或 `qb.exposure.report.interval-sec`（30）秒先到者，切到别的应用、锁屏或关闭时立即发；一次至多 50 条；流程限流每人每分钟 30 次。

## 8. 风险

- 客户端报告的秒数无法验证（同 Q75 D-Q75-1）：防线是每人每发布一次、每日上限、本人与店员不计、限流与运营商的可疑刷量页。
- 每分钟的任务汇总成功次数：只看有已购的进行中卡片（部分索引），每张卡片按（发布、用户）唯一索引数行。
- 并发超出：两次任务之间（至多约一分钟）的成功照记，不计费，核对按容差。
