# 压测程序：大题库与继续答题（实施计划，S1）

来源：上线准备"性能"："在上线所用的硬件上，以带千题题库与抽题的发布重测（版本快照变大后的开始、继续、提交），分析任务照常运行"。
2026-11-08 总控把"压测程序缺千题与抽题场景的部分（代码）"交给 S1；staging 预跑与上线硬件实测随服务器。

## 做什么

- `LOAD_QUESTIONS`（缺省 2）：压测的测验有这么多题（每题三个选项），及格分与档位随之（全对得奖励）。
- `LOAD_CONTINUE=yes`：每个学者开始之后再打开一次答题（`QB_ATTEMPT_START` 对进行中的答题即继续，检查答复的 `resumed`），单独计时一行；"一位学者"一行改名为"开始 + 继续 + 提交"。
- 修复：压测的准备阶段在 Q7b 之后已跑不通。申请发起方须带当前有效的条款与隐私政策版本，充值与提交发布前须已同意。
  现在照页面的做法：申请时带上版本，充值与提交前先同意未同意的文本。
- **抽题与千题还做不了**：F-S6（千题题库）与 F-S7（抽题）由 S2 负责，都未开始；题数上限现在是 100（`ContentLimits.MAX_QUESTIONS`）。
  压测已按开始的答复中实际给出的题目作答，抽题合入后只需在发布的保存中加上抽题的参数（届时加 `LOAD_DRAW`），由合入 F-S7 的一方或 S1 补上。
