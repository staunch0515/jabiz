## 3. 保证"做出来与讨论一致"的办法

1. **规格只在一处**：`app/src/frame/xspec.ts`（数值）与 `brand.css`（颜色 token）。Q113 §9 表中的每个数（53、106、12/16、40、8、20、16、56、275/600/350/30、0.35s、0.17s、20px 空程、50px 回弹阈值、0.3 不透明度）在这里各有一个名字，页面与组件只引用名字；lint 规则禁止在 `frame/` 与改版过的页面中写这些数的字面值。
2. **几何检查（Playwright，`e2e/tests/x-spec.spec.ts`）**：在 390×844 与 1280×900 两种尺寸下量真实页面，断言 Q113 §9 的每一行，例如：
   - 条目：头像 40×40、头像左边距 16、内容左边 = 头像右 + 8、**名字行顶端 = 头像顶端**、"…"不改变名字行高度、媒体圆角 16 且宽度 = 内容列宽、操作行距上 12。
   - 头部 53、标签行 53、选中指示条高 4 且宽度 = 文字宽（不小于 56）；子页返回按钮 36、距左 8。
   - 底部栏 53 + 安全区、只有图标（26）、4 项等分；悬浮按钮 56、距右 20、距底部栏 20。
   - 宽屏：左 275、中 600、右 350、中右相隔 30；导航项 58、主按钮 233×52。
   - 页面里没有任何竖向滚动区（除整个文档），手机上不显示滚动条。
3. **滚动行为检查（同一文件）**：向下滚 60px → 头部上移 40（20 空程）、底部栏不透明度 ≈ 1 − 0.7×40/106；滚满 → −106 与 0.3；分 5 次各上滚 20px → 不出现；一次上滚 60px → 全部恢复；回到顶端 → 恢复。
4. **单元测试**：滚动规则写成一个纯函数（`frame/scrollChrome.ts`：输入上次位置、本次位置、当前偏移，输出新偏移），用 Vitest 按 §9.1a 的实测数列逐条测。
5. **截图对照**：每个阶段在 PR 中附手机与宽屏的截图，与原型并排；需求方确认后才合入。
6. **PR 描述逐行对照** Q113 §9 的表格，每行写"满足 / 不满足（原因）"。

## 4. 各阶段的改动

### Q113a 框架

- `brand.css`（两个 SPA 共用，CI 比较）：方案 A 的 token：正文、次要、分隔线、描边、强调、主按钮近黑、奖励金（填色与文字两个）；亮色先做，暗色在 Q113e。
- `frame/xspec.ts`、`frame/scrollChrome.ts`（纯函数）与 `frame/useScrollChrome.ts`（文档滚动 → 偏移 → 头部 `transform` 与底部栏、悬浮按钮的不透明度）。
- `frame/Header.tsx`：三种头部（一级页：32px 头像 → 抽屉、20px 标题、右侧图标；首页：中间标志；子页：返回 36 + 标题 + 小字；沉浸页：只有关闭），吸顶、85% 白加模糊。替换现在的字标栏与 `AreaHeader` 的大圆图标。
- `frame/Tabs.tsx`：53px 标签，指示条与文字同宽；平台 `PageTabs` 能表达则用平台的，不能则先补平台（同 P）。
- `frame/AppFrame.tsx`：底部栏 4 项（平台 `BottomBar`，P 的新属性）、悬浮按钮"扫一扫"、侧边抽屉（平台 `Sheet`，左侧，宽 280）、宽屏三栏（左 275 导航 + 主按钮 + 账号块；中 600；右 350 辅助栏：搜索、待领奖品、值得关注的发起方）。
- `frame/areas.ts`：区域改为 首页 / 搜索 / 已答 / 通知；"我的"的条目移入抽屉；旧地址（`/scan` 作为区域、`/account` 作为区域）的转向经 `LEGACY_APP_…`。
- 测试：`frame.test.tsx`、`areas.test.ts`、`up.test.ts` 按新结构改；新增 `scrollChrome.test.ts`；e2e `taker-frame.spec.ts` 改为新导航，新增 `x-spec.spec.ts` 的框架部分。

### Q113b 首页与答题开始页（普通模式）

- `qb/view/FeedCard.tsx`：X 的帖子结构（头像 40 + 8 + 内容；名字行 20 与头像顶端对齐；"…"浮在右上；正文；媒体 12/16；操作行：奖励金色、已答人数、时限、分享）。三处点按：头像与名字 → 迷你网站，名称与正文 → 普通模式，视频 → 视频流转模式（Q113c 之前先进普通模式）。**`qb/` 是两个 SPA 共用的目录**，发起方页面的预览随之改变，预览测试一起更新。

- `pages/PublicationPage.tsx` 与 `qb/view/PublicationContent.tsx`：答题开始页的普通模式按 X 的帖子详情（作者行 + "主页"、17px 正文、发布信息行、信息行在两条分隔线之间、资料与规则两个标签、底部固定"开始答题"栏，看视频的进度在栏中）。去掉给学者看的完成统计表（Q113 P8）。

### Q113c 视频流转模式

- `shorts/ShortsViewer.tsx` 扩展为所有带视频的答题（横屏视频居中、黑底），从被点的那一条开始，按首页顺序，跳过不带视频的。地址沿用 `shorts=<id>`（首页的浏览位置保留）。
- 叠加层：发起方（→ 迷你网站）、名称、奖励、"详情"（→ 普通模式）与"开始答题"（直接开始；Q75 未满足时不可用并显示还差秒数）。条目模型的两个按钮各自可有可无（为以后的广告与娱乐视频留位置，本阶段不实现这两类）。
- 测试：`shorts.test.tsx` 扩展（横屏、跳过、两个按钮、看视频的门槛、声音保持）；e2e 一条：首页点视频 → 流转 → 上滑 → "开始答题"。

## 5. 风险

- **改动面大**：框架、首页、开始页、竖屏模式与约 20 个页面；分阶段合入，每阶段都可单独回退。
- **平台依赖**：底部栏只显示图标、标签指示条等如平台组件不能表达，需先在 `1.3/platform` 补（阶段 P），会推迟 Q113a。
- **共用目录 `qb/`**：条目与开始页的改动会影响发起方页面的预览，两边测试一起改，CI 的目录比较照常。
- **首页视觉基线**：Q113a、b 必须更新，需在 PR 中说明。
- **无障碍**：底部栏只显示图标时，文字必须仍可被读屏读到；滚动变淡后仍要能点按且对比度不作要求（与 X 相同，属于暂时状态），恢复后满足 4.5:1。
- **X 的规格可能变化**：以 Q113 §9 记录的 2026-11-24 实测值为准，不追随 X 以后的改动。
