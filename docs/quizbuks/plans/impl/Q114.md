# Q114 实施计划：学者的头像（2026-11-27；需求方确认）

## 0. 为什么

Q113 照 X 改版之后，头像出现在三处：一级页头部的左上角（打开抽屉，32px）、宽屏左栏底部的账号块（40px）与我的主页（93px）。三处都是
`frame/Drawer.tsx` 的 `Initial`：名字首字加品牌绿（`bg-primary`）。所有学者同一种颜色，首字相同就完全一样。

需求方（2026-11-27）：要给每个学者选自己头像的功能；两步都做——先"选一个"（不上传），再"上传自己的照片"。

## 1. 已定的边界

- **只有本人看得到**。现在学者的头像不给发起方、其他学者看（管理员的数据浏览只有种类与预设代码，看不到照片）；两步都保持这一点。以后要给别人看（答题名单、排行、对话），是另外的决定：
  先要有举报、撤下与审核（中国大陆对公开的用户头像有内容审核的要求），不在 Q114。
- **横幅不做**（Q113 已定"没有上传横幅的功能，不新加"）。
- 头像只改三处的显示与"编辑资料"页，导航、尺寸（`xspec.ts` 的 `avatar: 32`）与其他页不变。
- 去掉的功能：无（首字头像保留为一种选择，也是缺省）。

## 3. 数据与流程（Q114a 建，Q114b 加照片）

### 3.1 为什么另建一张表，不加在 `QbProfile` 上

`QbProfile` 是时态实体（只追加）。头像放在它上面，换下的照片仍被旧版本引用：文件永远不会成为孤儿，只有删除账号时才会清除。
学者"换掉 / 去掉照片"时期望照片随即消失，所以头像另放一张**普通表**（可更新、可删除，平台审计 D27 照常记录前后值）。

### 3.2 `QbTakerAvatar`（普通表 `qb_taker_avatar`，迁移 `V<下一号>__qb_taker_avatar.sql`）

| 字段 | 说明 |
|---|---|
| `userId` | 主键（文本，不可变）：一人一行 |
| `kind` | `INITIAL` / `PRESET` / `PHOTO`（Q114b 起），代码字典 `qb-avatar-kind` |
| `preset` | 预设的代码（`p01`…`p12`，只在 `PRESET` 时有值），代码清单只在 `AvatarPresets.CODES`（前端 `avatar/presets.ts` 同一清单，`AvatarPresetsTest` 与前端测试读同一份 `avatar-presets.json`） |
| `photo` | 文件（策略 `qb.taker-avatar`，Q114b，只在 `PHOTO` 时有值；列 `uuid`，不加外键） |
| `editedAt` | `processOnly`，最近修改 |
| `version` | 平台的版本（普通表的更新按读到的版本） |

- 没有行 = `INITIAL`（缺省），所以已有的学者不需要迁移数据。
- 默认数据视图 `processOnlyWrites`，只给读用户的管理员（`qb.admin.users.read`，同 `QbUserSettings`）：数据浏览中看到种类与预设代码，照片文件本身他们读不到（§5.1）；
  本人只经 `me:QbTakerAvatar` 读自己的一行。
- 首字的颜色**不保存**：前端按 `userId` 的哈希从颜色表取（同一个人在所有设备上相同，规则只在 `avatar/colour.ts`）。

### 3.3 流程 `QB_AVATAR_SET`（`identity.AvatarProcesses`）

- 输入 `{ kind, preset?, photo? }`（`kind` 为枚举，未知的值 400）；权限 `qb.me`，`requiresVerifiedEmail()`（同 `QB_PROFILE_SAVE`），
  第一步读调用者的封禁（`CallerChecks.refuseBanned`，因此不在 `BanCoverageTest` 的例外中）；取本人的头像锁 `qb.avatar:<用户>`。
  后写的为准（同 `QB_SETTINGS_SAVE`）：一次点选就是一次完整的选择，没有要合并的字段，不比较版本。
- 校验：`PRESET` 必须有清单内的代码（422 `QB_AVATAR_PRESET_UNKNOWN`）；`PHOTO` 必须是存在的、本人上传的、策略为 `qb.taker-avatar` 的文件
  （本人上传照发起方头像的 `AccountEditing.requireOwnFile`；它不查文件是否存在与策略，这两条在头像流程中另查，422）；其他组合 400。
- Q114b：换下或去掉照片时，先清空引用并 `SaveChanges.now`，再 `CallProcess.of("FILE_DELETE", …)`（CLAUDE.md 的文件规则），照片当即删除。
- 不发事件、不写站内信；`input_summary` 不含文件名。

### 3.4 删除账号

`SponsorErasure`（它负责所有用户的资料）加 `ErasedEntity.delete(QbTakerAvatars.AVATAR, "userId")`：行删除，照片因此成为孤儿，
由 `FILE_PURGE_ORPHANS` 清除（平台 10 §17 的做法）。`TakerErasureIT` 覆盖新表。

## 4. Q114a：选一个

### 4.1 显示

- 新组件 `frame/Avatar.tsx` 取代 `Initial`（三处一起换，测试编号照旧：`me-avatar` 等）：
  - `INITIAL`：首字，底色是品牌档案的 8 个 token `--qb-avatar-1…8`（`brand.css`，亮暗相同；`avatar/colour.ts` 按编号取一个，白字 `--qb-avatar-foreground` 在每种上 ≥ 4.5:1，`qb/brand.test.ts` 检查每份档案）；
  - `PRESET`：品牌档案的图片 `brands/<品牌>/public/avatars/<代码>.svg`（站点自己提供，与图标同一处；页面代码中没有色值，CLAUDE.md §5 的品牌规则），读不出时退回首字；
  - `PHOTO`（Q114b）：`FileImage` 的 128 / 256 变体，`object-cover` 圆形裁切。
- 头像仍是 `aria-hidden`：旁边的链接已有名字（照现在）。
- 读本人的头像用一个查询（`AVATAR_QUERY`），保存后失效重读；读取失败时显示首字，不显示错误。

### 4.2 选择

- "编辑资料"（`/account/profile`，`AccountPage` 的 `ProfilePart` 在 `ProfileForm` 之上；欢迎页共用 `ProfileForm`，不加，保持短）顶部：93px 的当前头像与"更换头像"按钮。
- 按钮打开平台的 `Dialog`（手机上也是 `Dialog`，与 App 其他的选择框相同）：第一格"首字"、其后 12 个预设，网格每行 4 个，圆形 64px，选中有描边与勾；
  键盘可用（单选组，`RadioGroup`），点选即保存（一次 `QB_AVATAR_SET`），失败显示原因并保留原头像。
- 文案三语（`frame/messages.ts` 的 `avatar.*`）。

### 4.3 预设的画稿

12 个平面插画（Q114-0 原型中定：猫头鹰、狐狸、猫、兔子、企鹅、熊、鲸鱼、书、学士帽、灯泡、火箭、地球），每个是品牌档案中的一个 SVG 文件（自带浅色圆底，不随外观变化），
在 32px 仍能分辨。画稿只用应用自己的，不用第三方素材；文件只有图形（测试拒绝脚本、样式与外部引用），每份品牌档案都有全部代码的文件。
预设的名字（读屏读出）在 `avatar/messages.ts` 的 `avatar.presets.<代码>`，三语。

## 5. Q114b：上传照片

### 5.1 文件策略 `qb.taker-avatar`（`AccountsConfig`）

照发起方头像（`qb.sponsor-avatar`）：JPEG、PNG；上限 2 MB；`maxPixels(25_000_000)`；变体 128、256；平台重新编码、去掉 EXIF 与 GPS；
**`privateMetadata()`**（编号为随机 UUIDv4，原名与上传者不给他人看）；上传与读取权限 `qb.me`（只有本人有文件编号）。

### 5.2 上传

- 对话框中加"上传照片"（`<input type="file" accept="image/jpeg,image/png">`）与有照片时的"移除照片"（确认对话框）。
- 选了文件后，页面先在本机按中间裁成正方形、缩到 512px、存为 JPEG（canvas，普通代码），手机拍的 5–10 MB 照片因此不会超过上限；
  预览后点"使用这张"才经 `/api/files?policy=qb.taker-avatar` 上传、再 `QB_AVATAR_SET`。
- 上传或保存失败时显示原因（太大、不是图片、网络），已上传但未保存的文件由平台的孤儿清理删除。

### 5.3 裁剪的范围

第一版**自动按中间裁切**，不提供拖动、缩放的裁剪框。理由：裁剪框是新的界面组件，按规则要先加到平台的 `@jabiz/ui`（另一个平台阶段）。
需要时以后单独做，不影响已保存的数据。

### 5.4 隐私政策

`docs/quizbuks/legal/privacy-policy.{zh,ja,en}.md` 第 23 行"个人资料"加"头像照片（可选，只有您本人看得到；去除位置信息等元数据后保存）"。
法律文本的修改按惯例（Q113-0）由需求方确认生效日期后发布新版本；Q114b 的 PR 只改草稿，不自行发布。

## 8. 风险与待需求方确认

1. **预设的画稿**（Q114-0）：风格与内容由原型确认；不确认不开工 Q114a 的页面部分。
2. **只给本人看**：如果以后要给发起方看（隐私政策第 74 行他们已能看到显示名），需要另立阶段补举报与审核。
3. **裁剪框**：第一版只按中间自动裁切（§5.3）。
4. **隐私政策的生效日期**：Q114b 合并前由需求方决定；未发布新版本前，照片功能可以先关着（不加开关的话就要等新版本发布后再部署）。请确认要不要为此加一个开关，还是按发布日期部署。
5. 中国大陆：照片只给本人看，不属于公开展示的内容；以后公开时再评估审核要求。
