# Q49a 有奖活动规则与举报入口（2026-11-01）

需求方（2026-11-01）："继续，做有奖活动规则页和举报入口"。这是 Q49a（`Q49-mobile-apps.md`）中上架必需的两项；Q49a 的账号删除见 Q71。

- **有奖活动规则**：Apple 规则 5.3 与 Google Play 的竞赛政策要求有奖的 App 公开正式规则，并写明 Apple / Google 不是赞助方、不参与活动。
- **举报**：Apple 规则 1.2 要求含用户生成内容（这里是商家出的测验）的 App 提供举报方式，并有人处理。

## 1. 已确认的决定（需求方 2026-11-01）

| # | 决定 |
|---|---|
| D-Q49a-1 | **只做举报，不做"屏蔽商家"**：内容来自商家（事业者）而不是其他答题者，举报加总部或运营商的下架即满足 1.2；在 App 审核说明中写明（Q49d）。首页的查询不改 |
| D-Q49a-2 | **总部与运营商都处理**：总部的内容管理员看到全部举报；运营商只看到并处理自己负责的商家的（同 Q59c-2） |
| D-Q49a-3 | **规则是法律文本的一个种类**（`CONTEST_RULES`），沿用已有的版本、三语、管理后台发布与公开页；不要求同意 |

## 2. 有奖活动规则

- 法律文本种类 `CONTEST_RULES`（`QbLegal`、字典、`LegalDrafts` 的占位、发布公告的对象为 App 用户）；页面 `/taker/legal/contest-rules`，不登录也能读。
- 草稿 `docs/quizbuks/legal/contest-rules.{ja,zh,en}.md`（日文为准据文本）：主办方是活动页面上的商家，运营者提供平台；**Apple 与 Google 不是赞助方、不参与**；参加资格、免费参加、奖励的决定（按得分的档位、名额与预算按服务器受理的先后）、四种领取方式、取消资格、变更与中止、个人信息、税务、联系方式。须由需求方或律师确认后在管理后台发布（`legal/README.md`）。
- 链接：有奖励档位的测验页面底部、App 账户页的"帮助与信息"。

## 3. 举报

**答题者**：测验页面底部的"举报这个测验"，对话框中选原因（虚假或误导、冒犯或不当、未兑现奖励、垃圾信息或广告、其他）并可写 500 字以内的说明。需要已验证的邮箱（按钮只对已验证的显示），只能举报自己打开过的测验（有 `QB_VIEW` 记下的浏览；其他的与不存在的一样 404）；每人每个测验同时只有一份待处理的举报，每天至多 10 份（按举报人取锁计数）。不告诉商家是谁举报的。

**数据**：普通表 `qb_report`（迁移 V54）：测验、发布方、举报人、原因、说明、状态（待处理 / 驳回 / 已处理）、处理人、时间与处理说明。数据视图与模板要求 `qb.review.publication`（审核发布的人：总部的内容管理员与运营商；财务读不到举报人与说明），按运营商限定（`OperatorScopes`）。

**流程**：
- `QB_REPORT_SUBMIT`（`qb.play`）：先取举报人的锁、再取测验的锁，一条语句读出卡片、浏览、举报人当天的与待处理的举报，写入举报；测验的第一份待处理举报产生待办：商家有运营商时给该运营商（运营商的范围，D64），否则给总部的内容管理员。
- `QB_REPORT_RESOLVE`（总部，`qb.admin.content.write`）/ `QB_OPERATOR_REPORT_RESOLVE`（运营商，成员与自己的商家检查）：把一个测验的待处理举报全部关为驳回或已处理（附说明），关闭待办；需要二次验证。暂停与结束测验用已有的 `QB_PUBLICATION_ADMIN_*` / `QB_OPERATOR_PUBLICATION_*`。

**后台**：总部与运营商的"举报"页（`/qb/abuse-reports`，模板 `qb.admin.reports`）：按测验一行，待处理与全部的件数、按原因的件数、最近的举报；展开看每份举报的原因与说明（纯文本），驳回 / 标记已处理经平台的流程页。

**账号删除**：举报人的说明随账号抹除（`TakerErasure`：`keep(QbReport, reporterId, note)`），举报本身保留，以便处理中的审核继续。

**文档**：隐私政策（三语）第2条加"举报测验的原因与说明"；`store/play-data-safety.md`。

## 4. 测试

- `ReportIT`：
  - 举报、同一测验同时只有一份、另一人的另算、未知原因与不存在的测验；
  - 每天的上限；
  - 待办：没有运营商时给总部，有运营商时只给该运营商、另一运营商看不到；
  - 列表的件数；处理需要二次验证，关闭待办，之后可再举报；运营商只能处理自己商家的。
- 管理后台扩展 `abuseReports.test.tsx`；App `Play.test.tsx`（规则链接、举报对话框与错误）；`legal.test.ts`（两个 SPA）。
- 场景的快照：`QB_SETUP` 多建一份规则的草稿，此后的编号顺移；答题的选项顺序按编号打乱，几个场景的答案随之调整。

## 5. 部署后

- 再执行一次 `QB_SETUP`：为新的种类建草稿（已有的不动）。
- 规则的正式文本发布前，App 中的链接打开"尚未发布"。

## 6. 不在本项内

- 屏蔽商家（D-Q49a-1）。
- 举报商家主页与商品（只举报测验；商品已有总部与运营商的下架，Q60b）。
