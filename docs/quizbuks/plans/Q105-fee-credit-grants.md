# Q105 平台费 Kudos：赠送给发起方、只能用来付平台费（计划，2026-11-05 第三稿；需求方确认 §1）

> **已归档（2026-11-07）**：首次上线的内容以 [`docs/quizbuks/first-launch-spec.md`](../first-launch-spec.md) 为准，本文只作存档（查当初的讨论用）；两者不一致时以规格为准。

> **首次上线必须支持的业务**（需求方 2026-11-05，Q94 §3 第 7 项）。
> **讨论中的具体数字一律可以设置，不写死在代码中**：金额、有效期、倍数、汇率都是受控参数（§3.7），挑战的赠送额设在挑战发布上。
> 需求方 2026-11-05：**其他需求已经讨论清楚，本计划只是把"免费"量化**：免费 = 赠送的平台费 Kudos 额度。收费本身照各自的计划（Q101 配送费、Q47c 受众规则费由运营商定价；AI 费见 §2）。

需求方 2026-11-05 的讨论（几次补充，以最后一次为准）：

1. **对发起方不免费**：首次上线就收**配送费**（Q101）、**AI 费**、**受众规则费**（Q47c）。
2. 一段时期内**赠送**发起方平台费额度，用来试用系统、支付平台费。以后可能还送，但会越来越少；**活动怎么搞，账都不能乱**。
3. 赠送的叫"平台费 Kudos"，界面上也叫 Kudos，但**和发起方能发给答题者的 Kudos 不是同一个账户**，只能在平台消费，**不能给人做奖励**。
4. **免费由额度控制，可以精细到每个发起方**：每个发起方免费的程度可以不同。
5. 发起方**资料完整（由审核员主管判断）、入驻审核通过后**发放：**未认证 1,000，企业实名认证后 10,000**。
6. 也可以在发起方**答对某个题之后**赠送（如平台知识结构图上的挑战，Q90 §2.8）。
7. **赠送有有效期**。
8. **全部记账**，记在与奖励 Kudos 不同的科目中；平台上**不记负账**。
9. **赠送不分成**：用赠送额度付的平台费不进运营商的分成。
10. **赠送出去的，以后要从运营商的分成中扣出来**（取代第一稿"由财务线下记录、平台不反映"）。
11. **企业实名认证**：公开主页显示"已实名认证"；**真实性以电子邮件的域名判断**。
12. **首次上线就做**；送到什么时候、以后送多少，另定（受控参数）。

编号 Q105。**这只是计划**：§7 的几处细节定下后开发，在工作分支上经 PR 合入。

## 1. 决定

| # | 决定 |
|---|---|
| D-Q105-1 | **独立账户**：每个发起方多一个"平台费 Kudos"余额（`QbWallet` 新种类 `FEE_CREDIT`），与学分钱包（`SPONSOR`，发奖）、现金账户（`CASH`，Q87a）并列，三者在同一把锁 `qb.wallet:SPONSOR:<发起方>` 内修改；余额有 `>= 0` 的检查约束，从不为负 |
| D-Q105-2 | **只能付平台费**：配送费、AI 费、受众规则费，以及以后的其他平台费（`QB_FEE_CHARGE` 的各种类）。**不能换成学分、不能发奖、不能转让、不能提现或退款**；没有任何流程把它转出到别的账户 |
| D-Q105-3 | **支付顺序**：记费时先用平台费 Kudos，**先用最早到期的那一笔**；不够的部分照 Q87 的规则（预付从现金账户扣、不够即成未付账单；后付记应收）。一笔费用可以由两部分支付，账单上分开写明 |
| D-Q105-4 | **每一笔赠送都有有效期**：自发放起 `qb.fee-credit.valid-days` 天（受控参数）；到期未用完的部分由每日任务作废并记账（§3.3）。追加（D-Q105-8）可以另定该笔的有效期 |
| D-Q105-5 | **赠送只经一个流程** `QB_FEE_CREDIT_GRANT`（`subProcessOnly()`），每笔有来源与来源键（§3.1），记录 `QbFeeCreditGrant`（只写一次，带金额、到期、**发放时发起方所属的运营商**）；同一发起方、同一来源键至多一笔（唯一约束） |
| D-Q105-6 | **开户赠送由审核员主管确认"资料完整"后发放**：入驻已通过的发起方，由所属运营商的审核员主管在运营商后台的发起方页确认"资料完整"（`QB_SPONSOR_PROFILE_COMPLETE_CONFIRM`），确认即发放：未认证发 `qb.fee-credit.grant.basic`（1,000），已认证发 `qb.fee-credit.grant.certified`（10,000）。先领了未认证的、之后通过企业实名认证的，**补差额**（来源"认证补发"），合计不超过已认证的金额 |
| D-Q105-7 | **答题赠送**：平台的挑战发布（点亮者为发起方的平台知识结构图，Q90 §2.8，由运营商的官方账号发布）可以把"平台费 Kudos"设为合格时的奖励；合格即发放（来源"挑战"）。这代替 Q90 §2.8"发起方答题暂时不给学分" |
| D-Q105-8 | **按发起方追加**：运营商可以给某个发起方追加额度（金额、理由必填、可选的有效期），由另一位成员批准（四眼）。"每个发起方免费的程度不同"由此实现；平台不设追加的上限（需求方 2026-11-05：不用管），成本照 D-Q105-10 从该运营商的分成中扣回 |
| D-Q105-9 | **赠送不分成**：用平台费 Kudos 支付的平台费**不计入**运营商的分成基数（Q87b / Q92），结算单上单独列出 |
| D-Q105-10 | **从运营商的分成中扣回**：每月结算时，从该运营商应得的分成中扣除当月**用掉的**赠送额度（§3.4），扣不完的结转到下月（同 Q48d 的获客费用）。归属按发放时冻结的运营商 |
| D-Q105-11 | **企业实名认证以邮件域名判断**（§3.5）：发起方以公司域名的邮箱验证，审核员确认这个域名属于这家公司；通过后公开主页显示"已实名认证"。同一域名只认证一个发起方 |
| D-Q105-12 | **首次上线即做**；开关、金额、有效期、追加的上限都是受控参数（四眼修改），活动的开始、结束与以后的金额只改参数、不改代码 |

## 2. 首次上线收的费用（对 Q94 的影响）

需求方 2026-11-05：首次上线就收**配送费、AI 费、受众规则费**。因此除本计划外，首次上线还要做：

| 费用 | 依据 | 状态 | 说明 |
|---|---|---|---|
| 配送费 | `Q101-publication-fee.md` | 计划已确认，未开发 | 按开始答题的人数、单价随最高奖励、运营商定价、按月结算 |
| 受众规则费 | `Q47c-audience-billing.md` Q47c-2 | Q47c-1（价目与报价）已做，扣款未开发 | 提交时扣款、驳回等退回 |
| AI 费 | 本计划 §2.1 | 未开发 | **按大模型的收费的 150%**（需求方 2026-11-05），不由运营商定价 |

三者都经 Q87 的 `QB_FEE_CHARGE` 记费，所以都自动先用平台费 Kudos（D-Q105-3）。Q94 §4 的"平台不收钱"随之改写。配送费与受众规则费由运营商定价（各自的计划）。

### 2.1 AI 费

- **价格 = 大模型提供方的收费 × 150%**。提供方的收费即现有 `QbAiJob.costUsd`（`AiCost`：按各模型的标价计 token，回退模型的部分按回退模型，没有回答的尝试按预留计入，D52 第 5 条）；从官网生成（Q104）另加网页搜索的费用（`ClaudeWebResearch.searchCost`）。
- **换成日元**：费用 = ⌈`costUsd` × `qb.ai.fee.markup`（1.5）× `qb.ai.fee.usd-jpy`⌉ 日元；两个都是受控参数（汇率按需以四眼更新，同 `qb.prospect.usd-jpy`）。
- **何时记费**：作业结束时（完成、失败、取消都按实际用量，同现有的用量记录），由结局流程以 `QB_FEE_CHARGE`（种类 `AI`，来源为 `QbAiJob`）记费；不足 1 日元的不记。没有尝试运行过的取消不计费（同 Q8）。
- **适用**：AI 出题、AI 翻译与校对、从官网生成（Q104）。答题路径不变。
- **请求前的报价**：请求对话框显示按预估 token 的最高费用（预估 × 150% × 汇率），可用的平台费 Kudos 与现金一并显示；预付的发起方余额不足以支付最高费用时，请求被拒（同配送费的提交时检查）。
- AI 获客（Q48c）的费用不变：它由运营商承担、从结算中扣（Q48d），不向发起方收。

## 3. 设计

### 3.1 赠送的来源

| 来源 | 来源键（唯一） | 金额 | 有效期 |
|---|---|---|---|
| `ONBOARDING`（开户） | `onboarding` | 未认证 `qb.fee-credit.grant.basic`，已认证 `qb.fee-credit.grant.certified` | `qb.fee-credit.valid-days` |
| `CERTIFIED_TOP_UP`（认证补发） | `certified` | 已认证金额 − 已领的开户金额 | 同上 |
| `CHALLENGE`（答题） | `challenge:<发布>` | 挑战发布上设定的金额 | 同上 |
| `MANUAL`（按发起方追加） | 申请编号 | 申请的金额 | 申请时可另定，缺省同上 |

### 3.2 开户赠送的确认

- **谁确认**：所属运营商的**审核员主管**（新权限 `qb.fee-credit.onboarding.confirm`，授予运营商的主管角色；总部的同一权限可确认任何发起方）。
- **在哪里**：运营商后台的发起方页显示资料、主页、商品与入驻状态，按钮"确认资料完整并发放赠送"。
- **条件**（流程在钱包锁内重读，不满足即 422 并说明）：
  - 开关 `qb.fee-credit.grant.enabled` 为真；
  - 入驻已通过；
  - 未被封禁；
  - 尚未领过开户赠送。
- 企业实名认证在确认之后才通过的，认证通过时自动补差额（不必再确认）。

### 3.3 账

新科目（科目代码由 Q9d 的映射参数 `qb.journal.account.<科目>` 给出，受控，首个值为空）：

| 科目 | 性质 | 维度 |
|---|---|---|
| 平台费 Kudos（赠送额度） | 负债 | 发起方 |
| 推广费 | 费用 | 来源（开户、认证补发、挑战、追加）、运营商 |

| 事件 | 分录（来源单据） |
|---|---|
| 赠送 | 借 推广费 / 贷 平台费 Kudos（`QbFeeCreditGrant`） |
| 用平台费 Kudos 付费 | 借 平台费 Kudos / 贷 4120 平台使用费收入（`QbFeeCharge`；系统内的记账，不另记消费税） |
| 到期作废、注销作废 | 借 平台费 Kudos / 贷 推广费（`QbFeeCreditGrant` 的作废记录） |
| 从运营商分成中扣回 | 借 2140 应付运营商 / 贷 推广费（`QbOperatorSettlement`，同 Q48d 获客费用的扣除） |

- **每日核对**：平台费 Kudos 科目按发起方的余额 = 各发起方 `FEE_CREDIT` 钱包的余额，也等于各笔赠送剩余的合计。
- **月报** `qb.admin.monthly` 加四类：`FEE_CREDIT_GRANTED`、`FEE_CREDIT_USED`、`FEE_CREDIT_VOIDED`、`FEE_CREDIT_RECOVERED`（扣回），并加一列平台费 Kudos 的余额（`AdminFinanceIT` 逐行）。
- **分录导出**（Q9d）按发起方列出平台费 Kudos 的行。
- **税**：平台费 Kudos 是系统内的记账；报税按真实的银行进账，与它无关（需求方 2026-11-05）。

### 3.4 从运营商的分成中扣回

- 每月结算（`OperatorSettlements`）时，按发放时冻结的运营商，算出该运营商当月的赠送成本，从应得的分成中扣除；扣不完的结转下月，结算单写明"推广费（平台费 Kudos）"一行（同 Q48d 的获客费用）。
- **扣什么**（§7 第 1 条）：
  - **扣用掉的**（建议）：当月被用来付费的部分。到期作废、没人用的不扣，运营商只为真正发生的消费付钱；
  - 或者**扣送出的**：当月发放的全部，到期作废的部分在作废当月退回。
- 平台运营商与 Shopify 运营商同样扣除（结算为"内部结算"，Q92 §10-19）。

### 3.5 企业实名认证（以邮件域名判断）

| 项 | 做法 |
|---|---|
| 提交 | 发起方在商户中心"企业认证"一节提交：公司的正式名称与公司的域名（缺省取主页"网站"的域名）。账户的邮箱已是该域名的，直接进入审核；否则向该域名下的一个地址（如 `info@<域名>`，由发起方填写）发一次性确认链接，点开即证明能收这个域名的邮件 |
| 不接受 | 公共邮箱的域名（gmail.com、qq.com、163.com、outlook.com 等，清单在代码中，可以补充） |
| 审核 | 审批对象 `qb.sponsor-verification`（内容哈希绑定名称与域名），由所属运营商的另一位成员审核：确认这个域名确实属于这家公司（官网、公司名称一致），驳回附理由 |
| 结果 | 通过即在入驻行上记 `companyVerifiedAt` 与域名；**公开主页显示"已实名认证"**（与域名一起）；触发认证补发（D-Q105-6）；成为 Q90 的平台事实"企业已实名"（附录 B 新增） |
| 唯一 | 同一域名只能认证一个发起方（唯一约束），防止一家公司开多个账号重复领取 |
| 变更 | 域名或公司名称改变须重新认证；运营商可以撤销认证（理由必填），撤销不收回已发的额度 |

### 3.6 按发起方追加

- **申请**：运营商成员在运营商后台的发起方页"追加平台费 Kudos"：金额（正整数）、理由（必填）、可选的有效期，记为 `QbFeeCreditRequest`。
- **批准**：审批对象 `qb.fee-credit-request`，由运营商的另一位成员批准（四眼）；批准后以 `QB_FEE_CREDIT_GRANT`（来源 `MANUAL`）发放，驳回附理由。总部的财务也可以为任何发起方申请。
- **可见**：发起方在钱包页看到每一笔的来源、金额与到期（看不到理由）；总部的赠送列表按运营商、发起方、来源汇总。

### 3.7 受控参数（`ControlledParams`，四眼）

| 参数 | 缺省 | 说明 |
|---|---|---|
| `qb.fee-credit.grant.enabled` | false | 开户赠送的开关（活动的开始、结束） |
| `qb.fee-credit.grant.basic` | 1000 | 未认证的金额 |
| `qb.fee-credit.grant.certified` | 10000 | 企业实名认证后的金额 |
| `qb.fee-credit.valid-days` | 90 | 每笔赠送的有效期（天） |
| `qb.ai.fee.markup` | 1.5 | AI 费相对大模型收费的倍数（§2.1） |
| `qb.ai.fee.usd-jpy` | 150 | AI 费的美元对日元汇率 |

### 3.8 界面

- **发起方后台**：
  - 钱包页单独一块"平台费 Kudos（赠送）"，写明"只能用于支付平台费用，不能发奖"，列出每一笔的来源、金额、到期与使用，快到期的提醒；
  - 概况加一张卡；账单与收据写明"其中以平台费 Kudos 支付 X"；
  - 商户中心"企业认证"一节。
- **公开主页**：已认证的显示"已实名认证"与域名。
- **运营商后台**：发起方页的"确认资料完整并发放赠送"、"追加平台费 Kudos"、企业认证的审核；结算单的推广费一行。
- **总部后台**：赠送列表与合计；受控参数页照常出现新参数。

## 4. 测试

- `FeeCreditRulesTest`（纯 Java）：支付顺序（先赠送额度、最早到期的先用，再现金或应收，一笔两部分）、开户与补发的金额、到期、扣回的金额。
- `FeeCreditIT`：
  - 开关关着不发；主管确认才发；未认证 1,000，之后认证补 9,000；重复确认不多发；封禁的不发；
  - 付费先用赠送额度、最早到期的先用；到期作废并记账；
  - 赠送额度不能换学分、不能发奖（学分钱包不变）；
  - 每日核对与月报的新项；
  - 运营商结算：赠送支付的部分不进分成基数；赠送成本从分成中扣回，扣不完的结转；
  - 追加：四眼；注销时作废并记账。
  - AI 费：按 `costUsd` × 150% × 汇率记费、先用平台费 Kudos、预付余额不足时请求被拒、没有尝试运行过的取消不计费。
- `SponsorVerificationIT`：公共邮箱拒绝、域名邮箱的确认链接、审核、同一域名只认证一个、公开主页的标记、撤销。
- 挑战赠送随 Q90 T1a 的挑战发布一起测试。
- 前端：钱包的新卡、账单的两部分、企业认证、运营商后台的确认与追加、axe；e2e：发起方入驻通过 → 主管确认 → 收到 1,000 → 企业认证通过 → 补到 10,000 → 一笔费用由平台费 Kudos 支付。

## 7. 已定与缺省（需求方 2026-11-05：其他都已讨论清楚）

1. **扣回**：从运营商的分成中扣**用掉的**赠送额度，首次上线即开始（到期作废、没人用的不扣）。
2. **有效期**：缺省 90 天（受控参数，可改）。
3. **审核员主管**：运营商的负责人（Q48 的"负责人"）持有确认的权限；需要另设角色时再加。
4. **追加**：平台不设上限。
5. **AI 费**：大模型收费的 150%（§2.1）；其他费用由运营商定价。
6. **税**：不涉及（系统内记账；报税按真实的银行进账）。
