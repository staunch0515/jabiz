# Q85 科技树的画面：商户看客户点亮了什么，答题者看自己走到哪里（计划，2026-11-02，待需求方确认 §9）

`04-product-direction.md` §6.3"完整的科技树"的第二步（第一步是 Q76 的前置条件，已合入）。需求方 2026-11-02 的要求：
（1）商户后台要一个**图形的、直观的**页面，看到哪些客户已经点亮了哪些节点、哪些还没有；（2）商户的科技树也要给答题者看，答题者能看到**自己的能力到了什么位置**。
编号 Q85 是建议（Q83 完播奖励、Q84 付费解锁已占用），确认时可改。**这只是计划**：确认 §9 后开发，一个 PR，工作分支 `1.3/quizbuks-85-tech-tree`。

## 0. 为什么

- Q76 已经把"树"建好了：发布是节点，前置条件是边（有向无环，同一商户之内，至多 5 条前置、深度 20）。现在它只以**列表**出现：
  商户主页按层分组（`share/levels.ts`），发布页写"先完成：X"。商户在后台看不到整棵树，更看不到客户在树上的位置；答题者看到的是分层的清单，不是地图。
- 04 §8.6 定的四态（锁定 → 可解锁 → 挑战中 → 已点亮）与 §6.3 的"DAG 可视化"，只要**读**已有的数据就能画出来：会话（`QbAttempt`）决定每个人在每个节点上的状态，不需要新的表与流程。
- 商户要的"哪些客户点亮了、哪些没有"正是 S5（广告不乱投）与 S4（售后延伸）的运营视图：看完根节点却没往下走的人，是下一轮推广（通告、推荐）的对象。
- 不在这一步：消耗 Kudos 解锁（动钱）、勋章、跨商户的领域树、商户自己的认证——照 04 §6.3 与 Q69 §7 仍是以后；每条边的语义不变，答题路径一条语句也不加。

## 1. 现状

- **数据**：`qb_publication_prerequisite`（发布、前置发布、要求 `PASSED` / `ANSWERED`，发布方那一对）；`QbAttempt`（答题者、发布、状态、`passed`）；
  满足的唯一定义在 `play.PrerequisiteCheck`（已完成的会话；`PASSED` 另要求 `passed`），模板 `qb.app.publication` 与 `qb.system.audience-count` 各写了一遍同一段 SQL。
- **商户看答题者**：只有资料显示名与 `userKey`（`md5(商户:用户)`，Q9b），不给邮箱与用户编号；交易页可按 `userKey` 筛选一个人的奖励。分析页按发布给合格人数、漏斗与每题正确率（不足 `qb.stats.min-group` 人不显示）。
- **答题者看商户**：公开的商户主页（`/s/<handle>`，`qb.public.sponsor-page-publications`，公开模板不知道读者）按层分组列出进行中的发布；发布页按本人给出 `prerequisites[].met`；历史页列自己的会话。
- **画图**：两个 SPA 只有 Recharts 的统计图与内联 SVG 插画（`qb/Illustrations.tsx`）；没有图布局库，扩展与 SPA 不自带依赖（CLAUDE.md 第 4 节"前端"）。

## 2. 决定（草案）

| # | 决定 |
|---|---|
| D-Q85-1 | **树不另建模**：节点 = 商户**提交过**的发布（不含草稿），边 = Q76 的前置条件。没有前置也不被谁前置的发布是孤立的根，照样画（商户可用开关隐藏孤立节点与已结束的节点）。一个商户一棵树（森林）；树只属于一个商户，跨商户仍是以后。 |
| D-Q85-2 | **一个人在一个节点上的状态**（纯 Java `tree.TreeStates`，与 `PrerequisiteCheck` 共用"满足"的定义，一条 SQL 模板照 `qb.app.publication` 的写法）：`LIT`（已完成且 `passed`）、`ANSWERED`（已完成未合格；对要求 `ANSWERED` 的下游算满足，画成半亮）、`IN_PROGRESS`（会话进行中）、`UNLOCKED`（前置都满足、发布进行中、还没开始）、`LOCKED`（有前置未满足）、`CLOSED`（发布不在进行中又没答过：已结束、暂停、未开始；灰色）。优先级从左到右。 |
| D-Q85-3 | **商户后台新页"科技树"**（`/tree`，菜单"内容"组，图标 `Network`）：整棵树的 SVG，节点上写发布名与三个数：**已点亮 / 答过未合格 / 可解锁未开始**的人数；点一个节点，右侧（手机上为下方抽屉）列出该节点的客户，按状态分组：已点亮、答过未合格、可解锁未开始、锁定（锁定的只列在本商户**别的**节点上有已完成会话的人，不是全平台的人）。每个客户显示资料显示名与 `userKey`（同交易页），一键进交易页按此人筛选、进对话（Q82，有对话时）。 |
| D-Q85-4 | **按一个客户点亮**：页顶"查看一位客户"（输入 `userKey` 或从节点列表点一个人），整棵树按这个人的状态上色（同答题者看到的），并写"下一步：…"（可解锁未开始的节点）。只按 `userKey`，不按姓名搜索（显示名不唯一且是本人填的）。 |
| D-Q85-5 | **人数的下限不设**：节点上的人数与名单与交易页一样是逐人的数据（商户本来就看得到谁合格、谁领了奖），不受 `qb.stats.min-group` 约束；但**不显示**答题者的分数、答案与时间以外的任何资料字段（只有显示名、`userKey`、状态、最近完成时间）。锁定名单只告诉商户"他还没到这里"，不告诉差哪一条（商户自己看树就知道）。 |
| D-Q85-6 | **答题者：商户主页上的树**（`/s/<handle>` 加一个"树 / 列表"切换，登录后缺省树）：同一个 SVG 组件，按本人的状态上色，已点亮的节点打勾、可解锁的高亮并标"下一步"、锁定的灰并写"先完成：X"；点节点进发布页（锁定的也能进，发布页已有"先完成这些答卷"）。页顶一句话："你已点亮 3 / 7，下一步：…"。未登录仍是现在的分层列表（公开模板不知道读者）。 |
| D-Q85-7 | **答题者的"我的位置"入口**：结果页在"联系商户"旁加"看看下一步"（有前置关系时才显示，链到该商户主页的树并定位到刚答的节点）；历史页按商户分组时加"在 X 的树上：已点亮 n"。不做跨商户的"我的能力树"（04 §6.3 的领域树，以后）。 |
| D-Q85-8 | **节点包含已结束的发布**：答题者点亮过的节点在发布结束后仍留在树上（否则树会掉节点、进度倒退）；商户侧缺省显示全部提交过的发布，可隐藏已结束的；答题者侧显示进行中的 + 本人答过的。 |
| D-Q85-9 | **画法**：共用组件 `qb/TechTree.tsx`（两个 SPA 各一份、完全相同，`diff -r`），内联 SVG，不引入 d3 / dagre：层由 `levels.ts` 的算法给出（推广到任意节点集合），层内按名字排，边画成贝塞尔曲线，宽屏按层从左到右、手机按层从上到下，可缩放与拖动（指针事件），节点 ≤ 60 时一屏画完，更多时折叠到层。颜色只用主题 token（`--primary` 点亮、`--muted` 锁定、`--chart-2` 可解锁、`--destructive` 不用），亮暗两种外观过 axe；**同一数据另有列表形态**（现在的分层列表）供读屏与小屏，`aria-label` 写清节点名与状态。 |
| D-Q85-10 | **只读、不加语句**：三个新模板、没有新表、没有新流程、没有迁移；答题路径与 `AttemptStatementBudgetIT` 不变。商户的模板经 `sponsor:QbPublication` 与 `default:QbAttempt`（同交易页的做法）、`default:QbProfile`（显示名）；答题者的模板经 `taker:QbAttempt` 与公开的卡片与前置视图。 |
| D-Q85-11 | **缓存与性能**：商户的树与人数每次打开读一次（`cacheSeconds: 30`），名单按节点分页（每页 50）；`qb_attempt` 已有 `(user_id, publication_id)` 唯一索引与 `publication_id` 索引，一个商户的节点数在几十以内，名单的 SQL 是按发布的会话加前置的 `NOT EXISTS`，不需要新索引。 |
| D-Q85-12 | **隐私文案**：商户看客户在树上的位置，与交易页看"谁合格、谁领了奖"同一范围，隐私政策不改；答题者侧不显示别人的任何数据。 |

## 3. 后端（`backend/quizbuks`，包 `tree`）

### 3.1 模板

| 模板 | 给谁 | 内容 |
|---|---|---|
| `qb.sponsor.tree` | 商户（`qb.publication.write`） | 节点：本商户提交过的发布（编号、名字、状态、开始 / 结束、种类）；每个节点的 `prerequisites` JSON（同公开模板）；三个人数 `lit` / `answered` / `unlocked`（按 D-Q85-2 算：`unlocked` = 在本商户别的节点上有已完成会话、前置都满足、本发布进行中、没开始的人数）。参数 `includeEnded`、`includeIsolated`。 |
| `qb.sponsor.tree-people` | 商户 | 参数 `publicationId`、`state`（`LIT` / `ANSWERED` / `UNLOCKED` / `LOCKED`）、分页；列：`userKey`（`md5(商户:用户)`，同交易页）、`displayName`（`QbProfile`）、`state`、`finishedAt`、`hasConversation`（Q82）。只列本商户的客户（在本商户任一提交过的发布上有已完成会话的人）。 |
| `qb.sponsor.tree-person` | 商户 | 参数 `userKey`：这个人在每个节点上的状态（D-Q85-4）。`userKey` 不是用户编号，模板里以 `md5(商户 || ':' || user_id) = :userKey` 连，同交易页。 |
| `qb.app.sponsor-tree` | 答题者（`qb.me`） | 参数 `handle`：该商户进行中的公开发布 ∪ 本人答过的该商户的发布，每个节点本人的状态与 `prerequisites`；`nextIds`（可解锁未开始的）。 |

"状态"的那段 SQL 写一次（模板之间以 `LATERAL` 子查询的同一写法复制，像 Q76 的三处），`TreeStates`（纯 Java）给出同样的规则，`TreeStatesIT` 对全部会话断言两边一致（照 `PrerequisiteIT` 的 `audience-count` 对账）。

### 3.2 不改的

实体、流程、迁移、权限（商户用已有的 `qb.publication.write`，答题者用 `qb.me`）、审核、分析、推荐、奖励。`OperatorScopes` 不涉及（没有新实体）。
后台扩展不加页（运营商看树的需要没有提出；要看时经已有的发布页与会话页）。

## 4. 前端

- **共用**（`qb/`，两份相同）：`TechTree.tsx`（SVG，D-Q85-9）、`treeLayout.ts`（由 `share/levels.ts` 推广：输入节点与边，输出层与坐标；`levels.ts` 改为调用它）、`treeStates.ts`（状态的文案键与颜色 token）、`qb/messages.ts` 的 `tree.*` 三语文案。
- **商户后台**（`sponsor/src/tree/`）：`TreePage.tsx`（`/tree`，菜单"内容"组第三项）：树 + 右侧 / 抽屉 `TreePeople.tsx`（按状态分组的名单，`DataTable` 的卡片形态，Q80）+ 页顶 `TreePerson.tsx`（按一位客户点亮）；开关"显示已结束 / 显示孤立节点"；没有任何前置关系时显示说明与"去发布向导设置前置条件"的链接。`PublicationsPage` 的发布行加"在树上查看"。
- **App**：`share/SponsorPage.tsx` 加树 / 列表切换（登录后缺省树；未登录只有列表）；`ResultPage.tsx`"看看下一步"；`HistoryPage.tsx` 的每个商户一行进度。
- **a11y**：树有 `role="img"` 的总述与隐藏的列表形态；节点是 `<a>`（键盘可到）；两种外观过 `expectAccessible`。

## 8. 风险

| 等级 | 风险 | 对策 |
|---|---|---|
| 中 | 手写 SVG 布局在大树上难看（交叉的边、太宽） | 层内按前置的重心排序减少交叉；超过 60 个节点按层折叠；孤立与已结束的缺省可隐藏；真有上百个发布的商户以后再上布局库（平台先加） |
| 中 | 商户把"锁定名单"当作拉人清单群发 | 名单只给显示名与 `userKey`，联系仍只经通告（有节流）与对话（只有答题者能开）；不提供导出 |
| 低 | 状态规则在 SQL 与 Java 两处漂移 | `TreeStatesIT` 对账，同 Q76 |
| 低 | 商户主页的公开缓存与登录后的树混用 | 登录后另读 `qb.app.sponsor-tree`（带本人），公开模板不改 |

## 9. 需要需求方确认的

1. D-Q85-1：节点是商户提交过的全部发布（孤立的、已结束的也画，可隐藏），还是只画有前置关系的那些？
2. D-Q85-2：六态的定义，特别是"答过未合格"画成半亮、"已结束没答过"画成灰。
3. D-Q85-3 / D-Q85-5：商户看每个节点的客户名单（显示名 + `userKey`，含"锁定"的本商户客户），不设人数下限、不导出。
4. D-Q85-4：按 `userKey` 查看一位客户的树（不按姓名搜）。
5. D-Q85-6 / D-Q85-7：答题者的树放在商户主页（登录后缺省）；入口在结果页与历史页；**不做**跨商户的个人能力树（以后）。
6. D-Q85-9：手写 SVG，不引入布局库；节点超过 60 个按层折叠。
7. 编号 Q85，一个 PR，约 6 天，没有迁移。
