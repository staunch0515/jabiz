# Q36 内容包工具（计划，2026-10-26 确认；实现中）

需求方（2026-10-26）：在测试环境中不断积累可以在正式产品中使用的数据（真实的商户、真实的测验与发布），
上线时把这些"干净的测试数据"放进正式的数据库；需求方自己作为第一个商户，始终有一个长期的问卷，让新注册的答题者至少能看到一个。

**整库复制不可行**（2026-10-26 向需求方说明，需求方同意）：只追加表的封存链以 `JABIZ_INTEGRITY_KEY` 签名、密封的秘密以 `JABIZ_SEAL_KEY`
加密、二次验证以 `JABIZ_MFA_KEY` 加密，正式环境必须轮换这些密钥（`launch-checklist.md`"安全"），旧数据随之无法验证或解密；
测试中的作答、账本、审计、同意记录会混进正式数据；Stripe 测试模式的编号在正式模式中不存在。
所以只搬**内容**（测验与发布的设置），经与商户后台相同的接口写入，每条规则照常检查。

1.2 已冻结只修 bug；这是需求方要求的上线准备，只加工具（`tools/quizbuks/content/`）、e2e 与文档，不改后端、不加迁移。

## 1. 决定（已确认）

| # | 决定 |
|---|---|
| D-Q36-1 | **内容包**：一个目录，`content.json`（格式 `quizbuks.content` 第 1 版：商户的显示资料、发布列表）与 `quizzes/*.quizbuks.json`（每个测验一个，即商户后台"导出测验"的同一格式 `quizbuks.quiz` 第 1 版，Q16，含图片、PDF、音频的字节）。发布只记设置与**天数**（`durationDays`，1–366），不记日期、状态、编号、码池或任何秘密 |
| D-Q36-2 | **工具** `tools/quizbuks/content/qbcontent.mjs`（Node 22，无第三方依赖）：`export`（商户的测验与发布 → 内容包）、`apply`（内容包 → 商户的账号）、`renew`（快结束的发布接上新的一期）、`takers`（只限测试系统：虚构的答题者作答）。只经公开的 API（登录、流程、模板、数据视图、文件），**不连数据库**；以商户本人的账号登录，密码只从环境变量 `QB_PASSWORD` 读（不作参数，免得留在命令历史）；`--dry-run` 只说会做什么 |
| D-Q36-3 | **只写一次**：`apply` 按标题找测验（已有即不再导入，导入经 `QB_QUIZ_IMPORT_CHECK` / `QB_QUIZ_IMPORT`，与后台相同），按名称找发布（已有未结束的即跳过），所以可以反复运行。商户须已通过入驻审核；发布照常提交审核（D-Q4-4），保存时有问题就留作草稿并列出字段与原因 |
| D-Q36-4 | **不替真人同意条款**：服务器要求同意新版条款时（`QB_CONSENT_REQUIRED` / `QB_TERMS_OUTDATED`）工具停下，请本人在后台同意后再运行 |
| D-Q36-5 | **长期问卷**：发布最长 366 天（`PublishingLimits.MAX_RUNNING`）。`renew --renew-days N`：结束前 N 天内的发布，以同样的设置从上一期的结束时刻接上新的一期（已有排好的下一期就不再建）。每年运行一次即可；也可按月运行 |
| D-Q36-6 | **问卷的奖励**：至少一档有奖励（`TIER_NO_REWARD`），问卷只奖励完整的回答（D-Q12-4）。示范包用 Kudos 每份 10、上限 300 人（预算 3 000 Kudos，需求方的商户钱包要有余额）；也可改为到店兑换或电子奖品，见 `tools/quizbuks/content/README.md` |
| D-Q36-7 | **虚构的答题者只在测试系统**：`takers` 先读服务器自报的系统名（平台 16zd，`jabiz.web.environment`），是 `production` 或没有说明就拒绝；注册经 Mailpit 验证邮箱、以测试同意条款、随机作答内容包中的发布 |
| D-Q36-8 | **内容包放在需求方自己的私有仓库**（不进 jabiz 仓库：内容是业务资料，测验文件含图片）。jabiz 只有工具与一个示范包（`tools/quizbuks/content/example/`：一年期的欢迎问卷） |

## 2. 上线时的做法

1. 测试系统中，需求方的商户账号（与管理员不同的邮箱）建测验与发布，反复修改到满意。
2. `export` 到私有仓库中的内容包目录，提交。
3. 正式系统上线后，需求方以同一邮箱自助注册商户、通过入驻审核、充值。
4. `apply` 内容包；管理员审核发布。
5. 每年（或每月）运行 `renew`。

## 3. 测试

- `tools/quizbuks/content/lib.test.mjs`（`node --test`，CI 的 QuizBuks 前端作业）：测验文件的组装、发布的天数、内容包的检查、保存输入、续期的判断、示范包有效。
- e2e `quizbuks-web/e2e/tests/content-tool.spec.ts`（对打包的应用）：商户 A 导出 → 商户 B 应用（测验导入、发布提交）→ 再次应用跳过 → 续期接在上一期之后 → 虚构的答题者作答；示范包应用后是 366 天的发布。
