# Q20 答题后始终可回看完整题目与选项（A-3）

需求方 2026-10-24 确认："答题后始终可看完整题目和选项，这个做。排在 Q18 后面。" 取代 `QP-pages.md` 的 Q-2 缺省（刚完成时用 `sessionStorage`，之后只显示分数与逐题对错）。

## 做法

| 部分 | 内容 |
|---|---|
| 流程 `QB_ATTEMPT_RESULT` | `play.AttemptResults`（权限 `qb.me`，输入 `attemptId`）：经答题人视图读本人会话（别人的或不存在即 404）、会话所用的冻结版本与卡片。**已完成**（`SUBMITTED` / `EXPIRED`）时返回题目（与 `QB_ATTEMPT_START` 同一个视图：按会话的打乱顺序、选项按位置 1..k 编号、不含正误）与存储的 `result`（按同样的位置给出所选与正确选项、分值与得分）；进行中只返回状态与截止（页面据此回到答题或等待超时结束），不返回题目。另返回 `kind`、分数、及格线（问卷为 null）、是否通过、奖励与状态 |
| 不变的约束 | 正确答案仍只在完成后出现（设计第 9 节）；`optionOrder` 仍不离开服务端；`Scoring.fromJson` 解析存储的结果 |
| App 结果页 | 一律读 `QB_ATTEMPT_RESULT`（历史、其他设备、关闭标签页后都一样显示题目文字、本人所选与正确选项）；`sessionStorage` 只剩提交输出中"奖励待付"的服务端提示（本标签页）；去掉"题目内容只在刚完成时显示"的文案。`qb/play.ts` 的 `readAttemptResult` 复制到商家后台的 `qb/` |
| 没有迁移 | 版本快照与 `result` 已有全部数据 |

风险：发布进行中时答题人从历史能再看到正确答案——与刚完成时看到的相同，每人每发布只有一次会话，没有新的泄露。

## 测试

- `AttemptResultIT`：已完成的会话给出按会话顺序的题目文字（每个位置的文字与版本对照）、所选与正确位置、分数与及格线；进行中只有状态；他人的与不存在的 404；超时由系统结束的会话给出已保存的答案；问卷给出所选、没有正确选项、及格线为 null。
- App Vitest（`Play.test.tsx`）：从历史打开的结果显示题目与答案（不靠标签页）、超时等待、仍在时限内回到答题、不存在的会话；刚完成与问卷的结果页改经同一流程。
- e2e `play.spec.ts`：从历史打开结果页断言题目文字与答案。
