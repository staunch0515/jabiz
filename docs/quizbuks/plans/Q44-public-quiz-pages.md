# Q44 公开问卷页面（2026-10-27，计划，待确认）

需求方（2026-10-27）：不登录也能浏览正在进行的问卷，搜索引擎与社交网络能收录、能显示预览；看中了再注册或登录答题。
目的是获客：让问卷本身成为入口，而不是只有注册页。

编号说明：Q42、Q43 只在分支名中用过（决策改号、staging 重置的文档改动），没有计划文件，本计划从 Q44 起。

## 1. 现状（不必重做的部分）

- 分享链接 `/taker/p/<id>`（Q15）已经对匿名访客显示一份正在进行的问卷：名称、商户公司名、题数、时限、最高奖励、截止时间；
  "只填邮箱即可开始"（平台 16zb）与"用密码登录"两条路。数据来自公开模板 `qb.public.publication`，经公开视图
  `urn:jabiz:dataset:public:QbPublicationCard`（固定范围 `status = LIVE`、`audience = PUBLIC`，即正在进行、不限邀请的发布）。
- 平台的公开访问（设计 15、决策 D17）：匿名只经公开模板读公开视图的白名单字段，不写操作记录，按地址限流，带缓存头。`jabiz.public.enabled` 在 QuizBuks 缺省开启。
- 缺的是：**列表**（现在只能经分享链接看单个问卷）、**封面**（卡片的 `cover` 是文本，不是文件字段，公开文件接口发不出去）、
  **服务器给出的标题与预览信息**（App 是单页应用，`index.html` 是静态的，社交网络的预览抓取不执行脚本，看到的只有 "QuizBuks"）。

## 2. 拆分

| 部分 | 内容 | 线 | 迁移 | 估计 |
|---|---|---|---|---|
| **Q44a** | 公开列表 + 详情页完善 + 各处入口 | 1.2/quizbuks | 无 | 2 天 |
| **平台 16zl** | 单页应用的公开路由由服务器填写标题与 Open Graph 信息；按公开模板生成 sitemap | 1.2/platform | 无 | 2 天 |
| **Q44b** | 用 16zl 给 `/taker/explore` 与 `/taker/p/<id>` 加预览信息与 sitemap；根目录 `robots.txt` | 1.2/quizbuks | 无 | 0.5 天 |
| **Q44c** | 封面公开：卡片的 `cover` 改为文件字段并列入公开白名单；列表、详情、预览图用封面 | **1.3**/quizbuks | **有** | 1 天 |

封面需要把 `qb_publication_card.cover` 从文本列改为 `uuid` 列（文件字段的要求，设计 14），这是迁移；
按规则"不是最新的线不增加迁移"，1.2 不能做，所以封面放在 1.3（D-Q44-1）。1.2 上的列表与详情先不显示封面，用问卷类型的图形占位（与没有封面的卡片现在的样子相同）。

## 3. 决定（待确认）

| # | 决定 |
|---|---|
| D-Q44-1 | **按上表拆分**：Q44a、16zl、Q44b 在 1.2（都不需要迁移）；Q44c（封面）在 1.3，随 1.3 上线。备选：全部放到 1.3 一起做，1.2 不动 |
| D-Q44-2 | **公开列表的范围与 App 的首页一致，但只用公开的信息**：新公开模板 `qb.public.feed`，读公开卡片视图（正在进行、不限邀请）与公开商户视图（已审核的公司名）；按访客选的国家筛地区（与首页相同的地区规则；不选国家时只列面向全球的）、按开始时间降序或最高奖励排序、按名称搜索、分页（每页至多 20 条）。预算、名额是否用完不在公开信息里，不判断：用完的发布会被每分钟的任务结束而离开列表，开始答题时 `QB_ATTEMPT_START` 照旧检查。为此把卡片的 `regions` 加入公开白名单（地区本来就会出现在列表的筛选结果里，不是秘密） |
| D-Q44-3 | **页面**（答题人 App 中，未登录可看）：`/taker/explore` 列表（国家选择缺省按浏览器语言：日语→日本、中文→不选（全球）、其他→不选，记在本机；卡片显示名称、商户、类型、最高奖励与支付方式、题数、截止时间）；`/taker/p/<id>` 详情沿用 Q15 的页面，补上支付方式与兑换说明（模板已返回，页面未显示）。登录后访问 `/taker/explore` 转到首页（首页本来就是登录后的列表）。不显示参与人数（计数不公开） |
| D-Q44-4 | **入口**：App 的介绍页与登录页加"先看看有哪些问卷"；招商网站首页与"答题人"页的按钮加"浏览问卷"（新开 `/taker/explore`，与"开始答题"同样在电脑上开手机大小的窗口、已安装 App 时交给 App，Q41）；分享链接的详情页加"看看其他问卷"。三种语言的文案 |
| D-Q44-5 | **服务器给出的预览信息（平台 16zl，另写平台计划与决策）**：单页应用可声明"公开路由"：路径模式 → 公开模板 → 把结果的列映射到 `<title>`、`description`、`og:title`、`og:description`、`og:image`、`og:url`、`canonical`。服务器在返回该路由的 `index.html` 时把这些值（转义后）写进 `<head>`；模板没有结果（问卷已结束）时返回原样的 `index.html` 并加 `noindex`。不渲染页面内容（页面仍由前端渲染，搜索引擎会执行脚本），只解决标题与社交预览。同一机制按公开模板生成 `sitemap.xml`（列出正在进行的公开问卷）。不引入模板引擎（只在 `<head>` 的固定位置插入几行），缓存随模板的 `cacheSeconds` |
| D-Q44-6 | **Q44b 的设置**：`/taker/p/<id>`（标题 = 问卷名 + 商户，描述 = 最高奖励、题数、截止时间，按请求语言）与 `/taker/explore`（固定标题与描述，三种语言）；预览图在 1.2 上用一张品牌图（新做的 1200×630 图片），1.3 起用封面（Q44c）。`/robots.txt`：允许 `/biz/`、`/taker/explore`、`/taker/p/`，其他路径不收录；`sitemap.xml` 包括招商网站的页面与正在进行的公开问卷 |
| D-Q44-7 | **不做的**：不公开参与人数、商户头像、题目内容（只有题数）；不做匿名答题（答题仍要登录，奖励要记到账户）；不做按商户的公开主页（以后可以） |

## 4. 安全与隐私

- 只读、匿名、不写记录：全部经平台的公开模板与公开视图，字段白名单在启动时检查；新增的白名单字段只有 `regions`。
- 邀请制的发布（Q25）、未开始、暂停、已结束的发布一律不出现（固定范围）；商户未通过审核时不显示公司名（公开商户视图的范围）。
- 抓取：公开接口已有按地址的限流与缓存头；列表每页至多 20 条，模板时限 2 秒。
- 16zl 写进 `<head>` 的值一律 HTML 转义，长度截断；只来自公开模板（同样只有白名单字段），不读请求参数以外的输入。

## 6. 风险

- 搜索引擎对单页应用的收录比静态页面慢，列表页的内容靠脚本渲染；16zl 只保证标题、描述与预览。需要更好的收录时，以后可以把列表也在服务器端渲染（另议）。
- 1.2 上没有封面，列表的吸引力较弱；Q44c 随 1.3 补上。
- 问卷少的时候公开列表会显得空：上线初期可以由官方账号发几份长期的问卷（运营上的准备，不在本计划中）。
