# Q44 公开问卷页面（2026-10-27 记录，**待开发**，计划的其余决定待确认）

需求方（2026-10-27）：不登录也能浏览正在进行的问卷，搜索引擎与社交网络能收录、能显示预览；看中了再注册或登录答题。
目的是获客：让问卷本身成为入口，而不是只有注册页。

**状态**：需求方 2026-10-27 决定**全部在线 1.3 上做**（原计划在 1.2 先做无封面的版本、封面随 1.3，见已作废的分支 `1.2/quizbuks-44-public-pages`），
并要求先把这件事完整记录为待开发内容：当时正急着做上线演练，没有开工。开发前先确认第 3 节其余的决定（D-Q44-2 起），按惯例经确认后实施。
平台部分是线 1.3 的阶段 **17f**（`1.3/platform` 的 ROADMAP），先于 Q44b。

编号说明：Q42、Q43 只在 1.2 的分支名中用过（`1.2/quizbuks-42-d61` 决策改号、`1.2/quizbuks-43-staging-reset` staging 重置的文档），没有计划文件；本计划用 Q44。

## 1. 现状（不必重做的部分）

- 分享链接 `/taker/p/<id>`（Q15）已经对匿名访客显示一份正在进行的问卷：名称、商户公司名、题数、时限、最高奖励、截止时间；
  "只填邮箱即可开始"（平台 16zb）与"用密码登录"两条路。数据来自公开模板 `qb.public.publication`（`queries/qb/public/publication.sql`），经公开视图
  `urn:jabiz:dataset:public:QbPublicationCard`（`PublishingConfig.java`，固定范围 `status = LIVE`、`audience = PUBLIC`，即正在进行、不限邀请的发布）。
  页面是 `quizbuks-web/app/src/share/SharePage.tsx`；模板已返回支付方式与兑换说明（`rewardMethod`、`redeemDescription`、`digitalDelivery`、`digitalDescription`），页面没有显示。
- 平台的公开访问（设计 15、决策 D17）：匿名只经公开模板读公开视图的白名单字段，不写操作记录，按地址限流，带缓存头。`jabiz.public.enabled` 在 QuizBuks 缺省开启。
  公开商户视图 `urn:jabiz:dataset:public:QbSponsor`（`AccountsConfig.java`）只有已审核商户的 `userId` 与 `company`。
- 登录后的首页列表是模板 `qb.app.feed`（`queries/qb/app/feed.sql`）：正在进行、不限邀请、在时间窗内、地区与答题人的国家相交（没有国家时只列 `GLOBAL`）、预算与名额未用完、
  用 Kudos 奖励时商户钱包够付、排除已答过的与自己的、按名称搜索；开始答题时 `QB_ATTEMPT_START` 再检查一遍（`play.AttemptRules`）。
- 缺的是：
  1. **列表**：现在只能经分享链接看单个问卷。
  2. **封面**：卡片 `QbPublicationCard.cover` 是文本列（`text(36)`），不是文件字段，公开文件接口 `/api/public/files` 发不出去（设计 14、15 §4：文件字段要求 `uuid` 列并在公开白名单中）。
  3. **服务器给出的标题与预览信息**：App 是单页应用，`SpaFallbackFilter` 返回静态的 `index.html`（只有 `<title>QuizBuks</title>`），社交网络的预览抓取不执行脚本。
     招商网站 `/biz/` 是构建时生成的静态页面，已有 Open Graph 与 `sitemap.xml`（Q31），但不包含问卷。

| D-Q44-2 | （待确认）**公开列表的范围与首页一致，但只用公开的信息**：新公开模板 `qb.public.feed`，读公开卡片视图（正在进行、不限邀请）与公开商户视图（已审核的公司名）；按访客选的国家筛地区（与 `qb.app.feed` 相同的地区规则；不选国家时只列面向全球的）、在时间窗内（`startAt <= 请求时刻 < endAt`）、按开始时间降序或最高奖励排序、按名称搜索、分页（每页至多 20 条）。预算、名额、商户钱包是否够付不在公开信息里，不判断：用完的发布会被每分钟的任务结束（或因资金不足暂停）而离开固定范围，开始答题时 `QB_ATTEMPT_START` 照旧检查。为此把卡片的 `regions` 加入公开白名单（地区不是秘密） |
| D-Q44-3 | （待确认）**页面**（答题人 App 中，未登录可看）：`/taker/explore` 列表（国家选择缺省按浏览器语言：日语→日本，其他→不选即全球；选择记在本机 `localStorage`；卡片显示名称、商户、类型（问答 / 问卷）、最高奖励与支付方式、题数、截止时间）；`/taker/p/<id>` 详情沿用 Q15 的页面，补上支付方式与兑换说明。登录后访问 `/taker/explore` 转到首页（首页就是登录后的列表）。不显示参与人数（计数不公开）。路由加入 App 的公开页面判断（`App.tsx` 的 `isPublic`） |
| D-Q44-4 | （待确认）**入口**：App 的介绍页与登录页加"先看看有哪些问卷"；招商网站首页与"答题人"页的按钮加"浏览问卷"（`/taker/explore`，与"开始答题"一样在电脑上开手机大小的窗口、已安装 App 时交给 App，Q41）；分享链接的详情页加"看看其他问卷"。三种语言的文案 |
| D-Q44-5 | （待确认，平台 17f）**服务器给出的预览信息**：单页应用（`jabiz.web.spa[i]`）可声明"公开路由"：路径模式 → 公开模板 → 把结果的列映射到 `<title>`、`description`、`og:title`、`og:description`、`og:image`、`og:url`、`canonical`。服务器在返回该路由的 `index.html` 时把这些值（HTML 转义、截断长度）写进 `<head>` 的固定位置；模板没有结果（问卷已结束、不存在）时返回原样的 `index.html` 并加 `<meta name="robots" content="noindex">`。不渲染页面内容（页面仍由前端渲染，搜索引擎会执行脚本），只解决标题与社交预览；不引入模板引擎。同一机制按公开模板生成 `sitemap.xml`（有上限、可分页）。缓存随模板的 `cacheSeconds` |

## 4. 安全与隐私

- 只读、匿名、不写记录：全部经平台的公开模板与公开视图，字段白名单在启动时检查；新增的白名单字段只有 `regions` 与（Q44c）`cover`。
- 邀请制（Q25）、未开始、暂停、已结束的发布一律不出现（固定范围）；商户未通过审核时不显示公司名（公开商户视图的范围）。
- 抓取：公开接口已有按地址的限流与缓存头；列表每页至多 20 条，模板时限 2 秒。
- 17f 写进 `<head>` 的值一律转义与截断，只来自公开模板的结果（同样只有白名单字段）；路径参数按模板参数校验，不合格即按"没有结果"处理。
- 封面公开意味着商户上传的封面在发布期间对任何人可见：商户条款中写明（与分享链接已公开名称、奖励同理），Q44c 时一并更新条款草稿的说明。

## 6. 风险

- 搜索引擎对单页应用的收录比静态页面慢，列表内容靠脚本渲染；17f 只保证标题、描述与预览。需要更好的收录时以后再议服务器端渲染列表。
- 问卷少的时候公开列表会显得空：上线初期由官方账号发几份长期的问卷（运营上的准备，不在本计划中）。
- 依赖 1.3 的上线时间：1.2 上线时没有公开列表，只有分享链接。
