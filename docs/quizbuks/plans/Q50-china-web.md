# Q50 中国大陆只用网页与 PWA（2026-10-28 确认）

需求方（2026-10-28，最先落实）：中国大陆的用户只用网站与"安装到主屏幕"的网页 App（PWA）。不上中国的应用商店；iOS 上架时把中国区排除在销售地区之外。
网站在中国大陆可以访问，能注册、答题、收取 Kudos；商家以微信把现金奖励转给用户（平台外付款，平台只记"已发放"）。策略记在 `03-plan.md` 第 6 节。

只在线 1.3。平台的部分是 17m（`1.3/platform` 的 ROADMAP）：登录表单的 `emailLink`、`userNameLabel`，国产浏览器与内置浏览器的安装指引。

## 1. 核对现状（2026-10-28）

- 两个前端的登录页本来就是"名字与密码在上、Google / Facebook / LINE 的图标在最下"，注册页也是邮箱在前；缺的是：名字一栏写作"用户名"（其实邮箱也能登录）、
  答题者入口已开启邮件登录（`QB_APP_EMAIL_LINK`）但登录页上没有。
- 华为、小米、QQ、UC 的浏览器不给出 `beforeinstallprompt`，平台 16zj 因此什么都不提示；微信、QQ 的提示要等答完第一份问卷，且叫人用"Safari 或 Chrome"打开。
- 按钮的排列与安装指引都在平台的积木里，应用改不了：先做平台 17m。

## 2. 决定（2026-10-28 全部同意）

| # | 决定 |
|---|---|
| D-Q50-1 | **名字一栏写作"邮箱"**：三种语言、答题者 App 与商家后台都改（`userNameLabel="email"`）；QuizBuks 的用户都以邮箱注册，服务端照旧也接受用户名 |
| D-Q50-2 | **中文界面的答题者 App**：邮件登录在最上面，密码在"或用密码登录"之下，第三方图标在最后（`emailLink`，语言为 `zh`）。日语与英语照旧 |
| D-Q50-3 | **商家后台不开邮件登录**：商家入口不开 `email-link`（涉及资金，保持密码与可选的二次验证） |
| D-Q50-4 | **内置浏览器从第一次访问起提示**：微信、QQ、LINE 等内置浏览器中，登录类页面与分享页一开始就显示"在浏览器中打开"（修改 D-Q38-1）；关掉照 D-Q38-3 计数。普通浏览器中照旧等答完第一份问卷 |
| D-Q50-5 | **国产浏览器的"添加到桌面"**：账户页与答题后的提示按浏览器给出步骤（平台 17m），识别不了的安卓浏览器显示通用步骤；华为、小米等提示开启"桌面快捷方式"权限 |
| D-Q50-6 | **Q49 规划**：`Q49-mobile-apps.md` §6 写明 App Store 排除中国大陆、不上中国的应用商店 |

## 3. 实现

- `quizbuks-web/app/src/signin.ts`：`mailFirst(语言)`；`App.tsx` 的登录页传 `emailLink={mailFirst(…)}`、`userNameLabel="email"`。
- `quizbuks-web/app/src/install.tsx`：`InAppBrowserNotice`（只在 `in-app` 时显示，同一个键 `taker`），放在登录类页面的外框与分享页的最上面。
- `quizbuks-web/sponsor/src/App.tsx`：`userNameLabel="email"`。

## 4. 测试

- App：`App.test.tsx`（英语照旧、中文时邮件链接在密码之上且图标在最后、"电子邮箱"标签，axe；微信中登录页一开始就有提示、Safari 中没有）；`share.test.tsx`（微信中分享页的提示在标题之前）。
- 商家后台：`App.test.tsx`（"E-mail address"标签，没有邮件登录）。
- e2e：`install.spec.ts`（小米浏览器在账户页的菜单指引与权限提示，中文，axe；微信中打开登录页的提示与中文的邮件登录，axe）；登录辅助改按 `login-user-name` 找名字一栏。
