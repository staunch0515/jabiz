# Q74 店员的交付明细与统计（2026-11-01）

需求方（2026-11-01）："怎么能看到，哪些奖品是某个店员领出呢？""在店员的 App 的账户页面加一个小页面，可以单击打开这个显示二维码和自己经手的明细和统计。"
确认（2026-11-01）：按建议做——店员离开商户后看不到在这家的记录；明细中给店员看领取人的显示名（同领奖台）。

## 1. 现状

- Q39 已在商户后台"奖品领取"页显示经手人：只有店员交付的显示，而且只是"已领取"标记下的一行灰色小字，不容易发现。
- 不能按经手人筛选，也没有按人的统计；店员只在领奖台看到本人当天交付的。

## 2. 决定

| 编号 | 决定 |
|---|---|
| D-Q74-1 | 店员只经自己**当前**的店员关系看到本人在这家商户交付的；离开（或被移除）后看不到（同领奖台，D-Q39-3） |
| D-Q74-2 | 明细给店员看领取人的显示名（同领奖台） |
| D-Q74-3 | 期间按部署时区（`jabiz.fiscal-year-zone`，由分析任务记在 `qb_stats_run.zone`）的日界：今天、近 7 天（含今天）、本月、全部；"现在"取页面按服务端时钟的 `minuteNow()` |
| D-Q74-4 | 商户的统计包括已移除的店员（他们交付过的仍算他们的）；商户本人交付的单列为"本人" |
| D-Q74-5 | 只是读取：领取流程与答题路径不变 |

## 3. 后端（只是模板）

- `qb.app.staff-handled`（`qb.me`）：本人当前所属商户中、本人交付的已领取奖品（`redeemedBy` = 本人），按 `period`（`TODAY` / `WEEK` / `MONTH` / `ALL`）筛选，最新在前，分页计数。
- `qb.app.staff-handled-totals`（`qb.me`）：同一范围的今天、近 7 天、本月件数与价值，和时区。
- `qb.sponsor.redemption-handlers`（`qb.publication.write`）：商户的每位经手人（本人、在职与已移除的店员）今天、近 7 天、本月、全部的件数与价值。
- `qb.sponsor.redemptions` 加参数 `handledBy`（经手人的用户编号，或 `SELF`）与结果 `redeemedBy`、`handledBySelf`。

## 4. 页面

- **App**：
  - 账户页店员区域加"我的交付"，链接到 `/staff/handled`；
  - 页面顶部是"出示领奖码"（回到领奖台的二维码）；
  - 三个合计（今天、近 7 天、本月），注明时区；
  - 按期间筛选的明细（时间、奖品、价值、发布、领取人、码），每次显示 20 件，可以"显示更多"。
- **商户后台"奖品领取"页**：
  - "经手人"单独成列（店员名或"本人"），今天的列表同样标出；
  - 全部奖品可以按经手人筛选（全部、本人、每位经手人）；
  - 新增"经手人统计"表。

## 5. 测试

- `StaffHandledIT`：
  - 店员的明细与各期间的合计；
  - 10 天后的近 7 天为空，全部仍在；
  - 商户的按人统计、"本人"、按经手人筛选；
  - 别的商户与非店员什么也读不到；
  - 店员被移除后看不到，商户的统计仍有他。
- App `staff.test.tsx`：账户页的链接；页面的合计、明细、显示更多、期间筛选（含无障碍检查）；非店员的说明。
- 商户后台 `publishing.test.tsx`：经手人列（店员名与"本人"）、统计表、按经手人筛选（含无障碍检查）。
