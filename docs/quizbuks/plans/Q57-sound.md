# Q57 音效与开关（2026-10-30）

需求方（2026-10-30）："在答题者和商务的重要操作的地方加音效。但是有开关，可以控制是否执行音效。"音效开关**缺省开**（需求方确认）。

## 1. 设计

- **声音**：由浏览器的 Web Audio 合成的短音（`qb/sound.ts`），不带声音文件；音量很小，跟随设备音量。四种：
  `success`（上行三音：完成）、`reward`（两声清脆的金币：得到奖励）、`wrong`（柔和的下行两音：未通过，不是蜂鸣）、`tap`（打开开关时试听）。
- **何时响**：页面被触碰之前从不发声（浏览器本来也不允许；自己打开的页面保持安静），浏览器没有音频时什么也不做。

| 前端 | 时机 | 音效 |
|---|---|---|
| 答题者 | 刚交卷的结果页（本标签页刚提交的；从记录打开旧结果不响）：通过且有奖励 / 通过或问卷完成 / 未通过 | reward / success / wrong |
| 答题者 | 确认收到现金奖励、电子奖品；到店兑换的奖品已交付；店员柜台确认兑换 | reward |
| 商家 | 发布或提交审核；确认到店兑换 | success / reward |
| 商家 | 标记现金奖励已支付；发送邀请；AI 题目加入 Quiz | success |
| 商家 | 从支付页返回且充值到账 | reward |

- **开关**：每个用户自己的设置，保存在账户上（换设备也一样）：新表 `qb_user_settings`（普通表，每人一行，`sound_off`，没有行即全部缺省：音效开），
  实体 `QbUserSettings`，只由流程 `QB_SETTINGS_SAVE`（`qb.account.read`，答题者与商家都有；不需要已验证的邮箱）写入；本人经 `me:QbUserSettings` 读取，
  管理员（`qb.admin.users.read`）读全部。设备上记住最后一次的值（`localStorage` 的 `qb:sound`），读到账户的设置之前也照它。
  Q59 的内容语言开关加在同一张表。
- **位置**：答题者在"账户 → App 设置"（Q56），商家在账户页最后一节"音效"。开关立即保存，打开时试听一声。
- 个人信息：这张表只有开关，不含个人信息；QuizBuks 的 `PersonalDataEraser`（Q49a）建立时一并列入（删除）。

## 2. 测试

- `SettingsIT`：答题者与商家各自开关、只读到自己的、未验证的邮箱也可保存、管理员读全部、答题者读不到管理员的视图；缺少输入 400；任何人都不能经数据视图写入。
- `qb/sound.test.ts`（两个 SPA 共用）：开关开时按音阶发声，关后不发声且设备记住，页面未被触碰时与没有音频时不发声。
- `App.test.tsx`：App 设置页的开关读出账户的"关"，切换后保存 `QB_SETTINGS_SAVE` 并立即生效，axe。
