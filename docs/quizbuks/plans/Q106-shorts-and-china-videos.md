# Q106 首页的竖屏短视频（照 YouTube）与"含境外视频的 Quiz 不给中国大陆的用户看"

**状态**：需求，需求方 2026-11-05 提出并确认，**首次上线必须有**（`Q94-first-launch.md` §3）。开发前另给细化的实施计划（CLAUDE.md 第 7 节）。编号 Q106：Q105 之后的第一个空号。

## 0. 需求方的决定（2026-11-05）

1. **照 YouTube 的做法，不必创新**：答题者首页本来就是 YouTube 的风格。竖屏（窄）视频照 YouTube Shorts：首页的**一定位置放一排竖屏小卡**，点开后**全屏、手一滑一个**。
2. **视频由发起方负责**：只要不违法，来自哪个网站都可以，平台不限制来源。
3. **规则：Quiz 中有境外视频的，一律不让中国大陆的用户看到。** 国内的发起方用不了 YouTube，自然不会放；境外的发起方放了境外视频，中国大陆的答题者就看不到这个发布。
4. 改动不大，**首次上线就要有**。
5. 具体数字（小卡的位置、每排的个数等）一律是可以设置的参数，不写死在代码中（`backend/quizbuks/CLAUDE.md` 第 4 节）。

## 1. 竖屏短视频（照 YouTube Shorts）

### 1.1 首页的"短视频"一排

- 首页的信息流照旧（横屏卡片、Q65 的单一播放器）。在**一定位置**插入"短视频"一排：标题"短视频"，下面是**横向滑动的竖屏小卡**（9:16），照 YouTube 首页的 Shorts 一排。
- **插在哪里、每排几个**：参数 `qb.feed.shorts.positions`（插在第几张卡之后，如 `3,12`）与 `qb.feed.shorts.per-shelf`（如 10）；没有竖屏发布时这一排不出现。
- **小卡的内容**：发布的封面（Q64；按语言的封面 Q98b）裁成竖屏、发布名称、最高奖励（如"最多 50 Kudos"）。小卡上不播放视频，只显示封面，与 YouTube 一样。

### 1.2 全屏、手一滑一个

- 点一张小卡，进入**全屏的竖屏播放页**，从这一张开始；**上滑下一个、下滑上一个**，一次一屏（CSS 竖向滚动吸附，滚到哪一屏由 IntersectionObserver 判断）。
- **只有一个播放器**：沿用 Q65 的单一播放器（`src/video/stage.tsx`），停在哪一屏，播放器就挪到哪一屏播放；其他屏只显示封面。声音照现有的做法：点一下开声音，之后沿用。
- **叠在视频上的**（照 YouTube Shorts 的布局）：
  - 右侧竖排的按钮：发起方的头像（点进迷你主页）、分享（Q15 的链接）；
  - 下方：发布名称、奖励、"**去答题**"按钮（进入现有的开始答题页，Q75 的"看完才能答"照旧，只有 YouTube 与 Vimeo 能读进度）。
- **返回**：左上的返回按钮或系统的返回，回到首页原来的位置。
- **轮播里放什么**：首页同一批符合条件（受众、地区、前置、§2 的规则）的**竖屏**发布，按首页的顺序。
- **无障碍**：不只靠滑动，另有上一个、下一个按钮，键盘方向键可用；系统设为"减少动态效果"时不自动播放；叠加的文字有足够的对比（亮暗两种外观都过 axe）。

### 1.3 哪些算竖屏

- **自动**：YouTube 的 `/shorts/` 链接（`qb/video.ts` 与 `VideoEmbeds` 已认得）。
- **发起方勾选**：视频资料上加一个"竖屏视频"的勾选（其他网站的竖屏视频）。
- 发布上线时，和现在冻结 `video` 一样，把"竖屏"冻结到卡片上（`QbPublicationCard.videoVertical`，迁移加一列），首页模板多给这个字段；版本切换（Q51）时随之更新。答题路径不变。

## 2. 含境外视频的 Quiz 不给中国大陆的用户看

### 2.1 什么是"境外视频"

- 视频网站分两类，清单写在代码里（`VideoEmbeds` 与 `qb/video.ts` 同一组用例），每个网站标明在中国大陆能否访问：
  - **中国大陆可访问**：哔哩哔哩、优酷、腾讯视频；
  - **境外**：YouTube、Vimeo、niconico、Dailymotion。
- **认不出的网站一律算境外**（视频链接资料 `VIDEO_LINK` 可以是任何网址）：宁可少给，不让中国大陆的用户点开却打不开。新增国内的网站时，把它加进"可访问"的清单。
- **按 Quiz 版本判断**：版本中只要有一个境外的视频（视频资料、发布卡片上的视频，含其他语言的资料版本 Q73），这个版本即"含境外视频"。发布上线与版本切换时冻结到卡片（`QbPublicationCard.foreignVideo`，同一个迁移）。

### 2.2 谁是"中国大陆的用户"

- **已登录的答题者**：资料中的国家是 `CN`。首页模板已经按答题者的国家筛选地区（`qb.app.feed` 的 `country` 参数），在同一处加一个条件即可。
- **没有登录的访客**（分享链接、公开页、招商站的试答）：按浏览器的时区判断（`Asia/Shanghai`、`Asia/Urumqi` 等，维护页已有同样的做法）。这只是不展示，不是安全边界：平台不按 IP 判断位置（隐私政策与平台的原则）。

### 2.3 在哪里生效

| 地方 | 做法 |
|---|---|
| 首页信息流与短视频一排 | 不列出 |
| 发布页（分享链接打开的） | 显示"这个活动在你所在的地区不可用"，不显示内容与视频 |
| 开始答题 | 422 `QB_PUBLICATION_REGION_VIDEO`（直接调用接口也拒绝） |
| 发起方的迷你主页（Q60） | 不列出这类发布 |
| 收件箱的通知（Q7c） | 不显示这类发布的通知 |

### 2.4 告诉发起方

- 发布向导的"受众"一步：所选地区包含中国大陆（`CN`、`ASIA`、`GLOBAL`），而版本含境外视频时，提示"这个 Quiz 含境外视频（YouTube 等），中国大陆的用户看不到这个发布"。只是提示，不阻止提交。
- 提交检查与审核页同样显示这一条，审核人知道它在中国大陆不可见。

## 3. 测试

- 短视频：竖屏的认定（`/shorts/`、勾选）、首页按参数插入一排、没有竖屏时不出现、全屏滑动时只有一个播放器、上一个与下一个按钮、键盘、减少动态效果、去答题、返回原位、axe（亮暗）。
- 境外视频：网站清单前后端同一组用例、认不出的算境外、按版本判断（含其他语言的资料）、卡片冻结与版本切换、`CN` 的答题者在首页、短视频、发布页、开始答题、迷你主页、收件箱都看不到或被拒、其他国家照常、未登录按时区、向导与审核页的提示。
- 首页模板的筛选写在一处，`AudienceIT` 那样比较模板与 Java 的判断。
- 语句数：开始答题的筛选取卡片上已冻结的字段，`AttemptStatementBudgetIT` 不变。
- e2e：一个含 YouTube Shorts 的发布出现在短视频一排、全屏滑动、去答题；同一个发布对 `CN` 的答题者不出现。
