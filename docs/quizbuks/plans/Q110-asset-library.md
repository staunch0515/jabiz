# Q110 发起方的资源库

**状态**：需求方 2026-11-06 提出并确认；**Q110a 列入首次上线**（`Q94-first-launch.md` §3），Q110b 推迟。需求方："定在第一期的都必须做；第一期的内容太多可以推迟。"开工前另给细化的实施计划（CLAUDE.md 第 7 节）。

## 0. 需求方的话与决定（2026-11-06）

1. 发起方的东西很多（线上、线下）：题库、发布、商品、奖品等，要**统一的资源库**；资源库不一定包括题库与发布。
2. 要解决两件事：**"找不到"与"重复填"**。
3. **不是仓库管理系统**：不管库存数量、入库出库、门店，不跨发布共用码池，资源不单独审核。
4. **文字说明也是资源**（需求方认可）。
5. 第一期要做；内容太多可以推迟，但定在第一期的必须做完。
6. 具体数字（上限、长度、个数）一律是参数或已有的内容上限，不写死。

## 1. 核心做法："选了就复制"

- 资源库是发起方"我的东西"的目录：**可以找、可以复用，不管数量**。
- 在做 Quiz 或发布时**从库里选**，选中的内容**复制**进这次的 Quiz 或发布（文件不复制，引用同一个文件编号；文件本来就不可变）；之后各管各的。
- 因此发布的冻结、审批绑定的内容、答题结算、码池全都**不改**；改了库里的资源，已经做好的 Quiz 与发布不跟着变（发布本来就是提交即冻结）。
- 复制时记下来源（`assetId`），于是能显示"用在哪里"，并在资源改过之后提示"这些地方用的是旧的内容"（只提示，不自动改）。
- 反方向：在 Quiz 编辑器、发布向导中，把正在填的内容"**存入资源库**"，一步收进来。

## 2. 资源的种类

| 种类 | 内容 | 用在哪里（"从库里选"） |
|---|---|---|
| **素材** | 图片、PDF、音频（上传一次）；视频链接（照 Q99 认网站，带时长）；网页链接；文章（Markdown） | Quiz 的资料、题目与选项的图片、Quiz 封面、发布封面（Q64、Q98b） |
| **文字** | 一段可复用的说明，三语（基准语言 + 译文，带所译原文的哈希，同 `TextTranslations`），标明**用途** | 按用途出现在对应的输入框旁：到店兑换说明（`redeemDescription`）、电子奖品说明（`digitalDescription`）、推荐说明（`referral` 的说明）、Quiz 简介；通知与对话的快捷回复在 Q110b |
| **奖品** | 一个"奖品卡片"：名称（三语）、图片、领取方式（到店兑换 / 电子奖品 / 发起方付现金）、领取说明（三语）、电子奖品的交付方式与发送天数 | 发布向导的奖励一步：选一张奖品卡片，把方式、说明、交付设置一次填好（复制）；**兑换码照旧装进每个发布自己的码池** |
| **商品** | 现有的商品（Q60b，`QbSponsorProduct`），数据不动 | 资源库中显示与编辑（商户中心的"商品"移到这里，旧地址转向） |
| **认证** | 现有的发起方认证（Q88a），数据不动 | 资源库中显示与编辑（旧地址转向） |

不放进资源库：Quiz（题库）、发布、采购来的权益（留在"合作权益"）、码池、兑换记录。

## 3. "找不到"：一处找到全部

- 资源库的列表：搜索（名称、说明、标签）、按种类与用途筛选、按语言筛选、卡片 / 表格两种视图（Q34b、Q80 的写法）、预览。
- **标签**：自由填写，每个资源若干个（个数与长度为参数）。
- **用在哪里**：每个资源列出复制到了哪些 Quiz 与发布（由来源编号查得），可以点过去。
- **一次性收集现有内容**（首次上线即做）："把我已有的内容收进资源库"：读本人所有 Quiz 的资料与图片、发布的封面与奖励说明，去掉重复（文件按编号、文字按内容哈希），列出来让发起方勾选后收进库。只读本人的、只在本人点了之后做；之后不自动同步。

## 4. 数据与流程（后端）

- 新实体 `QbAsset`（普通表 `qb_asset`，主键 UUIDv7）：发起方账户自己的记录，按 CLAUDE.md 第 4 节"发布方"的范围规则用 **`sponsorId`**（不带 `publisherKind` 那一对）；`kind`（`IMAGE` `PDF` `AUDIO` `VIDEO_LINK` `LINK` `ARTICLE` `TEXT` `PRIZE`）、`name`、`description`、`language`、`translations`（jsonb）、`tags`、内容字段（文件编号、地址、正文、时长）、文字的 `usage`、奖品的领取方式与交付设置、`revision`、时间。
- 文件：内容策略照旧（`qb.content.image|pdf|audio`，`privateMetadata()`），上传者必须是本人（`QuizEditing.requireOwnFile` 的规则）；资源行引用文件，平台的清扫因此不会删掉它；删掉资源后没人引用的文件由平台清扫。
- 来源：`QbMaterial` 与 `QbPublication` 增加可空的 `assetId`（发布表是只追加表：只加列，`SealedColumnsHistory` 照常检查）。
- 写入只经 `QB_ASSET_SAVE` / `QB_ASSET_DELETE` / `QB_ASSET_COLLECT`（收集现有内容），数据视图 `processOnlyWrites`，商家视图只读、限本人；要求已验证邮箱、先查封禁；锁 `qb.assets:<发起方>`（数量上限在锁内检查）。规则在纯 Java 的 `AssetRules`（长度沿用目标字段的上限：素材用 `ContentLimits`，文字按用途用发布的字段上限）。
- "从库里选"**不新增写入流程**：页面读出资源后，照现有的 `QB_MATERIAL_*`、`QB_PUBLICATION_SAVE` 填入，多带一个 `assetId`；规则与手填完全相同。
- 新的默认数据视图登记 `OperatorScopes`；运营商与总部的客服可只读（排查问题时），不可改。
- 删除账号：资源随账号清除（登记 `PersonalDataEraser`）。
- 答题路径一条语句也不加（`AttemptStatementBudgetIT` 不变）。

## 5. 界面（发起方后台）

- 菜单：Q108 的新框架之前，在现有菜单"内容"组加"**资源库**"（标签：全部 / 素材 / 文字 / 奖品 / 商品 / 认证），商品、认证的旧菜单项与地址转到这里；Q108 实施时它就是 8 个区域之一（Q108 §2 的"商户中心"随之去掉商品与认证两个标签）。
- "从库里选"：一个共用的选择对话框（按种类、用途预先筛选，可搜索），放在 Quiz 编辑器的资料与图片、Quiz 与发布的封面、发布向导的奖励一步与各说明框旁。
- "存入资源库"：同样这些地方的一个小按钮。
- 文字与奖品的编辑：基准语言 + 译文（与商户短文字 Q73c 的编辑相同），可用现有的 AI 翻译候选。
- 页面只用 `@jabiz/ui`，三语文案，亮暗两种外观过 axe。
