# Q94 首次上线的范围（冻结用）

**状态**：需求方 2026-11-04 定下原则与钱的做法（§1、§4）；§6 的两点待确认。确认后冻结：**不在"做"之列的，一律不在首次上线前开发**；要加，先改本文并经需求方确认。

## 0. 为什么要有这一页

Q90 之前的功能各自成立，却连不成一条能转起来的路。Q90–Q92 的讨论把它们串成了一个闭环：**点亮知识结构图**。本文只回答三件事：首次上线**做什么、不做什么、做到什么程度算完成**。

**原则**（需求方 2026-11-04）：有限的真实使用；功能不要太复杂，但一定要让闭环转起来。

## 1. 首次上线是什么

- **正式上线**：正式系统、真实用户，不是测试系统中的试用。用户少，范围有限。
- **核心是点亮知识结构图**（§2）。
- **奖励以线下兑奖（Q89c 的兑奖码）与电子奖品（Q33）为主**。发起方自己给现金也可以，与平台无关、平台不管（Q92）。
- **钱**：平台暂时不收钱；Stripe 正式接口打开，有人付钱不拦；**有价的学分暂时控住、不放开**（§4）。
- **只有网页与 PWA**：不上 App Store 与 Google Play；iOS（Q49c）与 Android（Q49b）外壳不在本次。
- **没有 Shopify**：Q92a-3 与 Shopify 运营商往后排。

## 2. 要跑通的闭环

1. 发起方在后台定义自己的知识结构图（节点与条件），经运营商的另一位成员审核后生效。
2. 发起方发布挑战并绑定到节点，奖品为线下兑奖或电子奖品，经审核后公开。
3. 答题者答题，满足条件即点亮节点；在 App 中看到整张图与自己的状态。
4. 答题者领到奖品：电子奖品直接收到，线下奖品在店里出示兑奖码、店员核销。
5. 点亮的节点有证书，答题者可以出示，别人可以核实。
6. 平台运营商用平台图做同样的事（平台挑战由运营商的官方账号发布）。

这六步先在测试系统中由需求方亲手走通，再在正式系统中由第一批真实用户走通。

## 4. 钱的做法（不开发，只设开关）

| 项 | 首次上线 |
|---|---|
| 平台费、凑合与交易的抽成 | 不收：`qb.fee.monthly` 为 0，抽成为 0 |
| Stripe | 正式模式打开；有人充值不拦，照常记账、开收据 |
| 有价的学分 | 控住，不放开（具体开关见 §6 第 1 点） |
| 提现 | 不开 |
| 发起方给现金 | 平台不管（Q92），不做任何功能 |

因为 Stripe 正式模式打开，`launch-checklist.md` 中的特定商取引法表示、收据与隐私政策（Stripe 作为第三方）**都必须做完**才能上线。

## 6. 待需求方确认

1. **"有价学分控住"的具体做法**（建议）：
   - 充值（Stripe 与银行转账）照常可用，有人充值不拦，学分照常进账，可用于发布的学分奖励；
   - 学分不能流出平台：换回现金 `qb.kudos.sell.enabled`、转账 `qb.transfer.enabled`、提现都关；
   - 平台不主动推广充值（后台不在显眼处引导）。

   如果"控住"的意思是连充值成学分也不要，就把 `qb.topup.targets` 只设为 `CASH`（只进现金账户，不变成学分）。
2. **Q90 §10 第 1、2 条**：见 §3 末尾。
