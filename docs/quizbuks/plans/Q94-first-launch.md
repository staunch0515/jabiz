# Q94 首次上线的范围（冻结用）

**状态**：草案，2026-11-04，待需求方确认。确认后冻结：**不在"做"之列的，一律不在首次上线前开发**；要加，先改本文并经需求方确认。

## 0. 为什么要有这一页

Q1–Q93 多是讨论与设计，没有一个"到这里为止"的边界，做得越多越没底。本文只回答三件事：首次上线**做什么、不做什么、做到什么程度算完成**。

## 1. 首次上线是什么

- **封闭试用**：用户很少（需求方自己、平台运营商的直营发起方，再加几个邀请的发起方与答题者）。
- **不收钱**：没有充值、提现、平台费、学分买卖与付费称呼；涉及真钱的开关全部关着（见 §4）。
- **只有网页与 PWA**：不上 App Store 与 Google Play；iOS（Q49c）与 Android（Q49b）外壳不在本次。
- **没有 Shopify**：Q92a-3 与 Shopify 运营商往后排。
- **服务器费用**：将来以 Google 广告补贴（§5），不在本次开发。

## 2. 要跑通的闭环

1. 发起方在后台定义自己的知识结构图（节点与条件），经运营商的另一位成员审核后生效。
2. 发起方发布挑战并绑定到节点，经审核后公开。
3. 答题者答题，满足条件即点亮节点；在 App 中看到整张图与自己的状态。
4. 点亮的节点有证书，答题者可以出示，别人可以核实。
5. 平台运营商用平台图做同样的事（平台挑战由运营商的官方账号发布）。

这五步全部在测试系统中由真实的人走通一遍，才算首次上线完成。

## 5. 广告（往后排，先记下要求）

服务器费用打算以 Google 广告（AdSense）补贴。用户很少时广告几乎没有收入，AdSense 申请还要求有一定的内容与访问量，所以放在试用之后单独做。做的时候至少要处理：

- 只放在公开页面（公开问卷、发布页），不放在答题过程、后台与证书上；
- SPA 的 `content-security-policy` 加上 Google 广告的域名（平台配置 `jabiz.web.spa[i].content-security-policy`，不自己改头）；
- 隐私政策补上广告与第三方 Cookie（日本电气通信事业法的"外部送信"规则，欧盟访客需同意）；
- 广告内容与品牌调性：屏蔽竞品与不当类别。

## 6. 要需求方回答的一个问题

**不收钱时，发起方的学分从哪里来？** 奖励学分要发起方有余额，但首次上线不开充值。三个办法任选其一：

- (a) 总部向试用的发起方免费发放学分（建议：只记账、不对应真钱，试用结束清零或保留由需求方决定）；
- (b) 首次上线的发布不给学分奖励，只有点亮与证书；
- (c) 用 Stripe 测试模式充值（只是假钱，试用者需要测试卡号，体验较差）。
