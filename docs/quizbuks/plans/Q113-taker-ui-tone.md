# Q113 学者 App 界面定调（设计，2026-11-24；待需求方确认）

需求方（2026-11-24）：对学者页面的界面一直不满意。要求按专业 UI 设计师的思路，先分析问题，再定调子和方向，原则清楚之后再设计。
需求方最认可 X（原 Twitter）的**布局和操作**；配色另选一套。

本文只定调子、原则和骨架，**不画页面，也不开发**。确认后的顺序：设计规格（字号、间距、组件）→ 共用组件 → 逐页落实。

## 1. 诊断摘要（为什么以前的修改没用）

过去的修改都停留在表面：Q32 加了颜色、插画和横幅，Q34 改了圆角和紧凑度，此外还有大量逐页修补。体系从来没有定过，所以问题反复出现。主要有以下几类：

- **头部太重**：每个一级页面依次是"字标栏 + 深绿大圆图标 + 标题 + 标签"，合计约 165px。品牌压过内容，第一个标签还和标题重复。
- **后台感**：界面零件来自后台组件库，到处是带框的白盒子、14px 正文、灰色说明文字。筛选面板是一张查询表单，"我的"是 22 行的长列表。
- **形状混乱**：直角输入框和卡片、胶囊形选项、圆形头像和图标在同一屏里并存。
- **层级扁平**：文字基本只有 14px 和 12px 两档，学分、奖品和普通说明分量相同。
- **奖励没有统一的样子**：首页、开始答题页、结果页、已答页各用一种写法。
- **颜色失控**：暗色模式一屏里有四种绿，顶部状态栏也是亮绿。
- **框套框**：结果、题目、列表项都装在细边框的方盒子里。
- **宽屏只是拉宽的手机**：中间一条 448px 的窄带，七成屏幕空着。
- **文案与数据格式没有规范**：时间带到秒、中文里夹多余空格、"发布人"和"发起方"混用、把发起方的运营统计给学者看。

## 2. 调子

**一句话：像刷时间线一样刷题。内容是主角，界面退到后面，奖励是唯一的亮色。**

三个关键词：

1. **轻**：没有框，没有装饰，没有多余的头部。界面元素只在需要时出现。
2. **快**：一眼看清，一次点击就到。操作位置固定，手指形成记忆。
3. **有回报**：学分、奖品、合格这些时刻要有固定、醒目的视觉形象，是整个界面里最亮的东西。

## 3. 从 X 借鉴什么，不借鉴什么

**借鉴的是布局与操作的模式**，这些是通用的交互范式：

| # | X 的做法 | 在学者 App 中 |
|---|---|---|
| X1 | 一条固定宽度的中央时间线（约 600px），条目铺满列宽，条目之间只用一根细线分开，**没有卡片和边框** | 首页、已答、消息、学分交易都是这种列表 |
| X2 | 每个条目都是同一种结构：**左边头像，右边内容**。首行是"粗体名字 · 灰色元信息 · 右端更多"，其下是正文、媒体，最后一行是操作 | 发布、消息、已答记录、交易都套用这一种结构，学一次处处会用 |
| X3 | 宽屏分三栏：左侧导航（品牌、大号图标加文字、一个醒目的主按钮），中间时间线，右侧辅助栏（搜索、推荐）。中等宽度时导航只留图标，手机上换成底部标签栏 | 右侧放搜索、待领奖品、推荐的发起方；左侧的主按钮是"扫一扫" |
| X4 | 头部吸顶，半透明背景。一级页面的头部只有标题或一排标签；子页面是"← 标题"，下面可以有一行小字（如"12 条"）。**品牌只出现在导航里，不出现在每一页** | 去掉每页的字标栏和大圆图标。所有子页面使用同一种"← 标题"头部 |
| X5 | 顶部标签等宽排列，选中的那个下面有一条短而粗的下划线 | 首页的几种来源，以及已答、消息、扫一扫的分页 |
| X6 | 点进条目就是详情页：头部"← 标题"，内容用大字，下面是相关列表，主要操作固定在底部 | 开始答题页、结果页、消息详情 |
| X7 | 个人页：头像、名字、简介，一行内联的数字（如"120 正在关注"），下面是标签分页。**设置是另一个独立入口**，不和个人内容混在一起 | "我的"改成个人页：学分、证书、奖品是一行数字，下面分页显示已答、证书、地图；设置单独成页 |
| X8 | 设置页是纯列表：标题、一行说明、右箭头，没有框，靠分组标题分开 | 账号、安全、通知、偏好、帮助、条款 |
| X9 | 菜单、选择、筛选用底部抽屉或弹出菜单；"…"打开更多操作 | 首页筛选改成分段的抽屉，不用整张表单 |
| X10 | 所有按钮、标签、搜索框都是胶囊形，头像是圆形，媒体统一圆角 | 解决"三种形状"的问题 |
| X11 | 主操作只有一个强调色的胶囊按钮，其他按钮是描边或纯文字 | 每屏最多一个实心强调按钮 |
| X12 | 空状态：一个粗体大标题、一句说明、一个胶囊按钮，左对齐，不用插画 | 替换掉现在"插画加图标叠在一起"的做法 |
| X13 | 动效快而克制：进入下一层从右侧推入，返回时滑回 | 和现在已有的返回逻辑一致 |

**不借鉴的**：X 的品牌、标志、配色（黑、白、天蓝）、图标形状和名称都不用。图标继续用现有的 lucide，配色另定（第 6 节）。

## 4. 原则（每条都可以检验）

| # | 原则 | 检验方法 |
|---|---|---|
| P1 | **内容不装框**：列表条目、设置行、题目结果之间只用细分隔线，不加边框和背景卡片。只有浮层（抽屉、弹窗）和媒体有背景或圆角 | 页面里没有"边框套内容"的盒子 |
| P2 | **一种形状语言**：按钮、标签、搜索框、筛选项一律胶囊形；头像和徽标是圆形；图片和视频圆角 16px；不出现直角框 | 一屏里只有胶囊、圆和 16px 圆角三种 |
| P3 | **一种条目结构**：凡是一条记录（发布、消息、已答、交易、奖品），都用"左头像或图标 + 右内容"的结构 | 新列表直接复用条目组件，不另写版式 |
| P4 | **三种头部**：一级页（标签或标题）、子页（← 标题 + 小字）、沉浸页（答题、扫码：只有关闭按钮）。品牌只在导航中出现 | 每个页面都能归入其中一种 |
| P5 | **层级靠字重和明暗，不靠框和颜色块**：正文 15px；次要信息 13px 灰色；页面标题 20px 粗体；关键数字 24–32px 粗体。全 App 最多用这五档 | 代码里的字号只出现规格中的几档 |
| P6 | **奖励专属一种颜色**：学分、奖品、合格、待领奖使用统一的奖励组件和奖励色。奖励色不用在其他地方 | 奖励在四个页面长得一样 |
| P7 | **每屏一个主操作**：实心强调色按钮每屏最多一个，其余用描边或文字按钮 | 截图检查 |
| P8 | **学者只看对学者有用的信息**：完成统计表、内部编号、精确到秒的时间不给学者看；时间用"今天 14:22""3 天前" | 文案和格式规范 |
| P9 | **空状态是一等页面**：粗体标题说清状态，一句话说明，一个按钮指向下一步 | 每个列表都有设计过的空状态 |
| P10 | **宽屏是三栏，不是拉宽的手机**：中央列约 600px，左侧是导航，右侧是辅助栏 | 1280px 宽时没有大片空白 |
| P11 | **亮色和暗色分别设计**：暗色模式用中性的深灰或黑，强调色单独调过；状态栏颜色跟随外观 | 两种外观都单独过一遍截图 |

## 5. 骨架

**导航**

- 手机：底部 5 个标签保留，扫一扫仍在中间，但要和整体风格一致，不再是凸起的大绿圆。
- 中等宽度：左侧只显示图标。
- 宽屏：左侧显示图标加文字，最上方是品牌。

**页面宽度**：中央列约 600px；宽屏右侧辅助栏约 350px。

**各页落位（方向，不是设计稿）**

| 页面 | 新骨架 |
|---|---|
| 首页 | 一级头部：顶部标签（来源或类别）。条目按 X2 的结构：发起方头像在左，右侧依次是"名称 · 时间"、标题、圆角封面或视频、一行"奖励 · 已完成人数 · 分享 · 更多"。筛选是头部右端的一个按钮，打开抽屉 |
| 开始答题 | 详情页：← 标题；视频；大字标题；发起方一行；一行事实（只保留最重要的三项）；标签分页（说明、奖励、资料、规则）。底部固定"开始答题"按钮，看视频的进度画在按钮上。去掉给学者看的完成统计表 |
| 答题结果 | 详情页：得分作为大数字，奖励使用奖励组件，领奖码是一个清楚的操作；逐题结果是列表，不装框 |
| 已答 | 一级头部：标签"已答 / 待领奖"；列表条目套用 X2 结构 |
| 消息 | 一级头部：标签"收件箱 / 对话"；条目套用 X2 结构；"显示推广"移到设置里 |
| 我的 | 个人页（X7）：头像、名字、一行数字（学分、证书、奖品），下面分页。设置单独成页（X8），从头部右端的齿轮进入 |
| 设置及其子页 | 子页头部；纯列表 |

## 6. 配色（待选）

**配色原则**

- 底色用中性色（白，暗色时用近黑），不铺色块。
- **一个交互强调色**：只用在主按钮、选中状态、链接。
- **一个奖励色**：只用在学分和奖品上，和强调色明显不同。
- 成功、警告、错误用语义色。
- 亮色和暗色各调一套，对比度都要过 axe 检查。

**三套候选**（色值是初稿，选定后再精调对比度）

| 方案 | 强调色（亮 / 暗） | 奖励色 | 气质 |
|---|---|---|---|
| A 墨绿 + 金 | 深松绿 `#0F6B5C` / `#5FD4B8` | 金 `#D4A017` | 延续现在的品牌绿，但只用一层绿；沉稳、可信 |
| B 靛紫 + 金 | 靛紫 `#5B4BDB` / `#A69BFF` | 金 `#D4A017` | 知识、学习的感觉更强，和"学者""学分"呼应；与 X 的天蓝明显不同 |
| C 墨黑 + 橙 | 近黑 `#111418`（按钮）/ 白 | 橙 `#F2711C` | 最克制，像杂志；奖励的橙色最跳，最有"赚到了"的感觉 |

选定之后，品牌色继续只通过覆盖 token 来实现（`brand.css`，D-Q32-1），页面里不写死色值。

### 9.1a 滚动（实测）

| 情形 | X 的做法 | 学者 App |
|---|---|---|
| 谁在滚动 | 整个页面滚动（文档滚动），没有页面内的滚动区；手机上不显示滚动条 | 相同：页面里不出现任何滚动区和滚动条（横向滚动的标签行除外，也不显示滚动条） |
| 内容与头部 | 头部固定在顶端，白色 85% 透明加 12px 模糊，内容从它下面滚过 | 相同 |
| 向下滚 | **跟手**：先有约 20px 的空程，之后头部（顶栏 53px + 标签行 53px）随滚动距离一比一上移，最多 106px，即完全移出。底部栏和悬浮按钮的不透明度随之从 1 线性降到 0.3，**连白色背景一起变透明**，内容从下面透出来，看上去就是消失了，但仍可点按。CSS 过渡：头部 `transform 0.35s cubic-bezier(0,0,0,1)`，底部栏 `opacity 0.17s` 线性 | 相同 |
| 向上滚 | **不跟手**：慢慢地、小幅地往上滚不会出现；一次快速向上划动（单次超过约 50px）时，头部一下子滑回，底部栏和悬浮按钮恢复不透明。滚回顶端时也全部恢复。实测：分 5 次共上滚 110px 不出现，一次上滚 60px 立即出现 | 相同 |
| 子页面（帖子详情） | 同样：头部滑出，底部栏变淡 | 相同（答题详情底部的"开始答题"栏随底部栏） |
| 宽屏 | 整个窗口滚动，滚动条在窗口最右侧；左栏与右栏固定不动（吸顶）；中栏的标签行吸顶，不隐藏 | 相同 |

### 9.3 首页条目的点按与答题开始页的两种模式（需求方 2026-11-24 确认）

| 点哪里 | 去哪里 |
|---|---|
| 发起方头像、发起方名字 | 发起方迷你网站 |
| 答题名称、简介文字 | 答题开始页的**普通模式**（X 的帖子详情） |
| 视频（封面或正在播放的视频） | **最大化这条视频**：答题开始页的**视频流转模式**，从这条视频开始，同一个播放器带着声音接着播（2026-11-27 需求方确认：不是在首页原处出控制条） |

**普通模式**（2026-11-28：资料下面不再放发起方迷你网站的区块，最上面的发起方一行已经指向它；结果页照旧）：与原型的"答题详情"相同（视频、发起方、标题与简介、发布信息、信息行、资料与规则的标签，底部固定"开始答题"栏）。

**首页的视频**（2026-11-27 在 x.com 实测，手机 375px 与宽屏）：竖屏视频按自己的竖向比例显示，不放进 16:9：9:16 圆角框、靠左，宽至多 287px（高至多约 510px；x.com 手机上约 291×517、宽屏 285×506）；横屏照旧 16:9 满栏。封面与播放器是同一个框、同一个尺寸。静音自动播放、没有控制条；点视频即最大化（见上表）。**带视频的帖子不显示封面，也不在画面中间放播放标记**（2026-11-28 需求方：封面与视频切换时闪烁）：视频的位置在播放器出第一帧之前显示**视频自己的画面**（2026-11-28 第二次：底色一块不好看）：YouTube 用它对该视频的图片（`i.ytimg.com`，裁成视频框）；视频文件与其他网站用发起方的封面（2026-11-28 第三次需求方选定：视频文件开头一帧要用不播放的 `<video>` 显示，iPhone 上画不出、还会让正在播放的视频也不显示）。首页播放中的视频与封面一样铺满视频框（`object-cover`），不在旁边露出封面。播放器出第一帧后在这张画面上淡入，不出现黑屏；视频流转模式中各屏同样显示视频自己的画面，切换时播放器出第一帧之前也是这张画面，不出现黑屏。没有视频的帖子、播放失败的视频文件照旧显示封面。

**视频流转模式**（X App 点视频后的沉浸式视频浏览；现有 F-S10 竖屏模式扩展到所有视频，横屏视频也一样）：

- 全屏黑底，一屏一个视频，上滑下一个、下滑上一个；只放**带视频的答题**，按首页的顺序，**不带视频的答题跳过**。
- 视频正常播放，**不出现播放器自己的控制状态**（暂停、控制条、等点按）：屏幕接住对视频的点按，点一下暂停、再点继续，滑动换下一个；声音用"开声音"按钮。
- 不显示头部与底部栏；左上角只有关闭，回到首页原来的位置。
- 叠在视频上：发起方头像与名字（点按进迷你网站）、答题名称、奖励（金色）、**两个按钮**：
  1. **"详情"**：进入答题开始页的普通模式（看资料、规则后再开始）。
  2. **"开始答题"**：直接开始答题。看视频的要求（Q75）照常：没看够之前不可用，显示还差的秒数；在流转里看的时长计入。
- 以后流转中还会出现**广告视频与娱乐视频**作为引导：这类只有"详情"（进入答题开始页），没有"开始答题"。条目组件按此设计成两个按钮各自可有可无。
- 声音一经打开，切到下一个视频仍然开着（现有行为）。

### 9.4 登录与注册（2026-11-24 在 x.com 实测，未登录的独立浏览器）

**X 的做法：登录和注册是同一个页面**，没有"登录 / 注册"两个标签。页面只问"用什么继续"：

| 部分 | 手机（390px） | 宽屏（1280px） |
|---|---|---|
| 版式 | 左上角返回 32px；标志加一句标题（20px 粗体）居中；下面一列按钮，左右各约 38px 边距（内容宽约 314px） | 左半边一列，宽 384px，距左 36px：64px 的大标题（字重 600），下面同样一列按钮；右半边是巨大的标志；底部一行 11px 灰色链接 |
| 第一个按钮 | 近黑实心胶囊，高 46px："使用手机继续" | 同左 |
| 第三方 | 白底描边胶囊（1px），高 40–48px："使用 Google 继续""使用 Apple 继续"；按钮之间约 20px | 同左 |
| 分隔 | 细线中间一个"或"（15px 灰） | 同左 |
| 输入框 | 高 62px、圆角 6px；标签在框内（空时 17px，聚焦或有值时缩到 12px、移到上方）；聚焦时 2px 强调色边框 | 同左 |
| 继续 | 胶囊按钮，高约 48px；没填时灰色不可用，填了变近黑 | 同左 |
| 条款 | 按钮下一行 13px 灰字，"服务条款""隐私政策"加粗 | 同左 |

**学者 App 的对应**（配色方案 A，标志与文字换成答题拼好价）：

- 第一个近黑按钮：**"通过邮件链接继续"**（不用密码，对应 X 的"使用手机继续"）。
- 描边按钮：Google、LINE、Facebook（入口开启了哪些就显示哪些）与"使用通行密钥"。
- "或"之下：邮箱输入框与"继续"；继续之后是第二步：输入密码（附"忘记密码"）。
- 欢迎轮播保留在第一次打开时；之后直接是这个页面。

**待需求方决定：注册是否也并进同一个页面。**
X 的注册与登录完全合一：输入邮箱后，由系统判断是新用户（进入注册的下一步）还是老用户（进入输入密码）。
我们的平台目前是两条路：登录与注册是两个标签（`SignInForm` 的 `tabs`），而且为了安全，**登录时不透露某个邮箱是否已注册**（平台 D47 等）。所以：

- **做法一（推荐，不改安全规则）**：版式照 X，但页面底部仍有一行"还没有账号？注册"（X 旧版的写法），注册是同样版式的另一个页面（邮箱、密码、同意条款、注册）。
- **做法二（完全照 X）**：只有一个"继续"；系统按邮箱是否存在分流。要改平台的认证流程，并接受"邮箱是否注册过会被看出来"这一点，或者改为一律先寄邮件链接（新用户点链接后完成注册）。改动大，涉及安全评审。

**需求方决定（2026-11-24）：全部统一**，即做法二。登录与注册是同一个页面，只有一个"继续"。为了不透露某个邮箱是否注册过（平台 D47 等的要求不变），"继续"之后的第二步对所有人都一样：

1. 默认给这个邮箱寄一封**一次性链接**：老用户点链接即登录；新用户点链接后进入"完成注册"（名字、同意条款），完成即登录。
2. 同一步里可改用**密码登录**（输入密码，附"忘记密码"）；邮箱没有账号时，与密码错误显示同一句提示。
3. Google、LINE、Facebook 与通行密钥照常：第三方新用户按平台 D39 的规则开户，老用户直接登录。

这要改平台的认证流程（邮件链接可用于注册、入口页的统一流程），须先在 `1.3/platform` 完成并通过安全评审（`/security-review`）。原型中的"注册"页改为"完成注册"一步。
