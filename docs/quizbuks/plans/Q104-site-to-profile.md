# Q104 从企业官网生成发起方的迷你网站（资料包与"认识我们"的 Quiz）

**状态**：需求，2026-11-05 需求方提出并要求列入首次上线（`Q94-first-launch.md` §3 第 8 项）。各期开发前另给细化的实施计划（CLAUDE.md 第 7 节）。
编号 Q104：Q103 之后的第一个空号。它把 Q100 中尚未做的三步（D-Q100-9 提示词模板、Q100b 链接图片的下载、Q100d 从官网生成）收拢为一个需求，并增加"认识我们"的 Quiz。

## 0. 需求方的原话与目标

> 比如我给 AI 一个企业宣传网站，如何让 AI 生成一个可以导入 QuizBuks 的公司资料包呢？就是自动把一个企业的网站的内容移植到 QuizBuks 的迷你网站。

**目标**：给一个企业官网的地址，几分钟内得到该企业在 QuizBuks 上的"迷你网站"：

- 公开主页（Q60：地址名、标语、封面、官网链接，三种语言）；
- 基本信息（公司名、简介、头像）；
- 商品目录（Q60b，至多 50 个：名称、说明、价格、购买链接、图片）；
- 一个"认识我们"的 Quiz 草稿：官网上的介绍做成资料，再出几道题，导入后就可以发布一个"了解品牌"的活动。

**为什么首次上线就要**：

- 测试期要反复重置数据库（Q103）；
- 上线时要快速做出样板间（运营商的直营发起方，Q92a）；
- 第一批真实发起方手里只有官网，没有时间逐项填写。

## 1. 原则

| # | 原则 |
|---|---|
| P1 | **只起草，不写入**：AI 的结果一律进入现有的导入确认页（资料包为 Q100 的 `QB_PROFILE_IMPORT_CHECK`，Quiz 为 Q16 的 `QB_QUIZ_IMPORT_CHECK`），由发起方逐项校对后才写入。写入只经现有流程，规则与手填相同 |
| P2 | **审核一项不少**：主页照常要审核（Q60a）；入驻没有通过时，基本信息填进入驻申请表（D-Q100-3）；Quiz 是草稿，发布时照常审核。不因为"是 AI 生成的"而免审，也不因此多一道审核 |
| P3 | **不编造**：只用官网上有的内容。没有的字段留空，并在确认页列出"官网上没找到"。每个字段都记下取自哪一页，确认页在字段旁显示来源链接 |
| P4 | **权利**：发起方生成前勾选"这是我的（或我有权使用的）网站"。尊重网站的 `robots.txt`（提供方的网页读取本来就会拒绝被禁止的页面）。图片下载一次后归入我们的存储，之后不再访问原网站（D-Q100-6） |
| P5 | **不收集个人的信息**：联系人姓名不从官网取，用发起方账户的名字；网站上的个人邮箱、电话一律不取。"联系方式"只取公司的公开地址或公开表单的链接，放在主页的说明中 |
| P6 | **费用与开关同 AI 出题**：计入发起方的 AI 限额；请求时须同意 `AI_NOTICE`；受 `qb.ai.enabled` 控制。首次上线 AI 费用由平台承担（Q94 §4） |

## 2. 官网内容到 QuizBuks 的对应

| QuizBuks 的字段 | 取自官网的哪里 | 说明 |
|---|---|---|
| `basics.company` | 页眉、页脚、"公司概要 / 会社概要 / About" | 正式名称 |
| `basics.contactName` | **不取**（P5） | 用账户的显示名，发起方可改 |
| `basics.intro` | "关于我们"、首页的介绍段落 | 简介，2–5 句，不照搬整页 |
| `basics.avatar` | 网站的 logo（`<link rel=icon>`、`og:image`、页眉图片） | 链接图片 |
| `page.handle` | 由域名得出（`www.aini-helmet.com` → `aini-helmet`），按规则清洗（3–30 个小写字母、数字、连字符） | 被占用时由确认页提示另选 |
| `page.headline` | 首页的主标题或 `og:title` / `description` | 一句话标语 |
| `page.website` | 输入的官网地址（规范化为 `https://…/`） | 官网的地址放在这一栏，不是地址名（T10 的误会） |
| `page.cover` | 首页的主视觉、`og:image` | 链接图片 |
| `products[i]` | 产品与服务页、在线商店的商品页 | 名称、说明（2–3 句）、价格与币种（明码标价才取，不猜）、购买链接、商品图片、货号（有则作为商品编号 `code`，Q100e）；至多 50 个，按网站上的顺序 |
| 语言 | 网站的 `<html lang>`、页面文字 | 网站的语言为基准语言；发起方选的其他语言由 Claude 翻译，标明"机器翻译" |
| "认识我们"的 Quiz | "关于我们"、"品牌故事"、"产品特点"、"常见问题"等页的正文 | 见 §4 |

## 3. 三条路

### 3.1 路线 A：提示词模板（任何 AI 都能用，零开发成本）

`docs/quizbuks/profile-package-prompts.md`，照 Q16 的 `quiz-file-prompts.md`：

- **给 AI 的提示词**，带参数：官网地址、基准语言、其他语言、要不要商品、商品的上限。
- **资料包的格式规则**：导入检查的全部规则写成清单，例如字段、长度、三语写成 `{ja, zh, en}`、图片写成 `{"url": …}`、商品至多 50 个、地址名的规则。
- **§2 的对应表与 P3、P5**：不编造、不取个人信息、没有的留空。
- 两个完整的示例：只有基准语言的；三语、带商品的。
- 一段"文件被拒时让 AI 修正"的提示词：把确认页列出的问题原样贴给 AI。
- **测试**：`ProfilePackagePromptsTest` 让文档里的示例 JSON 经过服务器的资料包检查（`ProfilePackage`），规则改了而文档没跟着改即失败。

同时补上 Quiz 的提示词（已有 `quiz-file-prompts.md`）中"从官网生成认识我们的 Quiz"的一段（§4 的规则）。

### 3.2 路线 B：商家后台"从官网生成"（产品内，一键完成）

**入口**：商户中心"概况"页的"商户资料包"卡片里，加一个"从官网生成"按钮（Q100 的导出、导入旁边）。

**流程**：

1. 发起方输入官网地址，选择语言（基准语言缺省为网站的语言，可另选其他语言）和要生成的内容（主页与基本信息、商品、"认识我们"的 Quiz，缺省全选），勾选权利声明（P4），同意 AI 说明（P6）。
2. 提交即建立一个异步外部作业（平台 D38），页面显示"正在读取官网（约 1–3 分钟）"。离开页面也照常进行，完成后在消息中心通知。
3. 作业由 Claude 经现有的 `ClaudeWebResearch`（网页搜索与读取，AI 获客已在用）完成：
   - 只读这个网站：网页读取限定在该域名（`allowed_domains`），一般不用网页搜索；
   - 至多约 10 页，每页至多 2 万 token（`MAX_CONTENT_TOKENS`）；
   - 以 JSON 作答：资料包 + 每个字段的来源页 + 没找到的字段 + "认识我们"的资料正文。
4. 结果先经与导入相同的检查（`ProfilePackage`、`QuizFileChecks`）。不合格的字段去掉，并在确认页列出原因，不让整个结果失败。地址名被占用时给出备选。
5. 打开现有的导入确认页，在字段旁多显示来源链接和"机器翻译"标记。发起方修改、确认后，资料经 `QB_PROFILE_IMPORT` 写入，Quiz 经 `QB_QUIZ_IMPORT` 生成草稿。

**后端**（`backend/quizbuks`，包 `page` 或 `content.ai`）：

- 外部作业类型 `qb.ai.site-profile`：处理器不访问数据库，声明 `enabledBy(qb.ai.enabled)`，输入只有地址、语言、选项与预留的 token（不含发起方的身份）。
- 流程：`QB_SITE_PROFILE_REQUEST`（发起方本人，要求已验证邮箱、未封禁，取 `qb.ai:<发起方>` 锁，计入限额：同时未结束的至多 1 个、每日次数）；完成、失败、取消的结局流程都是 `internal()`，用量照 AI 出题的做法计入 `QbAiUsage`，没有回答的尝试按预留计费（D52 第 5 条）。
- 结果保存在 AI 作业（`QbAiJob` 新的种类 `SITE_PROFILE`，或独立的一张表，细化时定），7 天后过期，同 Q8 的候选。确认页从它读取；导入之后与之前的作业无关。
- 失败的说明要具体：网站打不开、`robots.txt` 禁止、页面几乎没有文字（只靠脚本渲染的网站）、超时。都给出"改用路线 A 或手填"的提示。

**前端**（`quizbuks-web/sponsor/src/profile/`）：请求对话框、进行中的状态（每 5 秒查询，至多 5 分钟，离开即停，同 Q8）、确认页增加来源与机器翻译的标记、三语文案、axe。

### 3.3 链接图片的下载（Q100b，平台能力，A 与 B 都用）

资料包里的图片写成 `{"url": …}` 时，由服务器下载一次，走上传的同一条流水线：判断类型、重新编码、去掉位置信息，记为发起方自己上传的文件，链接不保存。安全要求照 Q100 §3：

- 只限 `https`；
- 每一跳（至多 3 跳）解析出的地址都必须是公网地址，拒绝回环、内网、链路本地和云厂商的元数据地址，并按解析出的地址连接，防 DNS 重绑定；
- 只收图片，大小上限同文件策略，有时限，不带 Cookie 与凭据；
- 作为外部作业或阻塞步骤运行。

这是平台能力，先在 `1.3/platform` 上做（带平台自己的测试与示范应用中的示范），再合并到 `1.3/quizbuks`（根 CLAUDE.md 第 8 节）。在它合入之前，链接图片在确认页列为"请下载后自己上传"，其余照常导入（Q100a 已是这样）。

## 4. "认识我们"的 Quiz

官网上的长内容（品牌故事、产品特点、常见问题）放不进迷你主页，正好做成一个 Quiz，让答题者"读完再答"。这就是 QuizBuks 的用法。

- **资料**：取 2–5 页的正文，每页成为一个文章资料（`ARTICLE`），标题取页面标题，正文为原文的整理（不超过 `ContentLimits.MATERIAL_BODY_LENGTH`，去掉导航与重复），并附原页面的链接。
- **题目**：缺省 5 道单选题，每题 4 个选项，只考资料里写明的事实。出题沿用 Q8 AI 出题的规则：只出候选，**发起方逐题勾选"我已校对"才能加入**（M-26），计入同一个 AI 限额。
- **结果**：一个 Quiz 草稿（Q16 文件，经 `QB_QUIZ_IMPORT` 生成），标题为"认识 <公司名>"，三语时同样带译文（Q73）。发起方校对后保存版本、发布，发布照常审核。
- 商品已在资料包中有编号时，题目可以关联到对应的商品（Q100e 的 Quiz 文件版本 3）。

## 5. 与其他功能的关系

| 功能 | 关系 |
|---|---|
| Q100 资料包 | 生成的就是资料包，导入、确认页、三语、商品编号全部沿用 |
| Q103 发起方包 | 生成 → 导入 → 校对 → 导出发起方包，以后测试期重置数据库时直接导回，不必再生成 |
| Q16 Quiz 文件 | "认识我们"是一个 Quiz 文件 |
| Q8 AI 出题 | 题目的生成与校对规则、限额、开关、同意 |
| Q48c AI 获客 | 复用 `ClaudeWebResearch`；获客的研究可以顺手给出官网地址，运营商为样板间生成时更快 |
| Q92a 运营商化 | 样板间由运营商的直营发起方生成与导入，照常经运营商另一位成员审核 |
| T10（链接名的误会） | 生成的资料包把官网地址放进"网站"、地址名由域名得出，从根本上避开这个误会 |

## 6. 测试

- **路线 A**：`ProfilePackagePromptsTest`，文档中的示例经资料包检查。
- **路线 B 后端**：作业的输入不含发起方身份；结果的检查（不合格的字段去掉并列出、地址名被占用给出备选、个人信息不取）；限额、开关、同意、取消与计费（照 `AiJobIT` 的做法）。本地桩 `tools/quizbuks/claude-stub` 增加官网读取的回答，测试与 e2e 从不访问网络。
- **路线 B 前端**：请求对话框、进行中、确认页的来源与机器翻译标记、axe。
- **平台下载**：内网与元数据地址、跳转到内网、非图片、超大、超时都被拒；正常图片经流水线登记为上传者的文件。
- **e2e**：发起方从官网（桩）生成 → 确认页 → 导入 → 主页草稿与商品、"认识我们"的 Quiz 草稿都在 → 主页提交审核。

## 8. 风险

| 等级 | 风险 | 对策 |
|---|---|---|
| 中 | 只靠脚本渲染的网站（SPA）读不到文字 | 失败的说明具体，并提示改用路线 A（让能执行网页的 AI 生成）或手填 |
| 中 | AI 编造价格、商品或公司信息 | P3：只取有来源的内容、确认页显示来源、价格不明确即留空；发起方逐项校对后才写入，主页照常审核 |
| 中 | 侵犯他人网站的权利 | P4：权利声明、`robots.txt`、只读一个网站、图片只下载一次；主页审核时可以核对官网 |
| 低 | 费用失控 | 计入 AI 限额，每个发起方同时只有 1 个、每日有次数上限；每次至多约 10 页 |
| 低 | 下载图片被用来探测内网 | 平台的下载能力只连公网地址、按解析出的地址连接、有跳数上限（§3.3） |
