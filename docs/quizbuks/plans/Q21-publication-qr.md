# Q21 发布的二维码：印在站点附近的海报上

需求方 2026-10-24："Please add a QR code for every publication. So that sponsors can print the QR code on the poster posted the stops nearby."
确认（2026-10-24）：二维码只需把人带到答题（即 Q15 的分享链接），不另做追踪、不另做落地页。

## 1. 做法

| 部分 | 内容 |
|---|---|
| 内容 | 二维码的内容就是分享链接 `<站点>/p/<发布>`（`plans/Q15-share-link.md`）：扫码后在 App 的分享页用邮箱登录并答题。没有新的接口、流程或表，服务端不知道有人扫码 |
| 生成 | 全部在商家后台的浏览器中由 `qrcode`（两个 SPA 已有的依赖，平台的二次验证也用它）生成；文件由浏览器下载保存。不经服务器，不写 `sys_file` |
| 商家后台 | 发布页中，进行中与已排期的发布在"复制分享链接"旁多一个"二维码"（`publication-qr`），打开对话框：码的图像（SVG，`data:` 图像，CSP 允许）、链接文字，三个保存：**PNG**（1024 px，静区 4 模块，纠错 H，脏了的海报也能扫）、**SVG**（放进商家自己的设计）、**海报**（A4 300 dpi 的 PNG：发布名称、大码、三种语言各一行"扫码答题，赢取 Kudos"、链接文字，黑白）。文件以发布名称命名（去掉文件系统不接受的字符，至多 60 字） |
| 不显示的 | 草稿、审核中、暂停、结束的发布没有二维码（链接此时打不开）；列表页不显示（每个发布的码在它自己的页面上） |
| 海报的三种语言 | 站点附近经过的人语言不一；指示行按 App 支持的三种语言各写一行（消息 `publishing.qr.posterLine`，以 `lng` 取各语言），字体用系统字体（含 Noto Sans CJK 的回退） |

没有迁移。`src/qb/` 不变（没有 App 侧的改动）。

## 2. 测试

- 商家 Vitest `publishing/qr.test.ts`：图像 URL 与 SVG 文件的内容与参数（静区、纠错 H）、PNG 的尺寸与参数、海报的画布尺寸、名称、码、每一行指示与底部的链接、长名称至多三行并以省略号收尾、文件名的清理。
- 商家 Vitest `publishing.test.tsx`：进行中的发布打开对话框显示码与链接（可访问名含发布名称），三个保存各产生正确名字的文件；暂停的发布没有按钮。
- e2e `a11y.spec.ts`：进行中的发布的二维码对话框过 axe（亮暗两种外观）。

## 3. 风险

- 商家把码印在海报上后暂停或结束发布：扫码到的分享页说明"目前未开放"（Q15 已有）。
- 海报的字体：在没有 CJK 字体的机器上中文、日文行可能缺字——由操作系统决定；商家可改用 SVG/PNG 自己排版。
- 码里只有本站链接；没有用户输入进入文件内容以外的地方（名称只用于文件名与海报文字，经 canvas 绘制，不是 HTML）。

## 4. 独立评审的修正

| 级别 | 问题 | 处理 |
|---|---|---|
| 中 | 海报底部的链接过长时被省略号截断，不能扫码的人无法使用 | 链接不截断，字号缩小到放得下（最小 24 px） |
| 中 | 码的图像生成失败时对话框永远显示占位，没有提示 | 显示"无法生成图片"的提示 |
| 中 | 保存时下载本身抛错会让三个按钮一直禁用 | `try / finally` 复位 |
| 低 | 名称中单个超宽的词超出海报边缘 | 每一行都收尾 |
| 低 | 图像背景用了颜色值 `bg-white`；语言列表、下载函数重复 | 图像自带浅色背景；用 `qb/messageKeys` 的 `LANGUAGES` 与 `content/transfer` 的 `download` |
| 低 | 文件名按 UTF-16 截断、末尾可能是点或空格 | 按字符截断，去掉末尾的点与空格 |
