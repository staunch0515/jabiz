# Q92 总体设计：全面运营商化、交易与资源、通用积木与知识结构图（设计，2026-11-04；待需求方审阅）

需求方 2026-11-03 至 11-04 的讨论结果。本文是这一轮改造的**总体设计**：说明系统的组织、收费原则、通用积木，以及 Q90（知识结构图）、Q91（称呼）与后续计划怎么拼在一起。
各项计划（Q90、Q91、Q92 的运营商化、Q93 的通用积木）以本文为准；与已有计划（Q47c、Q48、Q87、Q88、Q89）冲突之处，以本文为准，在各自的实施计划中改。
**只是设计**：不开发。§11 是仍待需求方确认的事项。

## 1. 远景与原则

1. **轻量的交易，付费的工具**：平台上的交易都是轻量的，**交易不收费**；使用平台的**工具与资源**付费；资金进出等**服务**收费。
2. **业务规定与系统能力分开**：业务规定可以说"某类不收费"，系统仍要**能够**对任何一类收费或抽成，只是配置为 0（§4.6）。业务改了，改配置，不改代码。
3. **一套机制，没有特例**：一个运营商与十个运营商走同一条路；平台自己的运营商与其他运营商没有区别。
4. **事前认真学习成为文化**：付费或有风险的能力，先要点亮一个"先了解方法与使用"的节点（Q90 §0-19）。
5. **通用积木，不特殊化**：反复出现的模式做成少数几块积木（§4），具体功能是积木的组合与配置（§5）；只在已有三个以上实例时抽象，不为"将来可能"造框架。

## 2. 组织：平台、运营商、发起方、答题者

| 层 | 是谁 | 管什么 |
|---|---|---|
| **平台（监控层）** | 总平台 | ① 建立与管理运营商（方案、分成、结算与付款）；② **全部资金进出**（充值、提现、账本、对账、收据与账单的开具、税务）；③ **全局规则**（法律文本、功能目录、平台知识结构图的模板、受控参数、费用规则）；④ **答题者的账号层面**（封禁、删除账号、个人信息的请求）——答题者不属于任何运营商；⑤ **监察**（抽查、报表、审计）与**应急**（违法内容下架、封号、法律保全、调取） |
| **运营商（经营层）** | 平台的业务部门；平台自己也有一个运营商（"平台运营商"），Shopify 另有一个运营商 | 发起方的招募、入驻审核、改派；发布审核；价目表（工具与资源的价格）；发起方知识结构图的审核；称呼的报价；涉及其发起方的争议与客服；获客；成员管理；基于平台模板调整自己的平台知识结构图（§4.1） |
| **直营发起方** | 每个运营商**恰好一个**，建运营商时自动建出，不能改派 | 出平台知识结构图的挑战发布（Q90 §2.6）；报价自己申报的称呼（Q91）；同时也是普通发起方，正常经营 |
| **发起方** | 每个都**属于一个运营商**（Shopify 店属于 Shopify 运营商）；没有无归属的发起方 | 做交易（§3）；在后台答平台的挑战（Q90 §2.8）；定义自己的知识结构图 |
| **答题者** | 不属于任何运营商 | 答题、领奖、提现；点亮平台的答题者知识结构图与发起方的知识结构图 |

**拿掉"直营即总部"**：现在没有归属的发起方算总部的（`direct`，Q48 D-Q48-1），带出价目表回落、总部终审、直营不出结算单、获客所有者 `direct`、发布卡片的运营商为空等特例。全部拿掉：平台运营商是一条普通的运营商记录，总部做日常经营的人是它的成员、用运营商后台工作；总部后台只留监控层的功能。平台在测试，**重置数据**，不迁移。

## 3. 三类定性

| 类别 | 谁和谁 | 业务规定 | 例子 |
|---|---|---|---|
| **交易** | 发起方之间；发起方和答题者之间 | **不收费、不抽成** | 赞助权益的买卖（Q89）、发学分奖励、学分买卖、付学分答题（Q88） |
| **工具与资源** | 运营商（代表平台）提供，发起方购买 | **收费**，走平台费（Q87） | 平台月费、受众规则（Q47c）、称呼（目录的与自己申报的，Q91）、AI、以后的其他工具 |
| **服务** | 平台提供 | **收费**，归平台 | 提现（平台有成本） |

**硬规则**：发起方与答题者在平台上**只能做交易，不能提供工具与资源**；工具与资源只由运营商（代表平台）提供。所以发起方与运营商之间的买卖，对象都是平台的工具与资源，都收费。

## 4. 通用积木（QuizBuks 应用内）

### 4.1 资格：知识结构图（Q90）

- 资格 = 节点点亮、平台事实、挑战合格（Q90 §2.1）；条件组合（Q90 §2.4）；点亮、有效期、"必须一直存在"（Q90 §2.5）。
- **购买工具与资源的资格**、**使用功能的资格**都指向知识结构图上的节点。
- **平台知识结构图的模板与运营商的副本**（需求方 2026-11-04，细节待定见 §11-2）：平台定义模板并版本化；运营商基于模板的某个版本修改，成为自己的图；运营商的发起方看到的是所属运营商的图。答题者的平台图只有平台的一份。

### 4.2 目录：可售项

- 一切可以买的东西是一个**可售项**：种类、卖方、三语名称与说明、价格方式、购买资格（节点）、是否先审核。
- **种类在代码中声明**（规则、称呼、AI 额度、权益……），每个种类只写自己独有的那一点（称呼：生效后替换显示的称呼；规则：在发布中选用；权益：由提供方核销）。不用一个什么都放的通用字段。
- 卖方：工具与资源的卖方只能是**运营商**（含它的直营发起方代为报价）；交易的卖方是**发起方**。
- **可售项归卖方的运营商管**：上架的审核、下架，由卖方所属的运营商（工具与资源的卖方就是运营商自己）。

### 4.3 交易与下单（凑合）

- 统一的流程：发起（选购或申报）→ 报价（需要时）→ 接受或拒绝 → 成立 → 履约 → 结束；另有暂停、作废与异常。"选了就买"是没有报价一步的下单。
- 每一笔记下双方，并**冻结双方当时所属的运营商**；可挂一段对话（复用 Q89 的发起方之间的对话）。
- **买卖归买方的运营商处理**（需求方 2026-11-04）：暂停、记录异常、裁定都由**买方（出钱方）的运营商**。理由：买方用买来的东西做发布，发布由买方的运营商审核，答题者的投诉也找发布方；运营商的收入来自其发起方使用工具与资源，所以买方的运营商有动力鼓励自己的发起方购买。
- 卖方的运营商：可以看、会收到通知；可以下架卖方的可售项（§4.2），**不处理这笔交易**；认为处理不公时可以提交平台。平台是安全阀，不参与日常处理。
- 待办与通知：交易的异常给买方的运营商；同时通知卖方的运营商（只读）。
- 改派不影响已成立的交易：照旧有效，新的运营商看得到，归属按冻结的运营商。

### 4.4 使用权

- 成交后得到"某段期间内可以用某个可售项"：开始、结束、状态；提前停用退还未用的天数、到期失效，统一在这一层（照 Q47c 的做法）。
- 同时持有几个使用权、选一个生效（如称呼的"买几个、换着用"）是这一层的通用能力。
- 受众规则的使用权期间就是发布的期间。

### 4.5 价目表

- 把 Q47c 只为受众规则做的价目表推广为通用的：**每个运营商一张**，按可售项定价，统一写**月价**，按日计费（月价 ÷ 30 × 天数，天数向上取整，金额取整到日元）。
- 每次最低使用费等 Q47c 的规则照用。

### 4.6 费用规则与结算

**费用规则**对三类一视同仁，按种类配置：

| 项 | 内容 |
|---|---|
| 适用对象 | 每种交易、工具与资源、服务各一条（奖励、学分买卖、权益交易、付学分答题、受众规则、称呼、AI、提现……） |
| 方式 | 比例、固定金额，或二者兼有；可设下限、上限（工具与资源的价格来自价目表，费用规则管交易与服务的抽成或费率） |
| 谁付 | 买方、卖方、答题者、发起方（按种类） |
| 收入归谁 | 平台独得；或平台与相关运营商按分成比例分 |
| 修改 | 受控参数（四眼），只影响修改之后发生的 |
| **现在的设置** | 交易类全部为 0；工具与资源按价目表、与运营商分成；提现按现行费率、**平台独得** |

- **现有的抽成机制不拆**：`qb.creator-fee-rate` 与科目 4110 的过账并入费用规则，设为 0，科目与对账保持可用。
- **运营商结算的通用公式**：应付运营商 = 当月"归该运营商分成"的各项费用合计 × 该运营商的分成比例。现在合计中实际只有其发起方付的**工具与资源费**；以后某种交易开始抽成并配置为与运营商分成，它自动进入合计。
- **平台运营商与 Shopify 运营商**与其他运营商同一公式：没有固定费、平台与运营商 50% 分成；结算单照常生成，收款方是平台自己，付款一步记为"内部结算"（待定见 §11-3）。

## 5. 现有与规划的功能如何用积木表达

| 功能 | 类别 | 拼法 |
|---|---|---|
| 平台月费（Q87） | 工具与资源 | 费用规则（按月），与运营商分成 |
| 受众规则（Q47c） | 工具与资源 | 可售项（规则）→ 发布中选用即下单 → 使用权 = 发布期间 → 价目表 → 平台费 |
| 目录称呼（Q91） | 工具与资源 | 可售项（称呼，卖方：运营商，资格：图上对应节点，不审核）→ 选购 → 使用权（自选期间）→ 平台费 |
| 自己申报的称呼（Q91） | 工具与资源 | 申报 → 卖方：运营商的直营发起方报价 → 同意 → 使用权 → 平台费 |
| AI 额度 | 工具与资源 | 可售项（AI）→ 使用权或按量（细化时定）→ 平台费 |
| 赞助权益（Q89） | 交易 | 可售项（权益，卖方：发起方）→ 磋商与提供方确认的交易 → 按份数履约；双方线下付款，平台只记录；费用规则 = 0 |
| 发学分奖励 | 交易 | 费用规则 = 0（原奖励抽成取消） |
| 学分买卖 | 交易 | 费用规则 = 0 |
| 付学分答题（Q88） | 交易 | 费用规则 = 0 |
| 提现 | 服务 | 费用规则（现行费率），平台独得 |
| 功能的使用 | — | 资格：功能目录（Q90 附录 A）中可门控的功能，点亮平台图上的节点才能用 |

## 8. 风险

1. **改动面很大**：组织、收费、资格三条主线同时重做；靠分期、每期可单独上线、重置数据来控制。
2. **通用化过度**：守住 §1-5 与 §4.2 的约束（种类在代码中声明，不用万能字段）。
3. **运营商的副本与模板的分叉**：模板升级不自动覆盖副本，由运营商逐项采用（待定 §11-2）。
4. **法律与合规**：交易不收费、平台不经手交易的钱，平台只在资金进出上提供服务，合规负担最轻；法律文本以平台名义对外，答题者的账号层面由平台负责。

## 9. 不做

- 发起方或答题者提供工具与资源（§3 硬规则）。
- 平台经手交易的付款（托管、代收代付）。
- 为没有三个实例的东西提前抽象。

## 10. 决定记录（需求方，2026-11-04）

1. 留在 `1.3/quizbuks`，不开 1.4 线（改动全部在应用内）。
2. 监控层的范围按 §2（含答题者账号层面、监察与应急）。
3. 运营商是平台的业务部门；平台运营商与其他运营商没有区别；每个运营商下有一个直营发起方。
4. Shopify 单独建一个运营商。
5. 平台运营商的结算与其他一致：没有固定费，与平台 50% 分成，最后都在一起。
6. 平台知识结构图：平台定义模板并版本化，运营商基于某个版本修改成自己的。
7. 交易由一个运营商处理：买方（出钱方）的运营商；卖方的运营商可以下架它所管发起方上架的东西。
8. 交易不收费、不抽成（奖励、学分买卖都是交易）；提现是服务、收费、全归平台；工具与资源收费。
9. 发起方之间、发起方与答题者之间都是交易，他们不能提供工具与资源；发起方与运营商之间的对象都是平台的工具与资源，都收费。
10. 自己申报的称呼是资源，走平台费。
11. 运营商的分成基础改为"其发起方付的工具与资源费"，奖励抽成整体取消。
12. 业务规定不抽成，但系统要能支持抽成（§4.6）。

## 11. 待定（需求方说先留着）

1. **直营发起方的发布免审核**：建议免审核直接上架，同时进入平台的监察列表；保留按运营商的开关"直营发起方的发布需要审核"（缺省关）。
2. **平台知识结构图的模板与副本**：运营商能改的范围（条件、有效期、挑战、证书、增删节点与连线；不能改功能目录、不能门控核心功能、授予只能从功能目录选）；副本**沿用模板的节点编号**、自己加的另起编号；模板升级不自动覆盖、运营商逐项采用；答题者的平台图不分运营商；运营商的图在运营商内部四眼生效；发起方只答所属运营商的官方账号出的挑战。
3. **平台运营商与 Shopify 运营商的结算**：收款方是平台自己，付款记为"内部结算"。
4. **运营商能否限制自己的发起方只与本运营商的发起方交易**：建议默认可以跨运营商，给运营商一个开关。
