# Q108 发起方后台的导航与页面框架

**状态**：需求方 2026-11-05 看过原型，"总体感觉非常好"；**暂不实施**。等 2026-11-06 起的功能大调整定下后，先做框架，页面随功能一起改（§5）。开工前另给实施计划（CLAUDE.md 第 7 节）。

原型（可点，示例数据，不接后台）：https://claude.ai/artifact/AS2gQnknL4dxTUFQQqwVru（源文件不在仓库中；改原型时以该页面为准）。

## 1. 需求方的不满（2026-11-05）

- 菜单越来越多：现在 6 组 19 项（`sponsor/src/App.tsx` 的 `groups`），每加一个功能就多一项。
- 页面框架、页面布局不统一。
- **"新建"按钮在最右边，屏幕大时很难找到**：`@jabiz/ui` 的 `PageHeader` 把 `actions` 放在标题行的另一端（`justify-between`），内容又是满屏宽。
- 商户资料的二级菜单（Q79 的 `ProfileLayout`）：大屏上是"侧栏 + 二级菜单 + 正文 + 右侧说明"四列，正文被挤窄；小屏上是要横着滑的一行。

## 2. 菜单：按"地方"分，8 个区域

每个菜单项是一个区域，区域里的页面用标题下的一排**页内标签**切换。**以后加功能只加标签，不加菜单项**（实施时写进 `backend/quizbuks/CLAUDE.md` 第 5 节，取代 Q79"新的商户设置页加为一个节"的写法）。

| 菜单 | 标签（现在的页面） |
|---|---|
| 首页 | 仪表盘与"待我处理"（待确认的领取、未读对话、预算不足、审核中、资料缺项；每条直接带到那一页） |
| Quiz | 模版列表、编辑 |
| 发布 | 列表 / 结构图（现在的"树"，Q85、Q90）/ 统计（现在设置下的"统计"）；发布详情另有自己的标签（概况、题目与版本、受众、奖励、统计、分享与二维码） |
| 奖品与兑换 | 到店兑换 / 现金奖励 / 电子奖品 |
| 客户与消息 | 对话 / 通知与公告（现在的"消息中心"）/ 客户（结构图上的人） |
| 合作权益 | 目录 / 我的权益 / 洽谈 / 采购单。**只有持有 `BENEFIT_PROVIDER` 或 `BENEFIT_SPONSOR` 的发起方才显示** |
| 资金 | 交易 / 钱包 / 账单与平台费（Q101、Q105） |
| 资源库（Q110） | 全部 / 素材 / 文字 / 奖品 / 商品 / 认证 |
| 商户中心 | 概况 / 基本信息 / 公开主页 / 店员 / 邮件服务器（商品与认证随 Q110 移到资源库） |

- 右上角头像菜单：账户与安全、外观、语言、帮助、退出（不再占左侧菜单）。
- 大屏：侧栏可收成只有图标的窄条（记在本机）。
- 手机：底部 首页 / 发布 / 兑换 / 消息 / 更多（"更多"打开全部菜单）；需求方对这 4 个的选择尚未确认。
- 旧地址全部保留转向（书签、邮件中的链接、PWA 的起始页），照 Q79 的 `LEGACY_PROFILE_PATHS` 的做法。

## 3. 页面框架

- **全局"＋ 新建"**：侧栏最上方，任何页面都能用（新建 Quiz、新建发布、发通知、导入发布设置）。
- **页头**：标题，**主按钮紧跟在标题旁**；说明一行；页内标签。手机上主按钮改为右下角的浮动按钮（在底部菜单之上）。
- **内容最大宽度**约 1360 像素居中（表单页约 960），宽屏上按钮不会离标题太远。
- 三种页面模板：
  - **列表页**：页头 → 工具栏（搜索、状态筛选的小标签、卡片 / 表格切换）→ 卡片或表格（Q34b、Q80 不变）。
  - **详情页**：左边内容，右边固定的"状态与下一步"栏（步骤、主要操作）；手机上这一栏在内容之前。
  - **表单页**：单栏、限宽，底部固定的"放弃 / 保存"条（显示是否有未保存的修改）。
- 商户中心的"概况"：完成度与每节一张卡片（完成或待填写、还差什么），二级菜单里的说明文字移到卡片上；资料包的导出与导入（Q100）在概况的页头。

## 4. 平台先行

侧栏的收起、页内标签、全局新建按钮、页头主按钮的位置、内容最大宽度、手机底部菜单与浮动按钮都在平台的 `@jabiz/ui`（`AppShell`、`ShellNav`、`PageHeader`）中，按根 CLAUDE.md 第 8 节先在 `1.3/platform` 上加（带平台自己的测试与示范，亮暗两种外观过 axe），再合并到 `1.3/quizbuks`。与 Q107 同样需要在平台分支上工作的许可。

## 5. 时机与顺序（需求方 2026-11-05 同意）

1. 2026-11-06 额度重置后，先定功能的大调整；8 个区域的分法随之微调（新功能落在哪个区域）。
2. **先做框架**（§2 的菜单、§3 的框架与模板），之后所有新功能直接按新样式写。
3. **页面随功能一起改**：功能调整碰到的页面，在那次修改里套上新模板；没碰到的页面最后集中迁移一次。
4. 粗估：平台框架 3–4 天，发起方后台 4–5 天（菜单、模板、各区域改成标签），e2e 随之改。

## 6. 答题者 App

需求方 2026-11-05 要看同样的思路用在答题者页面上的效果。原型：https://claude.ai/artifact/AuKS7YggSELPbZdfpvvg32。答题者 App 已基本满意，原型只做与此一致的小调整：

- 底部 5 项：首页 / 已答 / **扫一扫（正中、凸起）** / 消息 / 我的；右上角的菜单取消（扫一扫、推荐移走）。大屏改为左侧一列。
- "已答"中的**待领奖**放到第一层（标签与徽标），到店前一眼看到；扫一扫页同时有"出示我的通行码"（Q89c）。
- 收件箱与对话合并为"消息"，用标签分开。
- "我的"是答题者的中心：顶部三个数字（Kudos、待领奖品、证书）可点；下面两组："我拥有的"（奖品、证书、知识图、推荐、Kudos 明细）与"设置"（资料、账户与安全、通知、店员柜台、帮助与条款）。
- 发布详情：说明 / 奖励 / 资料 / 规则用标签分开，"开始答题"固定在底部。
- 首页不变。

### 6.1 需求方的决定（2026-11-05，看过原型之后）

**采用，与发起方后台一起排期**（§5 的顺序：先框架，页面随功能一起改）。需求方："其他页面都好很多，安排也更合理，框架也可能更好地满足手机和电脑。"

1. **首页保持现在的样子**，与 YouTube 一模一样（Q62、Q65、Q106 的首页不动）；改的只是首页之外的页面与框架。
2. **页面标题前有一个图标**，像原型"我的"页（名字前的头像）那样：每个一级页面（已答、扫一扫、消息、我的及其中的各页）的标题前都有该区域的图标，与底部菜单的图标相同。发起方后台的页头同样加（§3），两边一致。
3. **标题下的一排标签**：页面能容纳的内容多了很多；答题者的功能也在不断增加，**新功能加为某个区域里的标签或"我的"中的一项，不加底部菜单项**，使页面安排统一（与 §2 发起方后台的规则相同，实施时一起写进 `backend/quizbuks/CLAUDE.md` 第 5 节）。
4. 原型中的其他安排照做：底部 首页 / 已答 / 扫一扫（正中、凸起）/ 消息 / 我的，取消右上角菜单；"已答"中的待领奖在第一层；扫一扫页带"出示我的通行码"；收件箱与对话合为"消息"；"我的"顶部三个可点的数字与"我拥有的""设置"两组；发布详情用标签分开、"开始答题"固定在底部；大屏改为左侧一列。
5. 平台部分（页头图标、页内标签、底部菜单与大屏的左侧一列）与 §4 一起在平台上做，两个应用共用。

## 7. 登录、注册与邮件链接页（待需求方确认，2026-11-05 提出）

现状：两个应用的登录、注册、找回密码与邮件链接页都是平台的积木（`@jabiz/ui` 的 `SignInForm`、`SignUpForm`、`MailLinkPage`，带品牌），在菜单框架之外，各自居中一张表单。

建议（与 §3 同一套样式，作为第四种页面模板"入口页"）：

1. **大屏左右两栏**：左边是品牌与一句话说明（答题者："答题、学习、拿奖励"；发起方："用 Quiz 认识你的客户"），右边是表单；手机上品牌在上、表单在下。
2. **登录与注册在同一页，用标签切换**（与页内标签相同的样式），不再是两个页面来回跳。
3. **快捷方式在前**：通行密钥、Google、Apple、邮件链接的按钮在上，密码在下（平台已有这些方式，Q97、D54、D67）。
4. **两个入口说清楚是谁的**：发起方后台的登录页标明"发起方"，并有"我是答题者"的链接；反之亦然。
5. 邮件链接页（验证邮箱、找回密码、邀请、链接登录、退订）用同一模板。
6. 这些都是平台积木，改在平台上（两个应用与平台的通用后台一起受益），与 §4 同批。

待确认：现在的登录、注册页哪里不满意；是否先做原型。
