# 从中国大陆访问的核对表（上线前，在当地照做）

对应上线清单"性能"中的"从中国大陆访问（Q50）"与规格"上线准备与闭环验收"中的
"在中国大陆（手机流量与家庭宽带）打开首页、登录、答题，确认含境外视频的发布看不到、设了例外的能答"。
这些只能由在中国大陆的人用当地的网络做。开发与运维事先把下面"准备"一节做好，当地的人照"核对"一节走一遍、填"记录"。

## 准备（开发与运维，在正式系统上）

| # | 做什么 | 怎么确认 |
|---|---|---|
| P1 | 正式环境放好 IP 地址库，`.env` 有 `JABIZ_GEOIP_DATABASE`（`operations.md` §7.24 第 1–3 步） | 平台管理系统"中国大陆"页没有地址库的待办；日志有 `Address database …: N ranges` |
| P2 | 两份测试用的发布（官方账号或测试发起方，对公众不显眼即可）：**A** 资料中有 YouTube 视频（境外）；**B** 只有 bilibili 或没有视频 | 发布详情：A 的"含中国大陆无法播放的视频"为"是"，B 为"否" |
| P3 | 第三份发布 **C**，同 A 含 YouTube，在"中国大陆"页为它新增一个例外（按发布，写原因"上线核对"，到期日设为核对后一周） | 例外列表"生效中"有 C |
| P4 | 给当地的人一个学者测试账号（或让他当场注册），以及 A、B、C 的分享链接与二维码 | — |
| P5 | 当地的人的手机：系统浏览器一个，微信一个；一条手机流量线路、一处家庭宽带。**不开 VPN** | — |

## 核对（当地的人，每种网络各做一遍）

先手机流量，再家庭宽带。每一步记下"能 / 不能"和大约几秒；打不开或很慢时截图（含地址栏）。

| # | 做什么 | 应该是 |
|---|---|---|
| 1 | 浏览器打开 `https://quizbuks.com/api/client/region` | 显示 `"country":"CN"`、`"known":true`（不是 `CN` 时停下，把截图发给开发者：地址库判断错或经过了代理） |
| 2 | 打开首页 `https://quizbuks.com/taker/`，从输入地址到首屏出现 | 首屏出现；记下秒数（目标 5 秒内）；没有空白块、没有一直转圈的图片或字体 |
| 3 | 登录（邮箱与密码；如用邮件链接登录，邮件能收到、链接能打开） | 进入首页，右上角是账号 |
| 4 | 首页的卡片列表（A、B 已上线时） | 没有 A；有 B（C 出不出现都可以） |
| 5 | 打开 A 的分享链接 | 整页说明"该内容在你所在的地区不可用"，不显示视频与开始按钮 |
| 6 | 打开 B 的分享链接，开始答题、答完、看结果 | 每一步都能用；记下答题页出现的秒数（目标 3 秒内） |
| 7 | 打开 C 的分享链接，开始答题 | 能答（例外放开了它）；视频本身在中国大陆可能放不出来，是正常的 |
| 8 | 在微信中打开 B 的链接 | 出现"在浏览器中打开"的提示，或者能直接答 |
| 9 | 发起方页面 `https://quizbuks.com/sponsor/` 的登录页（只看能否打开） | 打开，记下秒数 |

## 出问题时

- 第 1 步不是 `CN`：`operations.md` §7.24 的"排查"第 4 条（地址库、`JABIZ_TRUSTED_PROXIES`）。
- 首屏或答题页慢、有打不开的资源：截图中的资源地址发给开发者（常见是境外的字体、统计或广告脚本；AdSense 在中国大陆打不开，不应挡住页面）。
- 第 5 步能看到 A：发布详情中 A 的标志是否为"是"；有没有误设的例外。
- 第 7 步不能答：例外是否"生效中"、是否按的是 C 这份发布。
