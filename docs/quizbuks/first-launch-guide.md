# 首发配置：一页说明

给需求方。写的是"要准备什么、怎么试、出错了怎么办、运维要设哪些变量"。详细的运维步骤在 `operations.md` §3"首发配置"，平台的规则在平台文档 `docs/guide/first-launch.md`。

## 1. 首发配置是什么

正式系统第一次启动时，用**一个文件夹**把系统一次准备好，不用人在页面上一项一项地做：

- 建好账号（只写名字、邮箱与角色，**不写密码**）；
- 建好运营商，并把负责人设为它的直营发起方；
- 导入直营发起方在测试系统上做好的内容（资料、Quiz、知识结构图、发布），发布照常审核、上线；
- 设几个参数（只限首发可设的那几个）。

内容全部就位之后，系统才对外开放，并给每个账号寄邀请邮件。本人从邮件里设密码、登录平台管理系统 `/admin/`、绑定二次验证，一分钟内得到配置里写的角色。

首发**只做一次**：数据库里有过任何用户，就永远不会再执行。

## 2. 怎么准备

1. 复制示例文件夹 `docs/quizbuks/first-launch-sample/`（两个账号的做法，同 `two-account-setup.md`）。里面有：
   - `first-launch.yml`：主文件，每一段都有中文注释；
   - `sponsors/official/package.json`：一个发起方包的示例。
2. 在**测试系统**上把直营发起方的内容做好，在发起方页面"概况 → 导入与导出 → 导出发起方包"，用导出的文件替换示例里的包。
3. 按注释改 `first-launch.yml`：
   - **账号**：每人一个代号（就是登录名）、本人的邮箱、角色；至少一个账号写 `report: true`（收完成报告）。
   - **邮箱域名** `allowedEmailDomains`：所有邮箱都要在这些域名之下，防止笔误把邀请寄到别处。
   - **运营商**：恰好一个 `default: true`；每个运营商有一个负责人；一个账号只能属于一个运营商。
   - **直营发起方**：每个运营商一项，指向它的包。
   - **发布**：包里每个发布都要写一项（按名称对应）。首发只允许线下兑换（`OFFLINE_REDEEM`），要写兑换说明（至多 500 字）；开始写 `launch`（首发运行的时刻）或带时区的时间；结束不能晚于开始后 366 天；发布必须绑定知识结构图的节点；不能动钱（奖励额、预算、报名费、推荐、数字奖品都为无或 0）。
   - **参数**：只能写首发可设的键（试运行的日志会列出清单）；金额和资金开关不能写。
4. **不要写任何密码、密钥或兑换码。** 键名里带 password、secret、token、codes 等的，一律被拒。

## 3. 怎么演练

先在**测试用的空数据库**上演练，正式那天再在正式的空数据库上做一次：

1. **试运行**：运维加上 `JABIZ_FIRST_LAUNCH_DRY_RUN=true` 启动。
   - 有问题：启动失败，日志一条一条写出"位置 | 问题 | 怎么改"。按它改配置，再试运行。
   - 没有问题：日志列出将要做的每一步，然后退出，什么也不写。请核对日志里的**每个邮箱**。
2. **真正运行一次**：去掉 `JABIZ_FIRST_LAUNCH_DRY_RUN`，在空数据库、空的文件目录上启动。内容就位之前，所有页面都显示"系统正在进行首发初始化"。
3. **检查**：收到邀请邮件、能设密码登录、角色到位、发起方的发布已上线、学者能打开并回答。

**出错了怎么办**（内容阶段的任何一步失败）：系统写出失败的步骤和原因，然后退出。首发不会接着做，所以：

1. 按日志**改配置**（或请开发修程序）；
2. **清空数据库和文件目录**（`JABIZ_FILES_LOCAL_ROOT` 指的那个目录）；
3. **重新启动**。

## 4. 正式那天与之后

- **超级管理员要运维确认**：本人接受邀请并绑定二次验证后，日志会给出这个账号的 12 位"指纹"和绑定的时刻。运维与本人核对时刻（例如电话），把指纹写进 `JABIZ_FIRST_LAUNCH_CONFIRM_ADMINS` 后重启，角色才授予。
- **邮箱写错了**：只要本人还没接受邀请，改配置里的 `email` 后重启，邀请就重寄到新地址，旧链接作废。已经接受的，在平台管理系统中照常改。
- **有可疑的账号**：在平台管理系统中停用它，首发就不再给它邀请或角色。
- **完成**：全部角色授予后，报告邮件寄给 `report: true` 的账号。超过 14 天还有人没完成，首发也结束，报告列出没完成的账号（以后在平台管理系统中照常办理）。
- **报告里列出的、要由人去做的事**：发布正式的法律文本（现在是测试占位）；负责人自己在发起方页面点"加入"（同意条款不能代做）；发布三条职责分离规则；在前提确定后发布某些参数；剩下的金额类提议；公司认证；运营商价格、银行设定、赠送额度和其他奖励方式。
- **完成之后**：请运维撤下配置文件和 `JABIZ_FIRST_LAUNCH_CONFIG`，并设 `QB_BOOTSTRAP_ADMIN_DONE=true`。

## 5. 运维要设的环境变量

| 变量 | 什么时候 | 说明 |
|---|---|---|
| `JABIZ_FIRST_LAUNCH_CONFIG` | 首发时 | 容器里 `first-launch.yml` 的路径（整个文件夹放到容器能读到的地方，例如只读挂载）。 |
| `JABIZ_FIRST_LAUNCH_DRY_RUN` | 试运行时 | `true`：只检查、列出步骤、退出。正式运行时不设。 |
| `JABIZ_FIRST_LAUNCH_CONFIRM_ADMINS` | 等人阶段 | 运维核对过的超级管理员指纹，逗号分隔；加了之后重启。 |
| `JABIZ_JWT_SECRET`、`JABIZ_INTEGRITY_KEY`、`JABIZ_MFA_KEY`、`JABIZ_SEAL_KEY` | 一直 | 四把密钥（`operations.md` §1.1）。缺任何一把，系统拒绝启动。 |
| `JABIZ_MAIL_ENABLED=true`、`JABIZ_MAIL_FROM`、`JABIZ_MAIL_BASE_URL`、`SPRING_MAIL_*` | 一直 | 邮件。没有邮件就寄不出邀请，首发等不到人。 |
| `JABIZ_WEB_ENVIRONMENT` | 一直 | 正式系统 `production`，测试系统 `staging`。 |
| `JABIZ_FILES_LOCAL_ROOT` | 一直 | 文件目录（镜像已设为 `/var/lib/jabiz/files` 的卷）。首发时这个卷必须是空的。 |
| `JABIZ_BOOTSTRAP_ADMIN_USER`、`JABIZ_BOOTSTRAP_ADMIN_PASSWORD` | **首发时不设** | 首发自己建账号；和 `JABIZ_FIRST_LAUNCH_CONFIG` 一起设，系统拒绝启动。 |
| `QB_BOOTSTRAP_ADMIN_DONE=true` | 首发完成后 | 撤下配置之后设它，系统照常启动。 |

可以不设、按缺省即可的：`JABIZ_FIRST_LAUNCH_DEADLINE`（等人的期限，缺省 14 天）、`JABIZ_FIRST_LAUNCH_REMIND_AFTER`（没接受的人再邀请一次，缺省 3 天）、`JABIZ_FIRST_LAUNCH_CONTENT_TIMEOUT`（内容阶段的时限，缺省 10 分钟）。
