# 答题点亮的平台功能：内容制作说明

给制作视频与题目的人看。列出平台图上"答题合格才能使用"的平台功能，按点亮者分为**学者**与**发起方**，每项写明功能是什么、怎么用、规则，以及题目与视频应当讲清的要点。

依据：`first-launch-spec.md` 的 F-S2（门槛节点）与 F-S4（发起方答题点亮与好处）、`plans/Q90-trees.md` 附录 A、`plans/Q89-sponsored-benefits.md`、使用说明 `manual-app.zh.md` 与 `manual-sponsor.zh.md`。用词照 `glossary.md`。

系统还在开发：下面写的是**需求方已经定下的规则**；界面上的按钮名、页面位置以上线时的为准，视频录屏要等测试系统上有了再录。

## 一、先了解：怎样点亮

- **平台图**：平台定义的知识结构图，有两张，一张的点亮者是学者，一张的点亮者是发起方。运营商可以在模板的基础上改成自己的副本。
- **点亮**：节点上绑定了发布（一份测验）。答这份测验合格，节点即点亮，对应的功能随即开通。
- **前置**：一个节点可以要求先点亮别的节点（"答题前条件"）。前置没点亮时，节点照样在图上显示（显示为"未满足前置"），但绑定这个节点的发布对这个人**不可见**。
- **三态**：未满足前置 → 可挑战（前置都已点亮、本节点还没点亮）→ 已点亮。
- **点亮永久**：首次上线没有有效期，规则改了也不熄灭。只有运营商或平台在出错时可以撤销（要填原因、另一位成员批准，本人会收到通知）。
- **在哪里答**：
  - 学者：在 App 中照常答题；"我的 → 知识结构图"里能看到整张图。
  - 发起方：在发起方页面的"挑战"页答题。只能由发起方账号本人答，店员和其他人不能代答；这些答题不给奖励、不动钱包，也不出现在学者的首页。
- **谁出题**：平台图上的发布由**直营发起方**（总部或运营商的官方账号）出。

## 二、首次上线确定的功能

需求方已定：首次上线只有下面六项由答题点亮。每一项对应哪个节点，由总部在受控参数中指定；没有指定时，这项功能对所有人都关闭。

### 学者（2 项）

#### T-1 申请成为发起方

- **功能**：学者在 App 中申请成为发起方，之后就能在发起方页面出题、发布、给学者发奖品。
- **门槛**：点亮参数 `qb.tree.gate.sponsor-apply-node` 指定的节点。没有点亮时不能申请。
- **怎么用**：
  1. 点亮门槛节点。
  2. 在 App 中进入申请成为发起方的入口，或在发起方页面用同一邮箱注册：账户即同时成为发起方账户。
  3. 填写基本信息（公司、简介、标志）并提交申请。
  4. 由所属运营商审核；结果以邮件通知。被驳回时会写明原因，修改后可以重新申请。
- **题目与视频要讲清**：
  - 发起方能做什么：出 Quiz、发布、设奖品、看统计。
  - 申请要审核，审核方是运营商，不是平台。
  - 发布是要付平台费的：配送费按开始答题的人数计；有赠送额度时先用赠送额度。
  - 发起方要遵守的规则：内容审核、奖品必须兑现、学者的屏蔽一定生效（付多少钱都越不过）。

#### T-2 推荐好友

- **功能**：有些发布允许推荐。学者答过或合格后得到推荐链接；好友在期限内合格，推荐人得到推荐奖励。
- **门槛**：点亮参数 `qb.tree.gate.referrer-node` 指定的节点。没有点亮时不能生成推荐链接。
- **怎么用**：
  1. 点亮门槛节点。
  2. 答一个允许推荐的发布；按发布的要求，答过或合格后，结果页或"推荐好友"（`/taker/referrals`）中出现推荐链接。
  3. 把链接发给好友；好友在期限内答这个发布并合格，推荐奖励即发放；过期的链接作废。
- **题目与视频要讲清**：
  - 不是每个发布都能推荐，要看发布是否允许推荐。
  - 有的要求推荐人自己先合格，有的只要答过。
  - 好友必须在期限内合格才算；期限、奖励多少由发起方在发布上设定。
  - 发起方的预算不够时，推荐奖励会等待支付。

### 发起方（4 项）

需求方定（2026-11-07）：**新发起方缺省没有任何奖励方式**。要在发布上给学者发奖品，先答题开通对应的奖励方式。首次上线不做学分奖励和现金奖励。

#### S-1 电子奖品

- **功能**：在发布上设电子奖品，学者合格后在 App 中直接收到码、券或链接。
- **门槛**：平台图上"电子奖品"的节点。合格即开通，写入该发起方的奖励方式。
- **怎么用**（发起方页面"电子奖品"，`/sponsor/digital-prizes`）：
  - 三种发法：
    - 码池：事先装载一批码，每位合格者一个，即时发出；
    - 共用码：所有合格者都用同一个码；
    - 自己发送：平台通知发起方，由发起方自己把奖品发给学者。
  - 码只以加密形式保存；学者本人点"查看奖品"才打开。
  - 学者打开后可以确认"能用"，或反馈问题；反馈由平台处理。
- **题目与视频要讲清**：
  - 三种发法的区别，以及各自适合的场景。
  - 码池的码要在发布前装够：份数不够时，后面合格的人得不到奖品。
  - 学者反馈"不能用"时怎么处理；处理不了会影响发起方的信誉。
  - 奖品内容要与发布上写的一致。

#### S-2 到店兑换（线下兑奖）

- **功能**：在发布上设到店领取的奖品，学者合格后在期限内到店领取。
- **门槛**：平台图上"线下兑奖"的节点。
- **怎么用**（发起方页面"奖品领取"，`/sponsor/redeem`）：
  - 学者扫店里的码：店员在手机上打开领取页，出示页面上的码，学者用 App 的"扫码"扫描后选要领取的奖品，即完成领取。
  - 印在海报上的码：可以长期贴出，但每次领取都要店员确认。
  - 店员扫学者的码：学者在"我的权益"中出示**领奖码**，即二维码和 6 位数字，60 秒有效、只能用一次。店员扫码，或在发起方页面输入数字，核对奖品和学者的名字后交付。
  - 店员：发起方在"发起方资料 → 店员"中添加店员，店员可以用自己的手机操作。
  - 领取期限：发布上可以设定天数，不设时用平台的缺省值。过期没领的作废。
- **题目与视频要讲清**：
  - 三条领取的路怎么选：店里出示码、海报码、扫学者的领奖码。
  - 海报码每次领取都要店员确认。
  - 领奖码只有 60 秒，过期了让学者重新出示。
  - 店员怎么添加、能做什么。
  - 写清领取地址、时间与期限，学者才不会白跑。

#### S-3 提供赞助权益

- **功能**：把自己的商品、服务或数字产品（例如视频的播放权）放进权益目录，让其他发起方买下来，作为奖品送给他们的学者，由自己履约（到店兑换或电子奖品）。
- **门槛**：点亮参数 `qb.tree.gate.benefit-provider-node` 指定的节点。
- **怎么用**（发起方页面"赞助权益"，`/sponsor/benefits`）：
  1. 在目录中登记权益：内容、价格、领取条件、地址与时间。
  2. 其他发起方来洽谈时，在洽谈中沟通；洽谈中允许交换联系方式。
  3. 对方建采购单，自己确认。平台只记录采购单，不代收代付，钱由双方自己结算。
  4. 学者合格得到凭证后，到自己店里领取（店员扫学者的领奖码），或由自己装载的码发出。
- **题目与视频要讲清**：
  - 提供方负责履约，不是出钱买的一方。
  - 平台不代收代付，结算在双方之间进行。
  - 一张采购单可以由对方的几个发布共用，份数用完即止。
  - 有异常（无法履约、暂停）要及时在平台上处理，否则学者白跑。

#### S-4 采购赞助权益

- **功能**：买其他发起方的权益，作为自己发布的奖品，送给自己的学者。例如冰箱厂商买面馆的牛肉面，答对冰箱 Quiz 的学者到面馆领面。
- **门槛**：点亮参数 `qb.tree.gate.benefit-sponsor-node` 指定的节点。
- **怎么用**：
  1. 在权益目录中找到权益，与提供方洽谈。
  2. 建采购单（份数、价格），等提供方确认。
  3. 发布时选用这张采购单：提交时划拨份数，发布结束时退回没用掉的份数；采购的内容也要经过发布审核。
  4. 学者在发布页看到"由 A 赞助，在 B 领取"，以及剩余份数。
- **题目与视频要讲清**：
  - 一位合格者得一份；份数用完后，新来的人不能开始答题。
  - 提交时划拨、结束时退回的意思。
  - 钱与提供方自己结算，平台不经手。
  - 学者在哪里领：在提供方那里，不在你的店里。

### 点亮赠送的额度（发起方图的附加好处）

- 平台图上发起方的节点，可以在定义中设"点亮赠送额度"：点亮后自动发给该发起方一笔平台费的赠送额度，可以用来付配送费。
- 金额随图的版本由另一位管理员审核；每个节点的上限是受控参数 `qb.tree.grant.max-per-node`，缺省为空，即不能设赠送。
- 赠送额度有有效期，过期作废，到期前会提醒；点亮被撤销时连带扣回。
- 如果要设，可以在题目或视频中提一句"答对即可得到赠送额度"，但**不要写具体金额**，原因见第四节。

## 三、候选功能（需求方还没有审核，暂不制作）

`Q90-trees.md` 附录 A 列出了可以挂到节点上的其他功能，需求方还在逐条审核，首次上线**不做**。定下来以后再按本说明的格式补写。

- **发起方**：
  - 公开主页；商品目录；用自己的发信服务器；
  - 导入测验；多语言与翻译；上架后切换版本；
  - 自己的知识结构图；受众规则；定向邀请；允许推荐；
  - 学分买卖；趋势与漏斗统计；店员；
  - AI 出题、AI 封面、AI 翻译；
  - 群发通知；与学者对话；App 内的发起方指标；
  - 购买称呼；节点证书。
- **学者**：分享证书；与发起方对话；分享发布。

Q90 还建议：付费或有风险的功能，先配一个"先了解方法"的入门节点（看使用手册或帮助，答题证明看过）。

以下永远不挂节点，人人可用：账户、条款、注销、帮助与联系客服、答题、领取已得的奖品、钱包与提现、账单与付款。

## 四、制作要点

- **题目里不写会变的数字**：期限天数、份数上限、赠送金额、单价、60 秒等都是平台的参数，以后可能调整。题目考的是"有期限""过期作废""先用赠送额度"这类规则；必须提到数字时，写"以页面显示为准"。
- **计分测验**：有对错的题目，设合格分；题目会乱序，选项不要写"以上都对""同 B"。
- **视频**：
  - 可以设"看完才能答"。
  - 竖屏视频会进首页的"短视频"。
  - YouTube 等境外视频在中国大陆看不到：面向大陆的学者，用平台自己服务器上的视频。
- **录屏**：等测试系统上有了这些页面再录；界面文字上线前可能还会改。
- **三种语言**：中文、日文、英文各做一份，用词照 `glossary.md`（学者 / テイカー / Taker；发起方 / 主催者 / Sponsor）。

## 五、要你决定的事

1. 六个节点的名称，以及彼此有没有前置关系。例如"采购赞助权益"要不要先点亮"到店兑换"。
2. 每个节点的合格分与题数。
3. 发起方的节点要不要设点亮赠送额度、金额多少。设的话，要先把 `qb.tree.grant.max-per-node` 设成非空。
4. 第三节的候选功能里，哪些要做。
