# QuizBuks 开发计划

依据：`01-requirements-analysis.md`、`02-design.md`。本文件给出**阶段划分、顺序与依赖**；每个阶段开工前按 CLAUDE.md 第 7 节
另出该阶段的实施计划（要改的类、表与迁移、测试清单、风险）并等待确认。

两条线并行：

- **平台**（`1.2/platform`，工作分支 `1.2/phase-<N><x>-<名>`）：阶段 15（Radix Themes）与阶段 16（QuizBuks 需要的通用能力 G*）。
  每项带平台自己的测试与示范（`backend/app`），不提 QuizBuks。登记在平台的 `docs/ROADMAP.md`。
- **应用**（`1.2/quizbuks`，工作分支 `1.2/quizbuks-<N>-<名>`）：Q1–Q10。平台阶段合入后，把 `1.2/platform` 合并进 `1.2/quizbuks` 再继续依赖它的应用阶段。

## 3. 顺序

```
平台前端：15a ─► 15b ─┐
                └► 15c ─┴► 15d
                └────────────► 16c（还需 16b）
平台后端：16a ─► 16b ─► 16f、16g
          16d、16e（随时，可与上面并行）

应用：Q1 ─► Q2（等 16a、16b）
       └─► Q3、Q4、Q5 的后端（不等平台）──► 页面（等 15a、16c）
            Q6（等 16d）   Q7（等 16a）   Q8（等 16e）   Q9   ─► Q10
```

建议的起步顺序：

1. **D34 – D39 六条决策的草稿**一次给出、一起确认（它们改变已有约定，确认前不写相关代码）。
2. 平台 15a 与 16a 同时开工；应用 Q1 同时开工（不依赖平台新能力）。
3. Q3 – Q5 的后端（实体、流程、模板、场景回放）在平台前端完成前先做；页面在 15a、16c 合入后补。

## 4. 风险

| 风险 | 应对 |
|---|---|
| 合规（资金決済法、GDPR，分析 4.6） | 在 Q6 之前取得法务意见；可能改变充值与转账的设计 |
| Stripe Connect 的跨境限制（Q18） | `PayoutGateway` 接口隔离；Q6 开工前确认平台 Stripe 账户的国家 |
| 阶段 15 的工作量（62 个文件、约 6 700 行 Ant Design 代码） | 15a 先定组件与封装，15b、15c 可并行；应用页面直接用新组件，不等 15d |
| 热门发布的结算吞吐（4.3） | Q10 压测；不足时改为按发布预留预算 |
| AI 生成质量与耗时 | 只作候选，必须人工校对；异步执行，不占流程事务 |
