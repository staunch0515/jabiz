# QuizBuks 开发计划

依据：`01-requirements-analysis.md`、`02-design.md`。本文件给出**阶段划分、顺序与依赖**；每个阶段开工前按 CLAUDE.md 第 7 节
另出该阶段的实施计划（要改的类、表与迁移、测试清单、风险）并等待确认。

**线 1.3 是开发、测试与部署的线（需求方 2026-10-28）**：staging 与 production 都从 1.3 部署（`deploy/quizbuks/DEPLOY.md`）。`1.2/quizbuks` 只作备份：不再部署（手动运行须确认）、不再从 1.2 向前合并，修复只做在 1.3。

本文件是线 1.2 的计划（Q1–Q33，已冻结）。线 1.3 上的 Shopify 集成（S0–S4 与平台 17a）在 `shopify/00-overview.md` 中，各阶段的实施计划在 `shopify/S<N>-….md`。

两条线并行：

- **平台**（`1.2/platform`，工作分支 `1.2/phase-<N><x>-<名>`）：阶段 15（shadcn/ui，D34）与阶段 16（QuizBuks 需要的通用能力 G*）。
  每项带平台自己的测试与示范（`backend/app`），不提 QuizBuks。登记在平台的 `docs/ROADMAP.md`。
- **应用**（`1.2/quizbuks`，工作分支 `1.2/quizbuks-<N>-<名>`）：Q1–Q10。平台阶段合入后，把 `1.2/platform` 合并进 `1.2/quizbuks` 再继续依赖它的应用阶段。

每个阶段的详细实施计划在 `plans/` 中（平台阶段的计划在平台的 `docs/ROADMAP.md`）。

## 6. 中国大陆策略（需求方 2026-10-28 决定）

- **中国大陆的用户只用网站与"安装到主屏幕"的网页 App（PWA）**。不上中国的应用商店（华为、小米、应用宝等）；App Store 上架时把中国大陆排除在销售地区之外（在那里上架须有 ICP 备案号）；Google Play 在中国大陆本来就不可用。
- 现状：网站在中国大陆可以访问，能注册、答题、收取 Kudos；商家以微信把现金奖励转给用户（平台外付款，平台只记"已发放"）。
- Google、Facebook、LINE 在中国大陆打不开，按钮仍保留：中文界面的登录页把邮件登录放在最上面，密码其次，第三方登录在最后（Q50，平台 17m）。
- 国产手机多用自带或国产的浏览器，微信、QQ 中打开的链接在它们的内置浏览器里：安装指引按浏览器给出，内置浏览器从第一次访问起提示"在浏览器中打开"（Q50）。
- 人工检查（`launch-checklist.md`）：两三台国产安卓手机实测"添加到桌面"；从中国大陆测首页与答题的加载时间，偶尔复测。
