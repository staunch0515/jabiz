执行方式与平台相同（根目录 `CLAUDE.md` 第 7 节）：每个阶段先出实施计划、经确认后实现；工作分支 `culture-<N>-<名>` 从 `culture` 拉出并合回；
PR 逐条对照本文件的验收标准。平台能力来自 `platform` 分支的阶段 13（`docs/ROADMAP.md`），合入 `platform` 后再合并到 `culture`。

## C1 内容模型、工作流与后台

**要求**
1. 模块 `backend/culture`（`jabiz.boot-app`，`/` 与 `/admin/` 两个 SPA，公开网站先放占位页）、`backend/culture/CLAUDE.md`。
2. 实体与迁移（设计 §3）、字典、文件策略、数据视图（§5）、文案（zh / ja / en）、文案块的英语预置内容。
3. 流程（§6.3）、两个开关（§6.5）、`CULTURE_SETUP`（§6.6）。
4. `deploy/culture/docker-compose.yml`；`docs/culture/editor-guide.md`。

**验收标准**
- [ ] 编辑只用后台（不写前端代码）即可完成：建地点、主题、参与者与同意记录，上传照片，起草多人故事，发布。
- [ ] 通讯员只能看到、改动自己的内容；提交后不能再改，退回后可以（集成测试）。
- [ ] 发布检查的每条违规都有测试；两个开关各取两种值的行为都有测试。
- [ ] 撤回同意后，包含该参与者的故事全部下线；抹除后相关行与文件都不存在（集成测试）。
- [ ] 场景回放"六个地点的 HOME 故事"全过程快照；`platformCheck` 通过；`check-app-paths` 通过。

## C2 公开接口

**要求**
1. 公开数据视图（§7.1）与公开模板（§7.2），搜索所需的迁移（`pg_trgm`、`cu_i18n_text`、索引）。
2. 公开模板目录快照与 `site/` 中的类型生成。

**验收标准**
- [ ] 属性测试：任意状态组合下，公开模板只返回已发布的数据。
- [ ] 同意书永远不能匿名获取；草稿与下线内容的文件 404；撤回同意后文件在失效后 404。
- [ ] 按地点、主题、媒体类型筛选与搜索（含中日文）返回正确结果；通配符被转义。

## C3 公开网站

**要求**
1. 视觉原型（首页、主题页、故事页；手机与桌面）→ **经确认后**实现。
2. 全部页面（设计 §9.1）、三种界面语言、组件（§9.3）、`site/CLAUDE.md`（含文案语气规则）。
3. CI：`site` 的 lint、typecheck、test、build 与端到端（`.github/workflows/culture.yml`）。

**验收标准**
- [ ] 没有任何写死的国家、参与者或主题：加一个地点、参与者、主题、故事后，不改代码即出现在所有相关页面（端到端测试）。
- [ ] 全部页面在三种语言、桌面与 375 px 宽度下 axe 检查的严重与重大问题为 0；只用键盘完成"首页 → 主题 → 故事 → 播放视频"。
- [ ] 视频在点击前页面没有任何第三方请求（Playwright 断言）。
- [ ] 与视觉原型一致（人工确认）。

## C4 地图、搜索与上线准备

**要求**
1. 地图（§9.5）与地点列表；搜索页。
2. Lighthouse 测量与优化；备份与恢复演练；部署文档（`docs/culture/operations.md`）。

**验收标准**
- [ ] 地图可键盘操作，地点列表提供相同内容。
- [ ] 移动端首页 LCP < 2.5 s、首屏 JS < 200 KB（gzip），Lighthouse 无障碍 100（记录在 `docs/culture/operations.md`）。
- [ ] 从备份恢复出一套可用的系统（数据库 + 文件），步骤写入运维文档。
