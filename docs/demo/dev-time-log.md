# 示范业务开发用时记录（ROADMAP 阶段 11）

示范领域：订单与库存（`backend/app/src/main/java/com/jabiz/app/commerce`），外加教程示例 `Supplier`。
全部用平台实现：实体声明、数据视图、SQL 模板、流程（平台 I/O 步骤 + 同步计算步骤）、消息资源；**没有前端代码**、没有手写 Repository / Controller / 事务代码。

## 1. 先说明测量方式（重要）

- 本阶段的代码由 AI 编码助手（Claude Code）在一次会话中编写。下表"实测"一栏是该会话中用 `date` 与提交时间记录的**墙钟时间**（UTC），
  包括编写、首次运行测试与修正，不包括事先阅读设计文档的时间。
- 它**不能**代表人类开发者的用时：AI 不需要查文档、打字很快，但这也说明"声明 + 同步计算"的写法足够规整，能被一次写对。
- 因此另列"人工参考估计"：给第一次接触本平台、熟悉 Java 与 SQL 的开发者的估计，**不是测量值**。
  验收标准 3（"未参与开发的人一天内新增一个业务对象"）需要真人按教程操作来验证，结果请补充到第 4 节。
- 实测的分段粒度有限：五个实体、四个流程与两个模板是一次写完的（第一段），无法再准确拆到每个对象；表中按对象列出的是代码量与估计。

## 3. 各业务对象：代码量与人工参考估计

| 业务对象 | 声明 / 代码 | 测试 | 人工参考估计* |
|---|---|---|---|
| `Supplier`（主数据：实体 + 视图 + 文案） | 迁移 22 行、声明 60 行、文案 3×10 行 | `SupplierIT` 92 行 | 2–3 小时 |
| `Product`（可预定调价的主数据） | 实体约 25 行、迁移约 8 行、`PRODUCT_REPRICE` 约 40 行 | `CommerceIT` / 单元测试 / 场景中的相关部分 | 3–4 小时 |
| `Warehouse` | 实体约 20 行、迁移约 6 行 | 同上 | 1–2 小时 |
| `StockLevel`（只经流程写入、实体级校验防负库存） | 实体约 30 行、迁移约 9 行、`STOCK_RECEIVE` 约 60 行 | 同上（含并发不超卖） | 3–4 小时 |
| `SalesOrder` + `SalesOrderLine`（状态机、三个流程、过账、两个模板） | 实体约 60 行、迁移约 25 行、流程约 250 行、模板 70 行 | 同上 + 跨月场景 | 1.5–2 天 |

\* 估计依据：教程每步的参考用时（`docs/guide/new-business-object.md`）与本仓库既有示例的规模。代码行数含注释与空行，
总计：`commerce` 包 890 行（含 `Supplier` 60 行）、迁移 90 行、SQL 模板 70 行；测试 602 行、场景 100 行。

观察：

- 业务代码里最长的是流程的计算步骤（`CommerceProcesses` 520 行中约一半是它们与输入输出 record）；实体和视图的声明很短。
- 事务、并发（版本冲突 409）、历史、撤销、权限检查、错误文案多语言、前端页面、审计记录、观测指标都没有写代码，是平台给的。
- 第一次运行就暴露的问题只有一处（场景 YAML 中未加引号的冒号），被场景解析器立即指出；元数据、表结构、模板的不一致由 `platformCheck` 覆盖。
